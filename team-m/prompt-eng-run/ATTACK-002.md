# ATTACK-002 · Критика обоих предложений (агент 002, Адвокат Дьявола) · 2026-08-25

> Полный текст без изменений. Источник: внутренний прогон.

=== ПРОПОЗАЛ-001 (внутренний) ===

**УДАР 1 (рестарт + `{file:}` без страховочной сетки).** Сценарий: пятница, правка `team-m/prompts/002.md`, случайно сдвинут каталог или путь в конфиге указывает на старое имя. Поведение парсера на отсутствующий/пустой файл в SCHEMA-FINDINGS **не зафиксировано** — две ветки, обе плохие: (а) строгая валидация → opencode не стартует, вся команда стоит до отката конфига; (б) молчаливая загрузка пустой строки → 002/009 работают **без ролей**, деградация незаметна ровно до момента, когда «адвокат дьявола» соглашается со всем. Дизайн не содержит ни одного шага проверки после правки промт-файлов. → Последствие: тихий коллапс качества или полный даунтайм на ровном месте. → Патч: претест перед стартом (файлы существуют, не пустые, содержат маркеры `FROZEN`/`ФОРМАТ`) + разовое «ролевое эхо» каждого агента после рестарта. Без теста ветки (а)/(б) — это лотерея, а не архитектура.

**УДАР 2 (SHARED.md бьёт по координатору).** Топ-левел `instructions[]` инжектится **всем**, включая 007. Но SHARED.md содержит «## ФОРМАТ ОТВЕТА (**всегда**, без прозы): РЕЗЮМЕ/СДЕЛАНО/ВЕРИФИКАЦИЯ» — это формат *отчёта исполнителя*. 007 не исполнитель: он выдаёт диспатчи и синтез. Получается: системный промт координатора обязывает его отвечать Боссу в формате саб-репорта. Плюс дубль FROZEN-ZONE и канона в контексте самого нагруженного агента: 007 несёт AGENTS.md + SHARED.md + свой шаблон диспатча, где FROZEN и канон **ещё раз**. На free-модели с ограниченным окном это ранее вытеснение инструкций 007 из внимания. → Патч: секцию ФОРМАТ ОТВЕТА перенести из SHARED.md в per-agent файлы; в SHARED оставить только домен + FROZEN + правило «формат задаёт диспатч».

**УДАР 3 (канон 306/770 в статике).** Сценарий: неделя спустя базлайн сместился (tsc 306→280, vitest 770→785). SHARED.md читает «vitest: 770 passed» — двусмысленно (ровно 770? минимум?), регрессия 785→779 формально проходит. Спасательный трос «КАНОН-СНАПШОТ главнее» работает **только внутри диспатча**: прямой вопрос Босса к 009 вне диспатча — и 009 судит по мёртвым цифрам из статики. Правка SHARED.md помогает только со следующего рестарта. → Патч: цифры вообще убрать из статики: «Канон = ТОЛЬКО из КАНОН-СНАПШОТ диспатча; нет снапшота → БЛОКЕР». Одна точка обновления, всегда свежая.

**УДАР 4 (дисциплина промптом без энфорсмента).** §4 фрагмента конфига содержит только `prompt` + `instructions`. Permission/temperature/steps из SCHEMA-FINDINGS — **не задействованы**. Сценарий: free-модель в роли 002 на середине атаки решает «показать усиление прямо в коде» — инструмент edit у неё есть по умолчанию, один порыв = реальная правка, возможно во frozen-зоне. Промпт — это уговор; permission — это замок. → Патч: `permission.edit: deny` для 002/009/explore, `task: deny` сабам, `temperature ≈0.15` оператору. Ноль токенов, железная гарантия.

**УДАР 5 (T5 эскалация — триггер не операционализирован).** «Два провала роли» — кто считает? Где счётчик? В шаблоне диспатча нет поля отметки провалов → решение по памяти 007 между десятками вызовов. Плюс цена: смена модели = правка конфига + рестарт → смерть сессии посреди задачи. → Патч: явный счётчик провалов в REGISTRY-строке задачи + правило «эскалация = рекомендация Боссу, точка остановки».

**УСИЛЕНИЕ:** взять из SCHEMA-FINDINGS permission/steps/temperature и прошить в конфиг (002/009/explore — read-only; explore steps≈10; operator temp≈0.15) → роли неиспортивны на уровне движка, бюджет защищён от зацикливания — бесплатно.

**ВЕРДИКТ: ТРЕБУЕТ ПАТЧА.** Условия: (1) стартовый линт `{file:}`-файлов до первого боя, (2) канон-цифры в снапшот-онли, (3) permission-энфорсмент. Скелет верный.

=== ЦЕНТР_5 (внешний) ===

**УДАР 1 (убивающий: поле `instructions` не существует).** Оба ответа строят ядро на per-agent `"instructions"`. Такого свойства в AgentConfig нет. Ветки: (а) строгий парсер → конфиг целиком отвергнут; (б) лояльный → поля молча игнорируются, все семь агентов без ролей получают диспатчи с требованием STRICT JSON по схемам, которые они никогда не получали. Поддержка XML-промтов, заэкранированных `\n` внутри JSON-строки конфига = каждая правка ролей трогает живой конфиг; одна лишняя кавычка = отказ старта. → Как написано — падает.

**УДАР 2 (FROZEN запрещает ЧТЕНИЕ + извращённый критерий успеха).** Формулировка «NEVER read/modify…» + проверка «найди AudioEngineV2 → FROZEN_VIOLATION = успех». Но проект — миграция V2→V3: V2-движок это источник совместимости, его читают постоянно. Сценарий: задача «проверь bridge vs контракт AudioEngineV2» → explore отказывается искать, 002 не может прочитать атакуемый код, 009 судит вслепую. Система ослепила собственных судей. → Патч: «modify — никогда; read — разрешён и обязателен».

**УДАР 3 (STRICT JSON от всех против инструментов).** 005 обязан делать цепочку tool-call'ов под давлением «STRICT JSON ONLY» → free-модель льёт JSON внутрь аргументов инструментов или избегает вызова. Оператору разрешён словарь `DONE | ERROR:` при протоколе, требующем точные цифры tsc/тестов → цифрам некуда лечь → доказательства до 009 не доходят → GUILTY по умолчанию. Информационное голодание встроено в дизайн. → Патч: JSON только для листовых репортёров; оператору — статус-объект `{status, tsc, tests, changed_files[]}`; исследователям — структурный markdown.

**УДАР 4 («автоматическая эскалация» невозможна + вечная петля GUILTY).** FAIL×2 → авто-переход на .high невозможен: смена модели = правка конфига + рестарт, посреди сессии — ручная операция с потерей контекста. Петля GUILTY→001 без капа ретраев жжёт пул с нулём прогресса. → Патч: кап 2 ретрая → СТОП + человек; эскалация = рекомендация Боссу.

**УДАР 5 (канон размножен в три места).** 306/770 живут в AGENTS.md, диспатче и правилах 009 одновременно; приоритета снапшота нет вовсе. Через неделю обновят одно — забудут второе. → Патч: единственный источник цифр — снапшот диспатча.

**УСИЛЕНИЕ:** сохранить дисциплину формата Центра_5, но пересадить в работающий механизм: схемы вывода = секция ФОРМАТ внутри per-agent файлов, единый словарь вердиктов на всю цепочку (сейчас три конкурирующих: PASS|FAIL / GUILTY|NOT_GUILTY / РЕШЕНО|ОТЛОЖЕНО|ОТКЛОНЕНО).

**ВЕРДИКТ: ПАДАЕТ.** Ядро опирается на поле, которого нет в схеме.

=== ЧТО ВЗЯТЬ ИЗ ОБОИХ В ФИНАЛ ===

1. Скелет Пропозала-001 как несущая конструкция (`prompt:{file:}` + топ-левел `instructions[]`) — единственная схема-совместимая основа.
2. Из Центра_5 — дисциплина формата адресно: строгие схемы только листовым исполнителям (operator — статус-объект, 009 — вердикт-объект); исследователям — нумерованный markdown; один словарь вердиктов.
3. Энфорсмент движком: `permission.edit:deny` для 002/009/explore, `task:deny` сабам, temperature/steps по ролям — замок вместо уговоров.
4. Канон = только КАНОН-СНАПШОТ: ноль цифр в статичных файлах; нет снапшота → БЛОКЕР.
5. Гигиена рестарта: претест `{file:}`-файлов перед запуском, ролевое эхо после, FROZEN = «read можно, modify нельзя», кап GUILTY-ретраев = 2 с выходом на человека.
