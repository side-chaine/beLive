## 1. ПРОБЛЕМА (VIS-14, формулировка 201 из ревизии)
Ложные гармоники в ~80% случаев: октавные ошибки YIN (F0/2-лочки) — наш octLock (`yin-detect.ts:163-172` — сдвиг после D-CLN-1)
детерминированная эвристика, пропускает кварт-в-октаву (r 1.4-1.6 — тоже лочится `/1.5`!). Two families:
(а) суб-гармоника принимается за основу (гроул-вокал, бас) · (б) верхняя гармоника принимается за F0 (breathy).

## 2. ТРЁХКОНТУРНЫЙ СТЕНД (v1.1 по консенсусу пары 10:44 + GO Никиты «собрать лучшее, питч должен быть умным»)
**A = статус-кво:** YinDetector (2048, threshold 0.15, octLock+median+autoCal, сабгармоники-прокси).
**B = MPM/NSDF:** pitchy@4 (0BSD, 134⭐, живой): freq+clarity, без octLock — NSDF-нормировка сама устойчива. Валидатор-референс, НЕ кандидат в бандл.
**C = 🆕 ГИБРИД-ФАВОРИТ: наш YIN-костяк + pYIN-голосование порогов** (досье 1.9 005_2, этап-1 «без Viterbi»):
та же CMND-кривая → 100 порогов из Beta(2,18) → Boltzmann-приор по локальным минимумам → взвешенное F0;
octLock/median ВЫКЛЮЧЕНЫ (их работу делает голосование). Якоря C-целей v1.2: octLock `:163-172` · median `:144` · autoCal `:149` · subharmonicRatio-вычислитель `:126-135` (RASP-SNAPSHOT-защищён). **Ключ:** CMND остаётся нашей → сабгармоник-метрики
(subScore/noiseScore, гроул/скрим-USP) живы в C, но НЕ живут в B. Фаворит пары: C закрывает октавные лжи (VIS-14,
15-20% вранья по уточнению Никиты) и не теряет ни USP, ни легковесность (+~0.5-1ms/кадр — в бюджет 46ms-тика).
**Судья (оффлайн):** CREPE (arXiv:1802.06182, сверен API) на тех же стемах — метрики MIREX: RPA±50ц, Chroma (октав-прыжки = суть VIS-14!), VR, VFA.
**Стенд:** Node-скрипт (не браузер): читает stem-файлы → A/B/C подсчёт → таблица + JSON.
**Вердикт-правило [002-У5, тай-брейкер]:** зона ничьей |ΔChroma(C−A)| < 2 п.п. → **A остаётся** (дешёвый в проде не проигрывает ничью); C = дефолт только при **C ≥ A+2 п.п. на бас/гроул И C ≥ A−1 п.п. на чистом** (числа — спек-канон). Если C < A−1 п.п. на чистом → разбираем C-кейсы на цепи (Beta/приор-тюнинг) до вердикта.

## 3. КЕЙСЫ (кейс-лист из 1.11 + Д-А; обязательные)
1. Чистый женский вокал (сопрано) — где YIN не хуже (прогноз 005_2).
2. Чистый мужской бас <150 Гц — где pitchy ждёмо сильнее (наш rangeClamp упирается).
3. Гроул/скрим — сабгармоник-семья (наш USP: distortion-метрики YIN; у pitchy нет).
4. Breathy/фальцет — верхняя гармоника-семья.
5. Вибрато — устойчивость трека по кадрам.
6. Утечка инструментала (стем vocals с пробоем барабанов) — реальность разделения.
По 3-5 файлов на кейс (стемы .wav из локального каталога; список файлов — в спеке оператору, без бинарников в git).

## 4. ПРОТОКОЛ (из Д-А: критерии приёмки спеки 005_2)
- **[002-У3] Агрегация = frame-pooled Chroma** (все voiced-кадры кейса в одном знаменателе; file-mean — вторая колонка JSON, НЕ гейтинг). Файл валиден при ≥300 voiced-кадров; кейс — при ≥2 валидных файлах; иначе кейс = «insufficient».
- RPA±50ц и Chroma — по-кейсово и агрегат; **пороги: стенд принимает B, если Chroma(B) > Chroma(A) на ≥3 п.п. на ≥4/6 кейсах** и RPA(B) не хуже A более чем на 1 п.п. Иначе A остаётся.
- CPU-latency: живой пайплайн-замер (46.4 ms-тик пассивного тапа; `_passiveTick` якорь v1.2: `pitch-engine.ts:202-233`) — B обязана уложиться в бюджет тика
  (питч не должен жрать >25% тика; замер performance.now вокруг detect() × 1000 кадров).
- **[002-У6] Гроул-кейс гейтится ТОЛЬКО Chroma** (f0 редко воспринимается — Kalbag; после CREPE-exclusion RPA-выжившие = не-гроул кадры, мал-n флапает): RPA(гроул) — отчётная колонка; <300 валидных кадров после exclusion → «insufficient».
- VR/VFA — контекстные (не решающие, но в отчёт).

## 5. ПАРАЛЛЕЛЬНЫЙ ЭТАП-1.5 (из Д-Б, если стенд утвердит B)
FFT-путь difference-функции: d(τ) = 2·(ACF(0) − ACF(τ)) − E(τ) через rFFT (Wiener-Khinchin):
наш O(N²) `yin-detect.ts:75-83` (~1.05M ops/кадр, сдвиг после D-CLN-1) → ~0.1M (~10× CPU). Грабли 005_2 (Д-Б):
(а) zero-pad ≥2N−1 (wraparound бьёт низкие = наш кейс!) · (б) block-size в 46ms-бюджете · (в) кэш FFT-планов
(1 инстанс/размер) · (г) E(τ) running-sum + periodic-reset 10⁴ кадров (дрифт-гаситель).
Приоритет: Этап-1.5 после стенда B (если YIN остаётся — FFT всё равно даёт headroom для fftSize 4096: τ=630 для 70 Гц).
