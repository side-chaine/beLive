## §0 · ПРИНЦИП, ИЗ КОТОРОГО СЛЕДУЕТ ВСЁ

**У каждого дока ровно одно состояние, и оно объявлено в первой строке.**

| Состояние | Правило | Что делает машина |
|---|---|---|
| 🟢 **LIVING** | контракт с кодом: числа и `file:line` обязаны совпадать с деревом | **G-3 проверяет каждый коммит** |
| 🗄 **HISTORY** | заморожен датой; **правка = фальсификация замера** (правило E1-3 пары 003 — уже ваше) | G-3 **не смотрит** |
| 📚 **REFERENCE** | внешнее: исследования, выжимки, статьи | G-3 не смотрит |
| 🔒 **PRIVATE** | внутреннее, **не для публичного репо** — уже реальность через `.gitignore` (см. Д-15) | G-3 не смотрит; **гейт публичности: файл обязан быть под ignore-правилом** |

**Ортогональность (правка v1.1, по находке счётчика):** PRIVATE — это **не четвёртый вид содержимого, а второе измерение**. Док имеет пару значений: `state` (LIVING/HISTORY/REFERENCE) × `visibility` (public/private). LIVING-док может быть приватным (внутренний контракт), HISTORY-док — публичным. В `DOC-CENSUS.yaml` это **два разных поля**, не одно перечисление. Схлопывание их в одну колонку — главная ловушка R-1: перепись начнёт спорить «это HISTORY или PRIVATE», хотя вопрос не имеет смысла.

Сегодня 236 из 254 доков в `docs/` **не говорят о себе ничего** — читатель (человек или агент) обязан догадываться, контракт перед ним или воспоминание. Это и есть корень всех дрейфов вида «доки 18 / машина 17».

## §2 · МАРШРУТ РЕФОРМЫ

### R-1 · ПЕРЕПИСЬ (003 + 003_2, ~полдня)

#### R-1.0 · ШАГ НОЛЬ: канонизировать счётчик (обязателен, иначе перепись считает не то)

Правка v1.1 по находке Д-15 и раунду-4 Соннета. **До присвоения состояний** пара фиксирует базу двумя командами и пишет обе цифры в метадату `DOC-CENSUS.yaml`:

```bash
find . -name "*.md" -not -path "./node_modules/*" -not -path "./.git/*" | wc -l   # on-disk  → 767
git ls-files '*.md' | wc -l                                                       # tracked  → 546
comm -23 <(find docs -name '*.md'|sort) <(git ls-files 'docs/**/*.md' 'docs/*.md'|sort)  # private/untracked → 90
```

Правило: **любая цифра в реформе публикуется с пометкой скоупа `on-disk` или `tracked`.** Расхождение 767/546 — не ошибка, а два законных измерения (подтверждено: Соннет в раунде-4 дал 544 tracked, я 767 on-disk, оба верны). Без этого шага G-3 будет сверять разные базы, а споры «у меня 254, у тебя 183» съедят перепись.

#### R-1.1 · Присвоение

Каждый док получает **пару значений**, не одно:

```yaml
- path: docs/architecture/audio-engine.md
  state: LIVING          # LIVING | HISTORY | REFERENCE
  visibility: public     # public | private   ← ОРТОГОНАЛЬНО state (см. §0)
  owner: 003
  date: 2026-09-03
  claims: [tsc, frozen-files]
```

Два правила разрешения споров, снимающие 90% обсуждений:

> **① Если док утверждает что-то о коде — он LIVING, либо его надо пометить HISTORY. Третьего нет.**
> **② Вопрос «HISTORY или PRIVATE?» не имеет смысла** — это разные поля. Приватный HISTORY-док нормален, публичный LIVING-док нормален, приватный LIVING-док нормален.

Выход: **`docs/DOC-CENSUS.yaml`** — метадата (два счётчика) + записи. Вход для R-3 (генерация индекса) и R-4 (гейт).

Пара работает как всегда: 003 переписывает, 003_2 бьёт выборку (прецедент: он поймал хвост ФВ-4).

⚠️ **Пересчитать сиротство.** 101 сирота из Д-2 измерена по `on-disk`-корпусу; часть объясняется тем, что публичные доки не линкуют gitignored-зоны (Д-15). В публичном срезе число будет другим — цифру перемерить здесь, не переносить из §1.

### R-2 · ФИЗИЧЕСКОЕ РАЗДЕЛЕНИЕ

| Вариант | Что делаем | Цена |

| **В** | ревизия приватности: часть 90 записей публикуется осознанно | требует чтения 90 файлов на секреты — работа, но однократная |

**Мой голос — Б** как дефолт (граница явная, ничего не теряем, ноль риска утечки), с возможностью позже перевести отдельные файлы в публичные через В. Но это 🔴, не рекомендация к исполнению.

### R-4b · G-3b — ГЕЙТ ПУБЛИЧНОСТИ (новое, следствие Д-15/Д-16)

`scripts/verify-doc-visibility.mjs`: для каждой записи `DOC-CENSUS.yaml` сверяет `visibility` с фактом `git check-ignore`.


## §3 · ПОЧЕМУ ЭТО ДО ГОРОДА, А НЕ ПОСЛЕ

Аргумент не мой — он в вашем собственном кадастре. `team-m/bLb/houses.yaml:22-24`:

> `floors: каждый этаж = реальный файл/модуль живого дерева`
> `КРИТЕРИЙ ЭТАПА 2: 19+ зданий = живые режимы, ни одного этажа без файла`

Это **контракт живости** — ровно то, что не проверяет ни один существующий гейт, и ровно то, что делает G-1. Пока G-1 нет, «этаж = живой файл» держится на том, что кто-то посмотрел глазами.

Живой пример дрейфа уже в кадастре: `deck/modules.ts:4-13` — здание «Mix» закомментировано, компонент `VolumeControls.tsx` **не в бандле** (проверено немифицированной сборкой: 0 вхождений в `dist/`), а в `houses.yaml` `mix` числится законсервированным зданием **по комментарию, а не по факту достижимости**.

⇒ Город, построенный до G-1, — это карта с домами, про которые нельзя машинно сказать, стоят ли они. Порядок: **гейты → де-фриз → реформа доков → город.** Тогда город получает не только чистое дерево, но и машину, которая держит его карту правдивой — то, что 201 сам назвал: «маркер должен проверяться машиной, а не мной».

## §5 · РИСКИ РЕФОРМЫ (сырьё для 002)

1. **Массовое перемещение файлов ломает ссылки** внутри доков (101 сирота — как раз те, кого не жалко; остальные 153 связаны). Защита: R-2 идёт **после** R-1, где связи уже описаны в `DOC-CENSUS.yaml`; перемещение — скриптом с переписыванием относительных ссылок, не руками.
2. **`git log` по перемещённым файлам** становится менее очевидным. Защита: `git mv`, один коммит на каталог, не «удалить+создать».
3. **G-3 в `fail` слишком рано** блокирует деплой на ложном срабатывании якоря. Защита: неделя `warn`.
4. **Перепись превращается в переписывание.** Защита: R-1 **только присваивает состояние**, не редактирует содержимое. Правки — отдельными шагами R-6.
5. **HISTORY-каталог станет свалкой** и через месяц кто-то начнёт «чинить» историю. Защита: правило E1-3 (фальсификация замера запрещена) — вписать в шапку `history/README.md` один раз.
6. 🔴 **ГЛАВНЫЙ НОВЫЙ РИСК (Д-16): переезд публикует приватное молча.** `git mv` из `docs/sync/` в `history/` снимает файл с ignore-правила `:66`, и 45 внутренних доков уезжают на GitHub при первом push. Обратимость плохая: удалить из индекса можно, из истории — только rewrite. Защита тройная: **① решение по варианту А/Б/В до первого `git mv`** · ② `git status` глазами после каждого перемещения каталога, до коммита · ③ G-3b (R-4b) в `warn` **до** R-2, а не после.
7. **Схлопывание `state` и `visibility` в одно поле.** Тогда перепись начнёт спорить «HISTORY или PRIVATE» — вопрос без ответа, и часть доков получит статус по спору, а не по факту. Защита: два поля в схеме `DOC-CENSUS.yaml` (§0 + R-1.1), правило ② в явном виде.
8. **Перепись стартует до канонизации счётчика** и половина работы уходит на выяснение, почему у 003 одна цифра, а у 003_2 другая (прецедент — расхождение с раундом-4 Соннета). Защита: R-1.0 — блокирующий шаг ноль, две команды.
