## 4. Правила синхрона (железно)
1. Каждый прогон заканчивается отчётом в `team-m/reports/<agent>/<task>.md` → скрипт → INBOX → **оба слышат колокол** 🔔 — это наш пульс.
2. Статусы — ТОЛЬКО в REGISTRY §7 (INBOX авто-регенерируется, durable-память — REGISTRY §5/§7).
3. Пересечение файлов запрещено матрицей REGISTRY §1; спорный файл → ратификация Hub до касания.
4. Точные правки src — MICRO-PACK → Оператор(Hub) → канон tsc 314 → браузер-тест юзера (логи+описание) → закрытие в REGISTRY.

## 5. Отказоустойчивость прогонов (проверено live)
Провайдер спавна иногда блипает («Upstream Endpoint is unavailable» / rate-limit 48/48 на фритире x-preview-f-free). Протокол деградации:
1. **Инлайн-роли** — исполнить [Ф001→Ф002→Ф009] внутри своей сессии без спавна (метод Мака, доказан Packet-1; применено Hub на P1#6).
2. **Носитель Оператор** — `operator` = big-pickle, отдельный пул (49/49), стабилен весь день (P1#6 применён им же).
3. **НОСИТЕЛЬ СКАУТ** 🔥 — `arch-scout` имеет СВОЙ счётчик (`SCOUT-OK`, полная цепь P1#4 идёт через него) — полноценный канал для исследовательских ролей при мёртвом фритире.
4. **Делегация лаборатории** — перекинуть исследование на второй фронт через REGISTRY/SYNC.
5. Ретрай обычного спавна после ресета фритир-лимита.

## 6. Статус дуэта (директива Босса)
**Mac = исследовательская лаборатория №2, PC = лаборатория №1 + исполнение. Hub = директор:** распределяет фронты (§1–3), ратифицирует, применяет Оператором. Лаборатории равноправны в исследованиях, фронт — по матрице возможностей §0.
