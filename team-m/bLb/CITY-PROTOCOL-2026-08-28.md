# CITY-PROTOCOL · beLiveBase · 2026-08-28
Статус: DRAFT v0.2 (Мак, по итогам дня дизайна с Боссом)
База: bLb-CITY-v0.2-quiet.html (GLM, одобрена Боссом 28.08) — город молчит, говорит только то, на что указали.

## 1. Что такое город
Город — игровая форма управления репозиторием, интегрированная прямо в репозиторий.
Не визуализация рядом с кодом, а интерфейс кода:
- читает реальный кадастр (houses.yaml + city-metrics.json),
- слушает реальные события приложения (EventBus v2),
- пишет обратно в репо (смена статусов зданий → дифф houses.yaml → журнал).

## 2. Слои данных
| Слой | Файл | Кто пишет |
|---|---|---|
| Кадастр (единственный источник) | team-m/bLb/houses.yaml | Мак/007, изменения через журнал |
| Метрики (loc/files/t30) | team-m/bLb/city-metrics.json | ПК: node team-m/bLb/city-metrics.mjs |
| Сценарий тура | team-m/bLb/tour.yaml | Мак/Босс |
| Журнал действий | team-m/bLb/city-journal.yaml | 007 по итогам сессий города |
| Сгенерированное состояние | team-m/bLb/city-state.json | city-gen (не редактировать) |
| Рендер | team-m/bLb/bLb-CITY-v0.2-quiet.html | city-gen инъекцией (маркеры CITY-STATE/TOUR) |

## 3. Контракт здания (houses.yaml)
Обязательные поля рендеримого здания:
- key (id города), quarter (имя), district, arch, grid {gx,gy,w,d}, modules, owner, status
- what — что делает, простыми словами (1 фраза)
- gives — что даёт пользователю как инструмент (список)
- rooms — "Название|описание" (смысловые модули = комнаты интерьера)
- metrics {loc, files, t30} — t30: -1 = ещё не посчитано ПК
Опциональные: route (маршрут приложения), frozen (sealed|read), gate (имя гейта), render (none|external).

Правило правды: визуал не врёт. Высота = f(loc), окна/свечение = f(t30), статус = силуэт.
Числа из головы запрещены: только замер (city-metrics.mjs) или помеченная оценка.

## 4. Статусы и переходы
alive | demo | planned | conserved | trash | cleared | external
- Переходы выполняются пультом города (кнопки в осмотре здания).
- Снос (trash→cleared) — только двойным подтверждением и только при пройденном гейте.
- Стройка (planned→alive) — только при пройденном гейте.
- Гейты объявлены в meta.gates houses.yaml: W5 (снос мастерской, BAC-107), rehearsal-prod (стройка Арен).
- Гейт считается пройденным, когда в houses.yaml state: passed (меняет 007 по факту волны/релиза).

## 5. Запись обратно (город → репо)
1. Действие в городе попадает в JOURNAL (в памяти) и в шёпот.
2. beLiveBase.exportCadastre() отдаёт текущие статусы; beLiveBase.journal() — историю.
3. 007 переносит подтверждённые переходы в houses.yaml (status) и в city-journal.yaml (аудит).
4. city-gen перегенерирует город. Никаких правок HTML вручную между маркерами.

## 6. Контракт событий (метро)
Имя линии метро = реальное событие EventBus v2 в формате канал:событие
(реестр: src/foundation/event-bus/types.ts, 28 событий) или служебное city:*.
Приложение кормит город: beLiveBase.emit({type:'sync:active-line-changed', from:'sync', to:'show', text:'...'}).
События, которых нет в шине (темы, реплики Билли) — городские city:* до появления реальных.
Известные дыры маппинга: темы/пресеты (нет события в EventBus v2), питч (legacy main.js вне шины).

## 7. Валидация (дисциплина frozen-guard)
city-gen.mjs падает (exit 1) если:
- у здания нет what/gives/rooms; неизвестный статус/архетип/квартал; grid вне границ 15x14;
- гейт не объявлен; метро ссылается на несуществующее здание; событие метро не в реестре и не city:*.
Предупреждения (не падение): t30 не посчитан, здание без линий метро, квартал без здания на карте.

## 8. Тур (YouTube-режим)
tour.yaml: цепочка остановок {building, dur, say, zoom}; building: center = общий план + CTA.
Проигрывается цепочка, не трек (Босс, 28.08). Для каждого ролика — свой tour-файл.

## 9. Разделение труда
- ПК (Вёдра): node team-m/bLb/city-metrics.mjs → node team-m/bLb/city-gen.mjs; финиш v2→v3 (W4/W5).
- Мак: кадастр, протокол, дизайн-итерации, разведка. src/ не трогает, пока PC в волне.
- Внешние Центры (GLM и др.): только рендер-слой по брифу; данные и контракт — всегда из репо.
