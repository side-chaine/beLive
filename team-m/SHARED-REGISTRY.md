### Правила записи (обязательны)

1. Блок: `## LOG YYYY-MM-DD <кто> — <тема>`. **Новый блок — сверху**, старые не трогать.
2. **Первая строка блока — модель и машина.** (Пробел с «Hy4 = ?» закрыт: **`hy4-preview`**.)
3. Формат доказательств: **`file:line`**. Утверждение без строки — мнение.
4. **≤250 слов** на блок.
5. **Не трогать чужие блоки.** Возражения — отдельным блоком `CROSS-CHECK`.
6. Перед словом «не существует» — **назови HEAD, в котором грепал**.
7. Верить **SHA**, не имени ref: `git show <sha>:path`, `git ls-tree <sha>`, `git grep <sha> -- src`.
   (⚠️ Ловушка **выстрелила 30.08 00:52**: `git fetch` напечатал `cdfb2eb..96d4c2d main -> origin/main`,
   но `git rev-parse refs/remotes/origin/main` → **`cdfb2eb`** (старый). Истинный tip брать
   **`git ls-remote origin main`** → `96d4c2d`. Проверка `96d4c2d..refs/remotes/origin/main`
   дала **пустоту не потому, что новых коммитов нет, а потому что ref отстал**.)

## LOG 2026-08-30 17:59 · 005_2 — ОХОТА №1: НАУЧНАЯ БАЗА ПИТЧА (YIN-vs-pYIN-vs-MPM + FFT-ускорение + CREPE-рамка) · 4/4 ТЕМ ДОБЫТЫ

**Модель: GLM 5.3 Free · ПК/Linux/openCode · HEAD `9b6bf83` (лок.) · зона §2 канала: статьи/алгоритмы**

Сверка с нашим кодом перед поиском (не по памяти): `src/audio/pitch/yin-detect.ts:84-92` — difference-функция O(N²)
(τ≤1024 × j<1024 ≈ **1.05M операций на кадр** при 21.5 Гц), шаги 3-4 (порог 0.15, параболическая интерполяция),
уровни octLock/rangeClamp/median/autoCal :154-226 — самодельные. Работа 005 подтверждена: pitchy=MPM (0BSD) A/B-оппонент.

**Добыча (первоисточники, не пересказы):**
1. **pYIN** (Mauch&Dixon, ICASSP-2014, DOI 10.1109/ICASSP.2014.6853678): вместо одного порога 0.15 — **100 порогов из
   Beta(2,18)** + **Boltzmann-приор** по локальным минимумам + **Viterbi** по цепочке кадров. Канон-реализация
   `librosa/core/pitch.py::__pyin_helper` (получена через Context7): `n_thresholds=100, beta_parameters=(2,18),
   boltzmann_parameter=2, resolution=0.1` (10-цент бины), `switch_prob=0.01`. **Ключ:** наш octLock+median — детерминированные
   эвристики, заменяемые одним вероятностным слоем; голосование порогов убирает «дико неверные» кадры YIN, которые признаёт
   даже pitchfinder README.
2. **MPM/NSDF** (McLeod, Tartini-наследник): NSDF-нормировка + отсечение пиков 0.97 от максимума + параболическая
   интерполяция. Сильнее YIN на низких частотах (бас-зона); в pitchfinder `cutoff` конфигурируется (0.93 для баса).
   Подтверждает: наш vocal-range 75-1200 Гц с упором в бас — точка, где pitchy может выиграть A/B.
3. **FFT-ускорение YIN-разности** (тема ③, канон librosa `_cumulative_mean_normalized_difference`): 
   **d(τ) = 2·(ACF(0) − ACF(τ)) − E(τ-1)**, где ACF через **rFFT/irFFT (Wiener-Khinchin)**. Наш наивный цикл
   (yin-detect.ts:84-92) ≈1.05M ops/кадр → FFT-путь = **2 FFT по 4096 + O(N)** ≈ 0.1M ops — **~10× CPU** на main thread
   (46ms-тик, пассивный тап). Точные формулы: ACF(0) − ACF(τ) из power-spectrum, E = кумулятивная сумма квадратов.
   **Дельта для V3:** пассивный vocal-тап может себе позволить fftSize 4096 (для 70 Гц нужен τ=630, наш tauMax=1024 при
   2048 это позволяет — с FFT-путём цена не квадратичная).
4. **CREPE-рамка** (Kim et al., ICASSP-2018, arXiv:1802.06182 — ID перепроверен через arXiv API после промаха по памяти):
   CREPE ≥ pYIN по точности. Для нашего A/B-стенда: офлайн-прогон CREPE (ML-эталон) vs наш YIN vs pitchy на общих стемах
   → метрики MIREX: RPA/RCA/VR/VFA (raw pitch/chroma accuracy, voicing recall/false alarm). Формат для RESEARCH-досье.

**Вердикт для пазла:** наш YIN — костяк верный (шаги 1-4 = канон YIN-2002), но три слоя самоделок (octLock/median/autoCal)
= «дешёвый pYIN». Кандидат: **АДАПТИРОВАТЬ** — п.1 (pYIN-слой над нашим YIN) и п.3 (FFT-путь) как два отдельных минимальных
усиления. Не трогаем frozen. Внедрение — через 200 → 007 → Оператор. Досье в PUZZLE следом.

**Инструменты:** Context7 (librosa/pitchfinder первоисточники) + webfetch (arXiv API против ложных ID) + чтение нашего
