**⇒ VDL живёт в своей БД `beLive_voice` v1. `TextAppDB` не трогаем ни на единицу.**

## §2 · (а) СХЕМА СУЩНОСТЕЙ — поля и обоснование каждого

### VoiceFrame — НЕ персистится (рабочая единица, 46 мс / ~21.5 Гц: `pitch-engine.ts:165-167`)

Уже течёт сегодня, новый код не нужен:

| Поле | Источник | Зачем |
|---|---|---|
| `f0`, `confidence`, `midi`, `rms` | `yin-detect.ts:154-160` | база высоты и уровня |
| `subharmonicRatio` | `yin-detect.ts:126-135` | расщеп/сабгармоника (семейство growl) |
| `noiseSFM` | `pitch-engine.ts:183-199` `_computeSFM` | шумовой признак, работает **без** питча (скрим/раск) |
| `kind: 'pitch' \| 'no_pitch' \| 'silence'` | `pitch-engine.ts:222-232` | дискретный канал — единственный честный признак тишины |

Новое, минимальное — **АЧХ по директиве Никиты**: `bands: Float32Array(24)` — 24 логарифмические полосы (≈50 Гц…8 кГц), свёрнутые из `getFloatFrequencyData`. Обоснование: 512 сырых бинов ×21.5 Гц — это ~1 МБ/мин мусора, который никто не прочтёт; 24 полосы дают форму спектра (то, что нужно и человеку, и модели) при 48× меньшем объёме. Число полос — константа спеки, чтобы снапшоты были сравнимы между версиями.

### VoiceMetricAggregate — **персистится**. Окно 500 мс ≈ 11 кадров

| Поле | Обоснование (почему именно это) |
|---|---|
| `sessionId`, `seq`, `t0`, `t1` | адресация без глобального времени; `seq` ловит пропуски окон |
| `frameCount` / `validCount` | **честность выборки**. Без пары «сколько было / сколько годно» любая медиана — ложь |
| `voicedRatio` | доля `kind==='pitch'`. Без неё медианы f0 считаются по тишине и врут систематически |
| `f0Median`, `f0MadCents` | медиана и MAD, **не среднее**: YIN даёт октавные выбросы, медианный фильтр уже стоит в детекторе (`yin-detect.ts:180-191`) — среднее их протащит |
| `rmsMedian`, `rmsPeak` | median = уровень, peak = клиппинг-гейт (порог 0.95) и детектор observer-effect |
| `subMedian`, `noiseMedian` | два **независимых** признака шума ⇒ перекрёстная валидация; расхождение = кадр не годен |
| `bands[24]` | медиана по кадрам, дБ. Это и есть «полный спектр / АЧХ» в агрегированном виде |
| `quality: 'green'\|'yellow'\|'red'` | вычислен на записи, не при чтении — иначе завтрашний код переоценит вчерашние данные |
| `deviceId` | из `stream.getAudioTracks()[0].getSettings().deviceId`, **не** из `MicSourceV3.deviceId:29` (тот слеп при `''` — вердикт 009 Д-4) |
| `schemaVersion` | версия **в записи**, не только в БД (см. §6) |

Объём: ~400 Б/агрегат × 2/с ⇒ **≈2.9 МБ/час** сырых агрегатов. Ретенция обязательна (§4).

### VoiceSnapshot — **это C1-C8 из SLEPOK, а не вторая сущность**

Спека SLEPOK-FINAL v1.0 уже прошла цепь 001→002→009 и определяет C1-C8. Но она персистит в `localStorage 'belive:voice-profile'` (`SLEPOK §1`), а VDL — в IDB. **Если оба поедут как написаны, получим два параллельных слоя голосовых данных — тот самый шрам V2-эпохи, который директива запрещает.**

⇒ Требование к цепи: `snapshots` — store в `beLive_voice`; SLEPOK v0.1 берёт персист оттуда. C1-C8 не переопределяются (они уже отсужены), добавляется только провенанс: `fromAggregates: [seq...]`, `schemaVersion`, `deviceId`, `createdAt`.

### VoiceProgram — заголовок, тела нет (см. §7 анти-скоуп)

**Факт разведки:** механики согласия в проекте **нет** (grep `consent|gdpr|privacy|retention` по `src` + `js` + `gateway` — 0 содержательных попаданий).

**И более важный факт: обязательство уже существует, до всякого VDL.** Аудио пользователя уже покидает устройство: `src/services/mvsep.service.ts:175-176` и `:214-220` грузят `audiofile` на `mvsep.com` (напрямую либо через воркер `belive-mvsep/index.js:105`). Гейта согласия на этом пути нет. ⇒ Гейт не «включается при старте В4» — он **опаздывает** уже сегодня, а VDL просто первый, кто обязан его иметь по построению.

**Три отдельных вопроса пользователю (гранулярно, не одна галка):**
1. локальный анализ голоса — метрики остаются на устройстве;
2. отправка **сводок** (не сырья) в облако — отдельно;
3. экспорт-паспорт — отдельно, по действию.

**Хранение согласия:** одна запись в `beLive_voice.sessions`-соседе `consent` (или `app_state`): `{ state: 'not-asked'|'granted'|'denied', scope, textVersion, at }`. Один писатель — `src/audio/voice/voice-consent.ts`.

**Гейт уровня frozen-guard (машина, не дисциплина):** `scripts/check-voice-gate.mjs` в `verify:ci` — статическая проверка: ни один файл `src/audio/voice/**` не обращается к `indexedDB`/`fetch` иначе как через `voice-consent.ts`. Прецедент такого статического гейта в проекте уже работает: К-7 static-grep через `?raw` (`src/audio/pitch/__tests__/pitch-engine-modes.test.ts:149-153`). Дёшево, машинно, не полагается на память людей.

**Retention:** ① срок — сырые агрегаты 30 дней, снапшоты бессрочно (они крошечные); ② объём — переиспользовать `src/utils/storage-quota.ts:16-41` (`navigator.storage.estimate`, уже написан); ③ **удаление одной кнопкой** «удалить мои голосовые данные» → `clear` трёх stores + delete-запрос в D1. Кнопка входит в первый же коммит, не «потом»: право на удаление, добавленное позже, всегда добавляется хуже.

## §6 · (д) МИГРАЦИЯ СХЕМЫ: от первого агрегата до паспорта

1. `schemaVersion` — **в каждой записи**, не только в версии БД. Прецеденты: `dataVersion` в `TrackRecord` (`idb.service.ts`) и `version`+`migrate` у zustand-persist (`user-profile.store.ts:187-200`).
2. **Только аддитивные поля.** Читатель обязан работать с минимальным набором v1 и не падать на отсутствии новых.
3. **Старые агрегаты никогда не перезаписываются** при росте схемы. Пересчёт задним числом = фальсификация замера (правило E1-3 пары 003) — вместо этого новый агрегат с новой версией.
4. `DB_VERSION` у `beLive_voice` растёт **только** при добавлении store/index. Изменение полей внутри записи версию БД не двигает.
5. Снапшот несёт `fromAggregates` ⇒ через год можно ответить «на каких данных это посчитано», не веря на слово.

## §9 · ЦЕНА / РИСК (честно)

- **Главный риск не технический.** Все механики уже живы (YIN, SFM, MicSource, IDB-паттерны). Риск — что VDL напишут в стиле окружающего кода (`?.` + молчаливые фолбэки), и он полгода будет собирать пустоту. Единственная защита — self-test + статический гейт, а не аккуратность автора.
- **Второй мик-тап** = +1 AnalyserNode + main-thread YIN при 21.5 Гц. Прецедент нагрузки уже в проде (vocal-трек PitchTab). Но VoiceTap обязан `release()` при выходе — иначе тёплый микрофон живёт вечно.
- **tsc:** новые файлы чистые; ожидаемая дельта 0. `beLive_voice` не пересекается с существующими БД по имени (проверено: `TextAppDB`, `beLive_scenes`).
- **Ключи localStorage** VDL не использует (канон `belive:` остаётся за настройками, данные — в IDB).
