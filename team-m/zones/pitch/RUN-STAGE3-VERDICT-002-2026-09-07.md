## Удары по утверждениям 001 (1-7)

**Удар-1.1 · Пороги — скрытая движко-зависимость (💰💰):** архитектура агностична, ПОРОГОВЫЙ СЛОЙ — нет: NoteTracker 0.6/0.4 (note-tracker.ts:21-22), NoteQuantizer 0.5 (note-quantizer.ts:33), VAD 0.6/0.45, autoCal 0.7 (yin-detect.ts:147) — всё калибровано под YIN conf=1−cmnd[te]. При победе C confidence = pYIN-posterior, ДРУГАЯ ШКАЛА (спека стенда признаёт: «confidence несравним между контурами»). Вердикт C молча ломает каждый потребительский порог. → требует: семантика PitchFrame.confidence (норм. voicing-вероятность) ЛИБО пороги=config, пересчитываемые вердиктом; VAD-пороги ПОСЛЕ вердикта.

**Удар-1.2 · Близнецы не равны по построению — УЖЕ сегодня (💰💰):** yin-detect.ts:104-107 при te=−1 делает fallback te=minTau и ВОЗВРАЩАЕТ pitch; yin-processor.js:132-135 при te=−1 шлёт no_pitch. Один кадр (шумный/breathy) — разные вердикты в двух ветках продукта. «Контракт равенства + тест-сравнение» провалится на первом прогоне. → уравнять (вне RASP-точек) ЛИБО задокументировать контракт различия + отдельное покрытие mic-ветки.

**Удар-2.1 · Reference-кривой нет дома (💰💰):** граф = ДВЕ кривые; ring хранит PitchSample только на 'pitch'-сообщениях (pitch-engine.ts:326-334) — silence/no_pitch не пишутся; offline reference-JSON живёт ВНЕ ring. Кто владелец, как rAF-читатель получает доступ при «store спит до V2»? + маркеры разрывов (иначе линия графа соединяет через 5-сек паузы).

**Удар-2.2 · NoteTracker ест integer-midi — Quantizer выпал (💰):** NoteTracker.update ожидает integer MIDI (note-tracker.ts:52); PitchFrame.midi = непрерывный. Кормление напрямую: midi≠currentMidi КАЖДЫЙ кадр → ветка note-change → endCurrentNote+push каждые 46мс → длительность < MIN_NOTE_DURATION 80мс → splice → клава стробит пустыми нотами. → цепочка PitchFrame→NoteQuantizer→NoteTracker явно.

**Удар-2.3 · Владелец движков не назван — ARC-2e-мина (💰💰):** PitchTab владеет ЛОКАЛЬНЫМИ инстансами (мина задокументирована pitch-engine.ts:22-26). PitchFrame-слой = третий потребитель: свой инстанс (CPU ×2) или get() (cleanup destroy() убьёт singleton). → назвать владельца жизненного цикла.

**Удар-2.4 · ring=300 ≈ 14с (💰):** скролл ±5-7с ок, но если пиксель-спека потребует >14с — capacity молча обрежет. → capacity=параметр после пиксель-замера.

**Удар-3.1 · Пороги без октавной политики = вердикт о не-том (💰💰):** BLEED-окно №1 (τ±1 октава вокруг reference-F0) лочит юзера в октаву эталона. Мужчина поёт женскую партию октавой ниже: F0=ref/2 — ровно НА границе; чуть флэтнул → кадр отвергнут → вечное «не попал» при идеальном интонировании. ПАК-4 обещает SingStar humming-зачёт (октав-агностик) — паки противоречат друг другу, 001 не свёл. Клава-вид с перескоком октав допускает мобильность, которую BLEED-окно запрещает. → октав-политика ДО порогов.

**Удар-3.2 · Пороги без dwell стробят (💰):** вибрато ±50-100ц на 5-6Гц → «попал» мигает GOOD↔LOW 5-6 раз/сек. ПАК-4 исследовал dwell — направление уронило. → dwell ~100-150мс в hit-логике.

**Удар-4.1 · Стенд докажет не то (💰💰):** (а) ~2% — аналитика, не эмпирика; (б) протокол меряет performance.now вокруг detect(), а тик = detect + getFloatFrequencyData (FFT) + _computeSFM (~470 бинов Math.pow/log) + push + listeners; (в) при победе C → mic-ветка: worklet-бюджет (audio-thread, аллокации — в _median `var a=[]` каждый кадр) стендом НЕ покрыт (скоуп У8 = vocal-tap). → полный тик в протоколе + worklet-гейт при победе C.

**Удар-5.1 · 💀 playbackRate сдвигает ПИТЧ — коридор умирает (блокирующее):** AudioBufferSourceNode.playbackRate сдвигает высоту линейно (StemPlayerV3.ts:165); preservesPitch у буферных источников нет. B·P·M ±5% = ∓89ц — УЖЕ за коридором ±50ц; practice 80% (реф-GPT-A «Скорость 80%») = −386ц. Юзер поёт то, что СЛЫШИТ → каждый кадр «не попал» у идеально поющего. Alignment-v0 не содержит rate-члена. → rate-компенсация явным пунктом.

**Удар-5.2 · Loop-врап + ctx.currentTime (💰💰):** ring-таймстампы = ctx.currentTime (монотонный); loop → media-time прыгает НАЗАД, ctx-время нет → наивный lookup тянет кривую из чужого места трека после первого врапа. → lookup по transport media-time (HybridClock — стык) + loop-врап-тест.

**Удар-5.3 · Tolerance без note-level матчинга (💰💰):** юзер на 0.7с позади — внутри допуска, но deviation против ref[t] на границе нот = ЧУЖАЯ нота → «не попал» у поющего правильно. → nearest-reference-note-in-window (v0.5) ЛИБО задокументированный лимит.

**Удар-6.1 · Симметричен алгоритм — асимметричны СИГНАЛЫ (💰💰):** mic: HPF80+LPF2000 (pitch-engine.ts:113-118); passive/reference: анализатор напрямую БЕЗ фильтров. Сопрано E5 (~659Гц) на mic: LPF-2000 оставляет F0+~2 гармоники → CMND-дипы хуже → conf ниже → VAD-гистерезис режет voiced-кадры юзера, которых reference-ветка не режет → дырявая юзер-линия против полной «Оригинала». → одинаковый front-end ЛИБО обоснование LPF.

**Удар-6.2 · Offline-проход без voicing-гейта = мусорный JSON (💰💰):** YinDetector при te=−1 ВСЁ РАВНО возвращает F0 (fallback minTau); null — только при rms<gate. Вдохи/bleed получат f0 с conf 0.2-0.5 → «Оригинал» рисует траекторию сквозь вдохи. CREPE-exclusion из протокола стенда в reference-спеку не перенесён. → voicing-политика (conf-гейт+мин-длительность).

**Удар-6.3 · «В воркере» без пути данных (💰💰):** 3-мин стем ≈ 30-60МБ float32; transfer = detach (нельзя); копия — блок track-load; SAB = COOP/COEP (не факт в деплое). → моно-даунмикс + чанковый перенос + readiness-контракт (деградация без «Оригинала», не блок).

**Удар-7.1/7.2:** клава-строб (см. 2.2) + разная октав-мобильность клавы и BLEED-окна (см. 3.1).
