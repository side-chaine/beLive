## §1 · ВЕРДИКТ ПО GPT-РЕКОМЕНДАЦИИ (Migration Map + PHASE R1 SURFACE EXTRACTION)

**ПРИНЯТЬ В РАБОТУ С ДВУМЯ ПОПРАВКАМИ.** Ядро рекомендации железное и совпадает с нашей А1-доктриной ХАБа + принципом «legacy demolition last» (который Split уже зафиксировал в своём прогоне):

✅ **Принимаем:** (а) «старые механики → новые поверхности», старый ControlDeck = fallback до конца реформы; (б) PHASE R1 = SURFACE EXTRACTION: зафиксировать actions → вынести mixer/transport/BPM/deck-navigation actions из JSX → новый UI подключается к тем же actions → снос последним; (в) нормализованные actions типа `setInstrumentalLevel(value)` — маршрутизация (V3+stems→music-bus / иначе→instrumental / exercise→override) живёт ВНУТРИ action, новый UI не знает о ветках; (г) фейдеры = первый кандидат на extraction: текущие — голый div+mousemove (проверено мной: нет keyboard/touch/aria/focus/pointer-capture — GPT прав полностью); (д) его Migration Map v1 (объект→где→механика→новый UI→reuse/do-not-touch/delete) — формат совместим с нашей OLD-MECHANICS-MAP ХАБа (12 объектов, сдан 23:50).

⚠️ **Поправка-1 (граница полномочий GPT):** его «я сам пройду слой репозитория и сделаю Migration Map» — НЕТ, не GPT-руками. У нас уже есть ХАБ-карта (12 объектов) и зонные агенты-хозяева. GPT-рекомендация = ВНЕШНИЙ РЕВЬЮОР: его карта ляжет ВХОДОМ на верификацию ХАБу (пересечение с OLD-MECHANICS-MAP: что GPT увидел, чего не видит ХАБ, и наоборот — дифф двух карт ценнее одной). Никита кормит GPT картой ХАБа → GPT ревьюит → расхождения — на мой арбитраж.

⚠️ **Поправка-2 (порядок до красоты):** GPT предлагает «первым делом» переписать фейдеры на полноценный slider-контрол (keyboard/aria/touch). ДА, но НЕ первым шагом реформы: сначала R1-extraction (механика отделяется от визуала — это и делает возможным безболезненно переписать control-слой), потом в [SB] новый контрол пишется сразу правильным (включая Phone-слой: touch/pointer-capture — это как раз горизонталь агента-Phone). Порядок: extraction → новый surface с правильными контролами → снос legacy.
