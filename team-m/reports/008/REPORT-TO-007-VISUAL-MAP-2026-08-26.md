## 4. ПАЙПЛАЙН СЕРВИСОВ (полная картина от владельца)

**Загрузка трека:**
1. **MVSEP** (mvsep.com) — stem-separation; владелец режет треки внешне, zip → ПОРТ. API-интеграция «трек в beLive → API → MVSEP → обратно» ПРОБОВАЛАСЬ, не пошла, **отложена до полного аудита**; план — свой API-ключ у каждого пользователя (лимит MVSEP ~49/день).
2. **ПОРТ** — дроп .ZIP в каталоге; **Ручная загрузка** — DUO-путь (Instrumental required + Vocals + Lyrics).
3. **Genius** — текст лирики + названия секций → **TrackMap формируется автоматически**; beLive сам чистит рекламу и распределяет по блокам. Нужна регистрация на Genius (кнопка edit → Ctrl+A/C).
4. **lrclib.net** — тайминги строк; версии в кнопке **Lines** (14 версий: длительность/число строк/Δ-сдвиг, бейдж ACTIVE). Будущее: ИИ выбирает версию сам.
5. **GetSongBPM** — BPM, тональность, данные карточек DNA; обязательна атрибуция-ссылка (сейчас перехватывает Back — баг #4).
6. **gateway-align** — сервер пословной синхронизации (Word-режим); статус `gateway-align:missing` виден в UI Sync.
7. **Telegram** — TG-каталог через бота (воркер существует; в сессиях «недоступен»); ZIP/TG/Publish из Sync — выгрузка обработанных треков в TG.
8. **OpenRouter** — свой AI для Билли (ключ/модель/temperature) + Built-in AI.
9. **Cloudflare-воркеры** — владелец обещал скриншоты всех воркеров: **НУЖЕН ПОЛНЫЙ АУДИТ** (его слова: «нам нужна полная картина, полный аудит»).

**Концепция владельца (дословно):** «beLive — это некий сосуд, который может подсветить трек; насыщать, заливать этот сосуд будет само наполнение трека». Все механизмы (фоны, сцены, HTML-проекции, DNA) строятся как мостик к тому, чтобы **ИИ-ассистент управлял ими и помогал пользователю**.

## 5. СТРАТЕГИЧЕСКАЯ РАЗВИЛКА (VMO-020)

Центральная вкладка = **hub beLive** (соцсеть: комьюнити, взаимодействие музыкантов). **НО:** в РФ создание соцсети юридически непросто → владельцу нужно **глобальное исследование** «что могу/что не могу». Запасная модель — **«пейджер» (односторонняя связь)**: beLive публикует упражнения/посты/статьи, пользователи принимают. Критерий: без рисков владельца.
