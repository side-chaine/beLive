## ГЛАВНОЕ АРХИТЕКТУРНОЕ РЕШЕНИЕ

Фасад роутит transport-команды **через `TransportV3`, а не через HPS напрямую**. Причины (проверено по коду):
- HPS `play(offset,rate)` — низкоуровневый «старт стемов»: не трогает HybridClock, не ставит state, не диспатчит `statechange` → V3StatePublisher молчит → `useAudioStore.isPlaying` не обновится → UI и Rehearsal не узнают о play. Прямой HPS-вызов = рассинхрон машины состояний.
- TransportV3 `play(initialOffset?)` / `seek(time)` **сам** берёт offset из clock (:157) и rate из clock.playbackRate (:158, :229) → проблема «откуда rate для play/seek» исчезает целиком. Гейт `idle/paused/ended`, autoplay-resume, seek-generation-guard, flush rate-throttler, `publishSeek` кэша — всё уже решено.
- Двойной HPS transport-lock невозможен: transport → `_restartStemsAt` → один `pipelineController.play` (:304-310) → один lock.
- ⚠️ **РАСХОЖДЕНИЕ СО СКАУТ-ПАКЕТОМ**: `__belive.transport` в main.tsx **НЕ публикуется** (есть только дебаг `__tp` :188 и `__getTransport` :185). Нужна 1 строка в main.tsx:170-175 блоке: `(window as any).__belive.transport = transport`. main.tsx НЕ frozen.

## PLAY-СЕМАНТИКА (offset-решение)

`play(offset?)` → `transport.play(offset)` — «продолжить с текущей позиции» честно выполняется самим TransportV3: из `paused` resume продолжит с точки паузы **вопреки** переданному offset (:130-134: initialOffset применяется только из idle/ended). HPS-рестарт-семантика не наша проблема — transport сам вычисляет offset=clock (:157) и rate=clock (:158) и зовёт `pipelineController.play(offset, rate)` ровно один раз. Rate вручную НЕ добываем нигде — весь вопрос диспатча «откуда rate» растворяется роутингом через transport. Hijack зовёт `origPlay(...args)` без аргументов → `undefined` → resume-семантика ✓. Опциональный `offset`-параметр — задел: `play(t)` из idle стартует с позиции (будет нужен для студента-новичка, см. Риски).

## STOP/двойной-стоп вердикт

**Наполняем: `stop() → transport.stop()`. Двойной стоп невозможен** — проверено по обоим путям:
- **loadTrack-путь** (track.loader): `before-track-change` c detail → main.tsx:212-213 стопает transport+pipeline, но track.loader фасадный stop() НЕ вызывает. Однократный стоп.
- **deleteTrack/clearAll** (track.actions:57-58/:157-160): диспатчат `new Event('before-track-change')` **БЕЗ detail** → main.tsx:208-209 `if (!trackId) return` — ранний выход, transport НЕ стопается! Фасадный stop() — **единственный** стоп в этом пути. Сегодня (пустышка) удалённый трек играет дальше — это и есть латаемый баг.
- Подстраховка: `TransportV3.stop()` сам идемпотентен (`if (state === 'idle') return`, :185).
