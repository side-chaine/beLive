## ОТДЕЛЬНЫЙ ВЕРДИКТ: G14-ЗНАК (пункт ⑤ диспатча) — ФИЗИКА С ЧИСЛАМИ

### Тракт (по живому коду)

- **Playback-путь**: programInput → _mainBranch → _mainDelay → _hallMaster → mainStream → `<audio>`-элемент (DeviceManager.ts:44 `el.srcObject = mainStream`) → уши. Задержка = **outputLatency ≈ 43мс**.
- **Мик-путь**: raw mic → [RNNoise-граф: **+rnnoiseDelay**] → micInput (MonitorRouter.ts:140) → _micDelay (:141) → _monitorGain → _monitorMaster → monitorStream → `<audio>` → уши.
- Текущий G14 (MonitorRouter.ts:165-167): `compMs = outputLatency*1000; _micDelay = compMs/1000` — допущение: мик-тракт без компенсации мгновенный (inputLatency ≈ 0, RNNoise = 0).

### Инвариант G14

`micDelay = (задержка playback-тракта) − (задержка мик-тракта без micDelay)`

С RNNoise: `micDelay = outputLatency − rnnoiseDelay` → **`compMs −= rnnoiseDelayMs`**. **001 ПРАВ. Диспатч 007 с «+=» — физически ошибочен**: micDelay = 43+delay → мик опоздает на 2×rnnoiseDelay относительно трека.

### Числа — и ошибка 001 в величине задержки

- RNNoise-модель ест **кадры 480 сэмплов @ 48к = 10мс** (не 128!). AudioWorklet-квант = 128 → ворклет обязан буферизовать ≥ ceil(480/128) = 4 кванта = **10.67мс минимум**; FIFO 1-2 кадра → **rnnoiseDelay ≈ 10-21мс**.
- Спека 001 «frame 128 сэмплов… 2.7-5.3ms» — **занижение в 2-4 раза**: rnnoise не работает с 128-сэмпловыми кадрами, его модель = 480. Источник ошибки — путаница worklet-кванта (128) с кадром модели (480).
- Правильная формула: `delayTime = max(0, outputLatency*1000 − rnnoiseDelayMs)` → при 43мс и 10-21мс: **22-33мс**.
- Вариант диспатча (+=): 53-64мс → рассинхрон 20-42мс — **за порогом слышимости** (~20мс для вокала, 5-10мс для перкуссии). Мик в наушниках будет «отставать» от собственного голоса — хуже, чем без компенсации вовсе.

### Вердикт G14

**001 ДЕРЖИТ по знаку (−=), НО число rnnoiseDelayMs в спеке занижено (2.7-5.3мс → фактически 10-21мс).** Патч-условие: константа rnnoiseDelayMs = 10.67 (1 кадр 480, консервативно 21 при FIFO=2 — измерить в круге-3 импульсом). Формула: `max(0, compMs − rnnoiseDelayMs)`. RN-7 тест обязан ассертить обе границы (10.67 и 21) — не «магическое 5.3».

## АТАКИ ПО ПУНКТАМ ①-⑧

### ① MicGraphV3 = расширение MicSourceV3, acquire() отдаёт denoised

**УДАР 1 (КРИТ): тоггл denoise в рантайме под живыми потребителями.**
Сценарий: 🎤 ON → ControlDeck.tsx:401 `src.acquire()` → raw-стрим → `__micMonitorNode` подключён к raw (:407-409). Пользователь жмёт шумодав → setDenoise(true) строит граф → acquire-семантика меняется, но `__micMonitorNode` **уже держит старый raw-стрим**. Питч-ворклет (pitch-engine.ts:86 `this._stream`) — тоже. «Потребители слепы к шумодаву» = они не узнают о смене стрима никогда.
→ Последствие: тоггл в рантайме — заявленная фича спеки (②: «Тоггл в рантайме = пересборка только графа, НЕ стрима») — **не работает для уже подключённых потребителей**. UI показывает ON, уши слышат шум, питч ест сырой сигнал. Провал фичи, не деградация.
→ Проверка удара: ломается при ЛЮБОМ ON после acquire от 🎤/REC/питча. RN-тесты 1-8 не покрывают «живой потребитель при тоггле» — RN-3 проверяет acquire ПОСЛЕ setDenoise(false), не подключённый до.
→ Патч: **UI-гейт — тоггл denoise разрешён только при refCount=0** (кнопка disabled при живом 🎤/REC/питче). Дешевле event-переподключения, закрывает класс «смена стрима под потребителем» целиком (включая удар 2). Альтернатива (event + переподключение ControlDeck/pitch-engine) — +2 движущиеся части, против канона «минимально».

**УДАР 2 (лёгкий): acquire при denoise ON, но WASM ещё не готов.**
Сценарий: setDenoise(true) → _open строит граф немедленно → acquire возвращает denoisedStream → ворклет ещё 100-300мс грузит WASM → process() без модели = нули.
→ Последствие: питч-ворклет получает тишину на время загрузки; при живом питче — окно «мёртвой детекции». Коротко, но не ноль.
→ Проверка: первый ON всегда. RN-1 не ловит (мок-ворклет синхронный).
→ Патч: перекрыт ударом 1 (refCount=0 при тоггле) + удар 2 пункта ④ (connect-after-ready).

**ВЕРДИКТ ①: ТРЕБУЕТ ПАТЧА** — ядро (расширение, не сервис; один refcount) держит, но рантайм-тоггл без гейта = неработающая фича.

### ② acquireRaw() для REC

**УДАР 3 (СРЕД): acquireRaw при _stream=null — UB в спеке.**
Сценарий: REC стартует первым (refCount=0, _stream=null) → acquireRaw обязан проделать полный _open()-путь. Спека: «тот же refcount, но возвращает this._stream (сырой)» — при null это undefined. Если реализация вернёт null → takes.recorder.ts:100 `throw 'Raw mic stream not available'` → REC сломан первым в очереди.
→ Проверка: REC-first-then-🎤 — штатный сценарий (диспетчер сам его называет: «делим in-flight между UI-входами (REC + 🎤)» — MicSourceV3.ts:37).
→ Патч: специфицировать явно: `acquireRaw() = await acquire() внутренне, возвращает raw`. Одна строка в спеке, ноль в коде.

**УДАР 4 (СРЕД): setDevice при живом REC убивает запись.**
Сценарий: REC пишет (takes.recorder.ts:84 acquire → MediaRecorder:121 держит стрим) → MixerPanel.tsx:312 setDevice → MicSourceV3.ts:62 `_stop()` → tracks.stop() (:82-84) → MediaRecorder пишет тишину, blob = обрезка. Существующий баг (не введён спекой), но спека добавляет RN-4 «setDevice при denoise ON → граф пересоздан» — тестирует граф, НЕ потребителя. Расширяет поверхность, не закрывая известную дыру.
→ Проверка: RN-4 проверяет пересоздание графа, не выживание REC-стрима.
→ Патч: вне круга-2 (семантика setDevice = отдельная задача). Патч-условие: RN-4 расширить ассертом «raw-треки живы при refCount>0» ЛИБО задокументировать known-issue в спеке. Молчать = провал тест-плана.

**ВЕРДИКТ ②: ТРЕБУЕТ ПАТЧА** — семантика null + RN-4-ассерт. Сама идея raw-REC (архивная правда) держит.

### ③ RnnoiseWorklet WASM в AudioWorkletGlobalScope

**УДАР 5 (СРЕД): ложный прецедент import.meta.url.**
Сценарий: спека ①: «Загрузка в ворклет: `new URL('../vendor/rnnoise.wasm', import.meta.url)` — тот же механизм, что yin-processor.js:122». ПРОВЕРЕНО по живому дереву: **yin-processor.js (222 строки) не содержит import.meta вообще** — механизм `new URL(..., import.meta.url)` живёт в pitch-engine.ts:122 — MAIN-поток, при addModule. Внутри ворклета: в dev Vite отдаёт ворклет по http-URL — относительный fetch сработает; в **prod** ворклет-файл может стать отдельным чанком → `../vendor/rnnoise.wasm` резолвится от чанка, не от исходника → 404 → wasm-fail **только на проде**. Классика «у меня локально работало».
→ Проверка: `vite build` + прод-деплой. RN-тесты с моками этого не ловят (мок не резолвит URL).
→ Патч: main-поток делает `new URL('../vendor/rnnoise.wasm', import.meta.url).href` (тут прецедент yin корректен) → передаёт **абсолютный URL через processorOptions** в `new AudioWorkletNode(ctx, 'rnnoise', { processorOptions: { wasmUrl } })` → ворклет `fetch(wasmUrl)`. Надёжно dev+prod, тот же jitsi-паттерн, ноль новых сущностей.

**УДАР 6 (лёгкий): addModule без _workletLoaded-кэша.**
Сценарий: pitch-engine.ts:121-124 кэширует addModule в `_workletLoaded` — повторный setDevice→пересборка графа зовёт addModule повторно? Спека не указывает кэш для rnnoise-модуля.
→ Последствие: повторный addModule того же URL — не фатально (браузер терпит), но лишняя работа + в Safari исторически капризно.
→ Патч: тот же module-level флаг, 2 строки. Копия прецедента pitch-engine.ts:121.

**ВЕРДИКТ ③: ТРЕБУЕТ ПАТЧА** — processorOptions вместо import.meta в ворклете.

### ④ bypass-фолбэк wasm-fail → тихая деградация

**УДАР 7 (КРИТ): wasm-fail ПОСЛЕ подключения = потребители на вечной тишине.**
Сценарий: setDenoise(true) → граф построен и подключён немедленно → acquire вернул denoisedStream → питч/монитор подключены → fetch/instantiate падает (404, offline, OOM) → 100-300мс process() = нули → wasm-fail postMessage → MicGraphV3 disconnect графа → **но потребители держат denoisedStream** (MediaStreamAudioDestinationNode.stream живёт независимо, у него свой трек) → после disconnect вход в destination = нет → **вечная тишина** при статусе running. Питч-детекция мертва, монитор молчит, UI шумодава OFF (тихая деградация отработала).
→ Проверка: любой битый URL/медленный CDN при живом потребителе. RN-5 тестирует «после fail acquire возвращает raw» — но НЕ «потребитель, acquire-нувший ДО fail». Дыра тест-плана.
→ Патч: **connect-after-ready**: _wasmReady-промис резолвится из ворклета (`postMessage({type:'ready'})` после instantiate) ДО подключения source→worklet; fail → граф не строится вовсе, acquire возвращает raw ВСЕМ. Т.е. граф подключается только когда модель жива. Плюс удар 1 (refCount=0-гейт) гарантирует, что живых потребителей в окне нет.

**ВЕРДИКТ ④: ТРЕБУЕТ ПАТЧА** — connect-after-ready вместо connect-and-hope.

### ⑥ 44.1kHz vs 48k native

**УДАР 8 (ВЫС): нет гварда sampleRate — искажение звука на 44.1k-системах.**
Сценарий: AudioContext создаётся `latencyHint:'interactive'` (src/audio/core/audioContext.ts:14) — sampleRate следует за устройством вывода; на части Windows/USB-наушников = 44100. MediaStreamSource подаёт 44.1k в rnnoise-ворклет → wasm-модель ждёт 48k → выход: питч сдвинут на 0.92× (голос «потолстел», вокал фальшивит) либо мусор — зависит от сборки jitsi.
→ Проверка: спека сама признаёт («002 должен проверить сборку на 44.1k») — риск признан, **патча нет**. Отложенная бомба: «проверить» ≠ «закрыть».
→ Патч: гвард в setDenoise: `if (ctx.sampleRate !== 48000) → тихая деградация (тот же путь, что wasm-fail) + warn`. Одна строка, закрывает класс. Resampler — запрещён каноном круга (не переписывать), гвард дешевле.

**ВЕРДИКТ ⑥: ТРЕБУЕТ ПАТЧА** — гвард 48k обязателен до имплементации.

### ⑦ refcount-гонки (REC+🎤+мост одновременно)

**УДАР 9 (ВЫС): dispose-порядок в _stop() — утечка worklet/тихий denoised-стрим.**
Сценарий: 🎤 OFF → ControlDeck.tsx:396 release() → refCount=0 → _stop() → raw tracks.stop() (MicSourceV3.ts:82-84). Denoised-граф: MediaStreamAudioDestinationNode.stream **не умирает от disconnect** — у него собственный трек. Если порядок dispose неверен (tracks.stop() раньше disconnect графа / без worklet.port.postMessage({type:'dispose'})) → worklet-процессор висит в графе ctx, WASM-инстанс жив, denoisedStream доступен с тишиной.
→ Проверка: RN-8 декларирует «нет утечки worklet/WASM» — но если тест только «не throw», дыра. Тест обязан ассертить: disconnect ВСЕХ нод (src, worklet, gain, dest) + dispose-сообщение + denoisedStream=null.
→ Патч: порядок в _stop(): (1) полный disconnect графа, (2) worklet.port.postMessage({type:'dispose'}), (3) tracks.stop() raw, (4) `_denoisedStream = null`. RN-8 — расширить до ассерта disconnect-списка.

**УДАР 10 (лёгкий): gen-гвард setDenoise — спека ссылается на образец, но не специфицирует сброс.**
Сценарий: setDenoise инкрементит gen (образец pitch-engine.ts:44/:72) — ок. Но при wasm-fail + повторном ON: _wasmReady-промис закэширован отвергнутым → повторный ON мгновенно падает без повторной попытки (fetch мог быть транзиентным 500).
→ Патч: при wasm-fail `_wasmReady = null` (разрешить ретрай). 1 строка.

**ВЕРДИКТ ⑦: ТРЕБУЕТ ПАТЧА** — dispose-порядок + RN-8-ассерты + ретрай. Сама refcount-модель (один счётчик на стрим) держит — второй refcount не появляется, канон 82e1c76 не нарушен.
