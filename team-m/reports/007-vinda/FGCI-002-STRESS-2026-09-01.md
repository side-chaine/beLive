## ВЕРДИКТ: ТРЕБУЕТ ПАТЧА

Механизм — SHA-замок в CI — верный и закрывает главный провал 301 §2 («тесты ≠ замок»). Но в тексте спеки 3 дыры, которые в реальном прогоне дают либо **вечный красный main**, либо **молчаливый обход замка**: семантика graveyard (Удар-2), порядок применения FG-CI↔Волна A + пин мёртвого HEAD (Удар-1), ничейный рассинхрон манифест↔док (Удар-6). Все правки — 1–2 строки каждая, суммарно ~8 строк; редизайн не требуется и запрещён.

## УДАРЫ (каждый: следствие + минимальная правка спеки)

### УДАР-1. Гонка применения FG-CI ↔ Волна A (+ гейт-1 пинит мёртвый HEAD)
**Сценарий A (опасный порядок):** Волна A получает GO и применяется ДО FG-CI — patchV1 снесён, дерево уже 18 frozen. Затем оператор применяет FG-CI, копируя манифест из спеки как есть: 19 файлов, patchV1 в guard-блоке.
**Следствие:** первый же `verify:frozen` на main → «guard-файл отсутствует» → ERROR → деплой стоит, main красный. Оператор чинит замок правкой манифеста под давлением красного CI — худший режим правки замка.
**Сценарий B (безопасный порядок):** FG-CI раньше Волны A → Волна A сносит patchV1 + удаляет манифест-строку в том же коммите → check-frozen читает обновлённый манифест → молчит, зелёный. Правило одного коммита в стационаре **достаточно и самопринудительно**: полуприменённая Волна A (файл снесён, манифест забыт) = ERROR = замок сам заставляет атомарность. Дыра — только в момент первоначального применения: спека порядок НЕ фиксирует.
**Вторая половина удара:** гейт-1 пинит «все 19 SHA сходятся на `4913e4c`», а канон уже `c20e15c` (три HEAD за утро: 1d2746b → 4913e4c → c20e15c). Гейт, привязанный к мёртвому хешу, невоспроизводим.
**Правка (2 строки):** (а) в блок «ВЗАИМОДЕЙСТВИЕ» добавить: «FG-CI применяется ДО Волны A; если Волна A уже в дереве — оператор исключает patchV1 из guard-блока по живому дереву (19→18) до коммита FG-CI»; (б) гейт-1: убрать пин `4913e4c` → «exit 0 на живом дереве применения».

### УДАР-2. graveyard=WARN — труп можно подправить «заодно» и отравить Волну C
**Сценарий:** FG-CI в дереве. Кто-то правит `lyrics.bridge.ts` (труп, 184 стр) «заодно» — CI зелёный (WARN не блокирует), diff замазан среди прочего. Наступает Волна C: её гейт — «diff bridge↔wrapper перед сносом» (DEFREEZE-A, НЕЛЬЗЯ-блок; WAVE-ПЛАН). Wrapper `lyrics-events.ts` портирован 1:1 с оригинала (заголовок файла: «ORIGINAL: src/bridges/lyrics.bridge.ts, 184 строк»). Подправленный bridge ≠ оригинал → дифф показывает **ложные расхождения**.
**Следствие (развилка, обе ветки плохи):** (а) оператор Волны C блокирует снос из-за «расхождений», которых нет — волна буксует; (б) хуже — оператор «допортирует» дельту трупа в живой wrapper: правки мёртвого кода мигрируют в живой код через ритуал, который должен был их фильтровать. Существующий `verify:bridge-parity.ts` НЕ ловит: он сверяет имена событий/структуру подписок, не байты — правка без изменения addEventListener-набора проходит паритет молча.
**Вторая половина удара:** graveyard **отсутствие** тоже WARN. Но легальный снос (Волна C) по правилу того же коммита удаляет манифест-строку → absent-кейс на легальном сносе вообще не срабатывает. Значит WARN об отсутствии срабатывает **только на несанкционированном сносе** — ровно тот случай, который надо ловить, а спека его молча пропускает.
**Правка (переписать 2 булета FG-2):** «graveyard-файл **изменён** → ERROR (трупы байт-стабильны до Волны C — это то, что делает bridge↔wrapper дифф достоверным); graveyard-файл **отсутствует** → ERROR (легальный снос = коммит с удалением манифест-строки, как у Волны A — тогда кейс не срабатывает вовсе)». WARN остаётся только echo-строкой в логе, не семантикой.

### УДАР-3. Мут-тест (гейт-2): не сказано «локальный», а раздел гейтов смешанный
**Сценарий:** раздел «Гейты» смешивает локальные проверки (tsc/vitest) и CI-шаг (verify:frozen ходит в deploy.yml). Оператор, читая гейт-2 («изменить 1 байт → ERROR → откат»), «автоматизирует доказательство» шагом в deploy.yml.
**Следствие:** CI красный НАВСЕГДА — мутация = ERROR по построению, откат мутации внутри CI невозможен. Это не проверка замка, а снятие замка с двери.
**Правка (1 строка в гейт-2):** «мут-тест = ЛОКАЛЬНЫЙ ручной ритуал при приёме FG-CI (002/007); в deploy.yml НЕ включается». FG-4 уже задаёт содержимое CI одним шагом — фраза закрывает дыру дешевле, чем чинится красный main.

### УДАР-4. SHA в одном JSON = конфликты мержей? — УДАР ПРОВЕРЕН И ОСЛАБЛЕН
**Проверка удара (какой вход его ловит?):** параллельные правки манифеста двумя волнами. Но волны сериализованы GO Никиты (WAVE-ПЛАН: A ждёт GO; DEFREEZE-A: «НЕ трогать Волну B/C — отдельные паки по GO»). Параллельных волн в текущем процессе не существует. Единственное реальное окно конфликта — PR FG-CI открыт + Волна A коммитится — это Удар-1, закрывается его же правкой порядка.
**Следствие при оставлении как есть:** конфликт мержа 19-строчного JSON тривиален (union удалений, решается глазами за минуту).
**Вердикт по удару:** дробление на `frozen-manifest/` по файлу на SHA = 19 файлов + логика обхода в check-frozen + рассеянный diff-ревью — дороже проблемы на порядок. **ОВЕРКИЛЛ, отклоняю.** Один JSON оставить.

### УДАР-5. Гейт-4 «YAML-парс» — инструмент не назван = гейт неисполним
**Сценарий:** три оператора читают «CI-yml валиден (YAML-парс)»: первый ставит actionlint (нет в репо, нужен install), второй `node -e` с js-yaml, третий пропускает «потом CI сам проверит».
**Следствие:** гейт без инструмента = гейт по настроению; опечатка в deploy.yml ловится упавшим деплоем на проде, а не на приёме.
**Правка (1 строка):** «гейт-4: `node -e "require('js-yaml').load(require('fs').readFileSync('.github/workflows/deploy.yml','utf8'))"` — js-yaml уже в devDeps (^4.1.0), ноль новых зависимостей; actionlint — опция, если нужен контроль схемы Actions, а не только синтаксис».

### УДАР-6. Манифест (19) ≠ док (зона шире): audioContext.ts — новый класс False-Green
**Сценарий:** frozen-zones-v2.md «Permanent frozen — никогда не трогать» перечисляет audioContext.ts, StemPlayer, AudioLoader, VocalMix, MicrophoneManager, js/*. FG-CI охраняет 19 — этих файлов в манифесте НЕТ. Живой grep 002 (c20e15c): audioContext.ts — **ЖИВОЙ**, 10 импортёров, вкл. `engine-v3/index.ts:34`, `main.tsx:16`, `useTakesPlayback.ts:7` — V3-инфраструктура, не труп V2. ДГ-13 (утечка `_ctx`-синглтона) требует файл ПРАВИТЬ.
**Следствие-а:** читатель дока правит audioContext.ts под ДГ-13 → CI зелёный → «frozen 0 = механизм» — ложь: механизм охраняет 19, док объявляет замороженной зону шире. False-Green нового класса — манифест ≠ док, и расхождением никто не владеет.
**Следствие-б (зеркальная ошибка):** наивный патч «добавить все док-frozen в guard» = заморозка ЖИВОЙ V3-инфры (audioContext нужен для ДГ-13 и V3) — ошибка противоположного знака.
**Правка (2 строки в FG-5/НЕЛЬЗЯ):** «манифест (19) = операционный канон заморозки; frozen-zones-v2.md шире (StemPlayer, AudioLoader, VocalMix, MicrophoneManager, audioContext.ts, js/*) — рассинхрон закрывает 003 в F-16 (audioContext.ts переклассифицировать: живой, снять "permanent frozen"). FG-CI СОЗНАТЕЛЬНО их не охраняет до решения 003».

## УСИЛЕНИЯ

1. **Назвать самопринудительность правила одного коммита.** ERROR-на-guard-отсутствие + «манифест-строка удаляется в коммите сноса» = атомарность волн обеспечивает САМ замок: полуприменённая Волна A физически не может пройти CI. Одна фраза («замок принуждает атомарность волн») превращает скрытое свойство в контракт.
2. **Двойной контур сверки SHA — назвать.** 007 сверил 19 хешей руками (и поймал копипасту patchV1←track.bridge — дефект аудита 301 §7), гейт-1 пересчитает машиной на живом дереве. Ручной + машинный контур закрывает копипаста-класс с двух сторон: «оператор не пересчитывает руками — гейт-1 пересчитывает машиной».
3. **Детектор resurrection (дёшево, без смены сути).** check-frozen WARN'ает (echo, не блокер) о .ts в `src/bridges/`, которых нет в манифесте, кроме `__tests__/`: откат/копипаста из истории, вернувшая труп на диск, сегодня невидима — манифест проверяет только перечисленное. Глаз на кладбище за 5 строк скрипта.
4. **Волна A: гейт-4 перепинтовать на манифест.** DEFREEZE-A гейт-4 говорит «21 → 18 (21×SHA)», затем сам себя правит «итог 19→18» — два числа в одном гейте. FG-CI даёт SSOT: гейт-4 Волны A должен гласить «удалить строку patchV1 из guard-блока frozen-manifest.json (19→18)» — рассинхрон 21/19 исчезает вместе с отдельным «инвентарём».
5. **Тесты НЕ в манифесте — верно (301 §2).** 800+ тест-файлов в SHA-замке неуправляемы; страховка ≠ замок. Граница правильная, не трогать.

## Что оставить

- **Архитектуру guard/graveyard (301 §7/§8) — целиком.** Кодирование намерения (постоянный vs до-сноса) в самом замке делает легальные сносы волн правилом, а не исключением. Удар-2 меняет семантику WARN→ERROR, не структуру.
- **19 файлов, один JSON, корень репо.** Скоуп выверен по живому дереву; один дифф = вся картина заморозки (Удар-4 это подтвердил).
- **ERROR-семантику guard (изменён/отсутствует).** Не трогать.
- **Позицию FG-4 (после Test, до Build)** — зеркалит существующий шаг `verify:ci` в deploy.yml, ноль новых CI-паттернов.
- **Пометку о пойманном дефекте аудита (patchV1-SHA)** — прецедент ритуала сверки, который уже один раз окупился; прецедент должен остаться в спеке как норма.
