## 1. ПОЧЕМУ YAML, А НЕ МЕГА-СКРИПТ

Ямл-носитель + тонкий интерпретатор (вердикт 201) сильнее мега-скрипта:
- **одна строка = один ассерт** (читаемо, версионируемо, дифается);
- добавление пары = **строка в реестре, не код** (не порождаем гейт-призраков ㉟);
- интерпретатор остаётся ~150-строчным и стабильным, истина — в данных;
- дух проекта: «у каждой пары — файл-протокол» (DIAGNOSTICS-LOG), «у каждой пары — реестр» (COM-карта).

## 2. НОСИТЕЛЬ: `scripts/junction-registry.yaml`

Формат записи (одна запись = один ассерт):
```yaml
# kind описывает, как проверять; a/b — два места; rule — логика; level — fail|warn
- id: wrangler-env-d1
  kind: env-to-toml
  a: { file: "gateway/src/index.ts", env: "METRICS_DB" }
  b: { file: "gateway/wrangler.toml", binding: "METRICS_DB", attr: "database_id", nonEmpty: true }
  rule: implies
  level: fail
```

## 3. ИНТЕРПРЕТАТОР: `scripts/verify-junction.mjs` (~150 строк)

Читает YAML; для каждой записи:
1. **Проверка места-A:** `file` существует, содержит ли `env`/`marker`/`entry` (по kind).
2. **Проверка места-B:** `file` существует, содержит ли `binding`/`attr`, `nonEmpty` — непуст ли.
3. **rule: implies** — A присутствует ∧ B отсутствует/пусто ⇒ violation; **rule: warn-only** ⇒ предупреждение.
4. `requires: cf-token` ⇒ запись выводится как UNVERIFIABLE (не зелёная и не красная) — честно: из репо секрет-типы не проверить.

## 5. ЗАПУСК И КНОПКА

- `node scripts/verify-junction.mjs` → npm-скрипт **`verify:junction`**.
- **`verify:ci` = verify:reach + verify:inert + verify:docvis + verify:junction** (4 гейта).
- CI-шаг — та же связка «гейт = файл + npm-скрипт + CI-шаг» (формула 201).
- **Первый запуск ожидаемо fail** (пара 1 поймает METRICS_DB) — это правильный запуск: гейт, который сразу нашёл живую невидимку. Лечение жертв — отдельный шаг (не в этой спеке): фикс METRICS_DB и судьба фантома belive-ai = решения Никиты из CF-батча.

## 6. ПРАВИЛА НОСИТЕЛЯ

- **Истина в данных:** новая пара = строка YAML, интерпретатор не меняется. Не порождаем гейт-призраков ㉟.
- **Не числится зелёной без проверки:** `requires: cf-token`-записи = UNVERIFIABLE, не зелёные.
- **Никаких мега-скриптов:** интерпретатор един и тонок (~150 строк); вся сложность — в реестре пар.
- **CSS-каскад:** только warn (вердикт 201: победителя решает порядок загрузки, статикой не вычислить).
- **Для v0.2:** каждая новая пара требует «жертву-пример» — пойманную руками невидимку, не гипотетическую.

## 7. ПРИЁМКА

1. `node scripts/verify-junction.mjs` печатает: пары всего / violations / warns / unverifiable + по каждой violation: `id`, место-A `file:line`, место-B, что именно отсутствует.
2. `npm run verify:ci` — 4 гейта, junction в составе.
3. Выход = 0, если violations=0 (warns не флипают).
4. Спека проходит цепь 001→002→001→009 стандартно; жертвы-фиксы (METRICS_DB, belive-ai) — отдельные решения Никиты после первого прогона.
