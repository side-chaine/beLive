## §2 · ЗАГОТОВКА, КОТОРАЯ ЭКОНОМИТ ПАРЕ ДЕНЬ

Прогнал эвристику по 254 докам `docs/` (проба в `/tmp`, дерево не тронуто, `git status` чист). Результат:

```
LIVING     93   ← в первых 1500 символах есть код-клейм (file:line, tsc=, frozen N, `*.ts`)
HISTORY    98   ← маркер HISTORICAL/SUPERSEDED/устарел ИЛИ путь /archive/ | /packs/era-
REFERENCE   1   ← имя намекает на внешнее (research/SOUNDTOUCH/GPT)
UNCLEAR    62   ← ни одного признака ⇒ РУЧНАЯ РАБОТА
PRIVATE    90   ← visibility, ортогонально (gitignored-зоны)
```

**Как это использовать:** 003 не размечает 254 файла руками. Он **проверяет 192 автоматических вердикта выборкой** и вручную решает **62 UNCLEAR**. Это разница между днём и полутора часами.

**Осторожно (три оговорки, обязательны):**
1. Эвристика LIVING смотрит только первые 1500 символов — док может упоминать код глубже. 003_2 обязан проверить хотя бы 10 из 93 LIVING на полный текст.
2. `REFERENCE = 1` подозрительно мало. Скорее всего часть REFERENCE ушла в HISTORY (папки `operations/context/SOUNDTOUCHJS-FULL` и подобные). Проверить руками.
3. **Эвристика не заменяет решение.** Она даёт черновик, ответственность — на паре. Если 003_2 найдёт >10% ошибок в выборке — черновик выбрасывается, размечаем руками. Это честный порог, зафиксировать заранее.

Первые 12 UNCLEAR для понимания класса: `docs/007-SPEC-STATUS.md` · `AUDIO-BEHAVIOR-SPEC.md` · `BILI-CONTEXT.md` · `HISTORY-MAP-V2-V3-MIGRATION.md` · `INDEX.md` · `MACRO-PACK-DUO-PHASE1.md` · `PLAN-v3.3-CANONICAL.md` · `SONNET-REPORT-13-DUO-STRATEGY.md` · `agents/MODEL-ROUTING-GUIDE.md` · три `agents-hub/*`.

Видно закономерность: **UNCLEAR — это в основном планы, спеки и контекст-документы**, то есть тот класс, где «утверждает ли он что-то о коде» решается только чтением. Правило ① из v1.1 («утверждает о коде → LIVING либо HISTORY, третьего нет») к ним и применяется.

```yaml
meta:
  head: e1bd7f6                    # ОБЯЗАТЕЛЬНО — иначе цифры бессмысленны
  measured_at: 2026-09-03T17:5x+03:00

    docs:    { on_disk: 254, tracked: 183 }

  method:
    on_disk: "find . -name '*.md' -not -path './node_modules/*' -not -path './.git/*' | wc -l"
    tracked: "git ls-files '*.md' | wc -l"
  heuristic_draft: { LIVING: 93, HISTORY: 98, REFERENCE: 1, UNCLEAR: 62 }
  heuristic_error_rate: null       # заполняет 003_2 после выборки; >10% = черновик выброшен

  - path: docs/architecture/audio-engine.md
    state: LIVING                  # LIVING | HISTORY | REFERENCE
```

**Два поля, а не одно** — это правило v1.1 §0. Вопрос «HISTORY или PRIVATE?» не имеет смысла: приватный LIVING нормален, публичный HISTORY нормален.

## §4 · ЧТО ПАРА ДОЛЖНА ЗАМЕТИТЬ ПО ХОДУ (три открытых вопроса)

**(1) `docs/INDEX.md` сам попал в UNCLEAR.** Индекс — это LIVING (он утверждает, какие доки существуют и в каком статусе) или служебный файл вне классификации? Мой голос: **LIVING с особым claim-типом** — G-3 должен проверять, что каждая запись индекса указывает на существующий файл. Это ловит самый частый гнилой случай: ссылка в индексе на переехавший док.

**(2) Три `REGISTRY.md` — переименование в R-3 затронет ссылки.** `docs/agents/REGISTRY.md` (STALE 15.06) · `docs/modernization/REGISTRY.md` (29.08) · `team-m/` (живой). Перед переименованием — `verify:refs` по каждому пути (гейт G-4 уже в проде, `npm run verify:refs <path>`). Это ровно тот инструмент, который спас деплой на CHECK-D.

**(3) `team-m/` растёт на 16 файлов за 7 часов.** Реформа v1.1 сознательно не трогает `team-m/` (зона 200, правило 48ч-архива). Но если рост такой, через месяц там будет 700 файлов. **Вопрос к 200, не к паре:** нужно ли `team-m/` тоже три состояния, или достаточно архива по дате. Пара фиксирует наблюдение в досье, решение не принимает.

## §5 · ГЕЙТЫ ПРИЁМКИ R-1 (для 009 и 200)

```bash
# 1. census существует и валиден
test -f docs/DOC-CENSUS.yaml && python3 -c "import yaml,sys; yaml.safe_load(open('docs/DOC-CENSUS.yaml'))"

# 2. метадата несёт head + оба счётчика (иначе цифры бессмысленны)
grep -E "^\s+head:|on_disk:|tracked:" docs/DOC-CENSUS.yaml

# 3. каждый док docs/ имеет запись — ни одного пропуска
[ "$(find docs -name '*.md' | wc -l)" = "$(grep -c '^  - path:' docs/DOC-CENSUS.yaml)" ]

# 4. у каждой записи ОБА поля
[ "$(grep -c 'state:' docs/DOC-CENSUS.yaml)" = "$(grep -c 'visibility:' docs/DOC-CENSUS.yaml)" ]

# 5. visibility сверен с фактом git (заготовка гейта G-3b)
#    private + не под ignore → УТЕЧКА · public + под ignore → невидимка

# 6. error_rate заполнен 003_2 и ≤10%
grep "heuristic_error_rate:" docs/DOC-CENSUS.yaml
```

**Красный флаг:** пункт 3 не сходится ⇒ перепись неполная, R-2 не стартует. Пункт 6 больше 10% ⇒ черновик эвристики выброшен, разметка ручная.
