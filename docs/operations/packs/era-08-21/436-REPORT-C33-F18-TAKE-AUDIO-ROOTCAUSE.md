## 1. Диагноз (трейс 435/435b — Ц3 N1 закрыт)

Пользователь кликнул Take в квесте. Трейс доказал:
```
TakeSlot.click {isReady:true, isEmpty:false}        ← клик дошёл до onPlay
useTakesPlayback: source создан, bufferDur=15.9s, ctx running  ← буфер реальный, контекст живой
useTakesPlayback: transport.play() called            ← транспорт играет
[НЕТ лога source.start]                              ← source.start НЕ вызван → :195 вернул
```

**Корень:** `handlePlayTake` (useTakesPlayback) завёрнут через `onPlay` в `interruptPracticeSession` (TakesControlStrip:917). В квесте активная практика → хендлер `handlePracticeInterrupt` при коммите записи (C31) зовёт `stopPreview()` → `previewGenRef.current++`. `handlePlayTake` захватывает `gen` ДО await (:108), а на `:195 if (gen !== previewGenRef.current) return;` ген уже не совпадает → **ранний return, `source.start()` не выполняется → тишина**. Буфер/контекст/подключение к `ctx.destination` живые — вина чисто в ген-гарде (гонка того же пользовательского действия, не реального «более нового» стопа).

## 2. Фикс (C33)
1. **Ре-захват gen ПОСЛЕ `await playResult`** (commit-осел, previewGenRef стабилен) → легитимный одиночный плей проходит; реальный более новый stop по-прежнему ловится декод-гардами (:116/:134).
2. **Кламп `startOffset` в `[0, bufferDur)`** — страховка от «старт за концом буфера» (кандидат параллельного 007а): если плейбек-позиция смещена внутри блока, тейк играет с начала, а не молчит.
3. Диагностические `[N1-TRACE]`-логи 435/435b удалены — код чистый.
