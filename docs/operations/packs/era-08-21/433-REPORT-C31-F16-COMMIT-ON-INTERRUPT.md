# 433-REPORT — C31: F-1.6 COMMIT-ON-INTERRUPT (тейк больше не пропадает на границе блока)

**Коммит:** C31 = `28ae59e` · база C30=`fae1d65` · frozen не тронут.

## 1. Диагноз (квест, живой репорт после C30)

Пользователь: «записал Take 1 → автопереход на следующий блок → вернулся → записи нет, можно только снова записать». При этом волна трека и живая волна записи уже работают (C30 подтверждён ✅).

**Корень — детерминированная гонка на границе блока в квесте:**
1. Квест = активная практика (`isPracticeSessionActive() = true`)
2. Автопереход/навигация дёргает `interruptPracticeSession()` (WagonTrain:86 и др.) → все зарегистрированные хендлеры
3. `handlePracticeInterrupt` (usePracticeInterrupt):
   - **шаг 3** чистит `timeCheckRef` → **автостоп блока убит до того как успел закоммитить**
   - **шаг 4** `recorder.cancel()` с комментарием «Do NOT commit partial blob» → **блоб выброшен**
4. Слот пуст, ноль ошибок в консоли. Тейк терялся при КАЖДОМ блоке квеста.

## 2. Фикс (C31)

`usePracticeInterrupt` шаг 4: если рекордер пишет — **коммит через штатный `handleStopRef.current()`** (тот же путь blob→decode→peaks→status:'ready'), вместо cancel. Семантика: частичный тейк лучше потерянного; прерывание по клику на вагон тоже сохранит частичную запись.

**Критическая деталь (ловушка, найденная при проектировании):** делегирование требует **немедленного `return`** — шаги 5–7 хендлера синхронно стирают analyser и `recordingSlot`, которые асинхронный коммит в handleStop читает ПОСЛЕ `await recorder.stop()`. Без return тейк терялся бы повторно уже внутри фикса.

Fallback: если `handleStopRef` не передан — старое поведение (cancel). Вне активной практики хендлеры не вызываются — поведение v2-флоу не меняется.
