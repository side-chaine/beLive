## 1. Диагноз (по живому репорту пользователя после C29)

**Симптом А:** запись тейка работает, живая волна при пении видна ✅ (F-1 подтверждён), но статичная волна трека в Quest — вечно «Loading waveform...».

V2-семантика: 'instrumental' — отдельный стем-файл; в v3 стемы vocals/bass/drums/guitar/keys(/other), инструментального нет.

**Симптом Б:** тейк записан, но слот не становится кликабельным («могу опять записывать, не могу прослушать»).
**Корень Б:** три сайта декода blob→AudioBuffer (`TakesControlStrip` :436 exercise / :686 handleStop / :771 scenario) использовали `ae?.audioContext ?? ae?._audioContext` с МОЛЧАЛИВЫМ `if (!ctx2) return`. Если в v3 у window.audioEngine нет этих свойств → декод тихо не выполняется → тейк навсегда `status:'processing'`, а кликабелен только `'ready'`. Ноль ошибок в консоли — класс «UX-ложь», тот же семейства, что корень 430.

## 2. Фикс (C30)

- **Волна (TakesPanel):** v3-ветка в обоих эффектах — инструментал = **сумма не-vocal стемов** из `__belive.pipeline.chainA.stems` (createBuffer на `pipeline.ctx`, поканальное сложение, длина = max), вокал = буфер стема `vocals`. V2-fallback в v3 не выполняется вовсе.

Гарантированно живой в обоих режимах. Молчаливый return заменён на `console.error('[Takes] нет AudioContext для декодирования')`.
