## ЯВЛЕНИЕ A — solo-маска пробивается изменением громкости (drums пробиваются через solo)

**Воспроизведение:** solo на vocals активен → двигаешь ползунок drums → drums начинает звучать.

**Корень (код):**
1. `stem-engine-sync.ts` volumes-блок (~136-154) применяет **RAW volume** при изменении ползунка:
   `pipeline.setStemVolume(id, current.stemVolumes[id])` — **без проверки активного solo** (Fix 389: «volume применяется к pipeline напрямую»).
2. `StemChain.setStemVolume` (StemChain.ts:80-83) пишет `stem.volume = volume` — solo-маска (`_soloed`, строки 86-103) **не консультируется**.
3. `hasSoloChange` (stem-engine-sync.ts:226-233) реагирует ТОЛЬКО на solo-изменения — volume-изменение не триггерит переприменение маски.
4. `applyAll` (stem-engine-sync.ts:235-247) — единственное solo-aware место (effectiveGain) — но **только cold-start**, не на diff-пути.

**Итог:** при активном solo изменение volume любого не-соло стема пробивает маску. Мой C25/C26-фикс закрывает solo-события, но не volume-события.

**Варианты решения (Ц3):**
- (a) volumes-блок становится solo-aware: при активном solo не-соло стемы получают 0 (формула как в моём re-apply);
- (b) solo-маска переприменяется после ЛЮБОГО volume-изменения при активном solo;
- (c) признать «пробивание» фичей (нестандартно, MX-03 против).

## ЯВЛЕНИЕ B — индикация над ползунками (обычный режим) «застревает»; в Visual работает

**Наблюдения:**
1. **Известный дефицит:** SONNET-REPORT-13 (строки 56, 69, 248): «Mixer пуст — V3 не публикует метры/уровни в UI» — отложено в Phase 2, спеки нет. Индикация в обычном режиме в V3-конфиге **читает V2 (заглушен V2AudioCage → нули/стагнация)**.
2. **Асимметрия UI:** `InstrumentStrip.tsx:30-36` (Visual) — **dual-call** (store + `ae.setStemSolo` → V2 держится свежим); `MixerPanel.tsx:45-51` (обычный) — **store-only** (V2 не трогается, остаётся stale), при `isV3`-гейте (MixerPanel.tsx:247) false — цикл читает stale caged V2.
3. Visual-режим работает через `stem-reactive.bridge.ts` (60Hz CSS vars `--bl-stem-{id}-energy`/`-hit`) — отдельный конвейер от trigger-visual, PVO acquire(reactive).
4. «После отжатия solo индикация не возвращается, пока не задеть что-то» — обновление идёт через diff-цикл; пока нет изменения стора — индикатор не пересчитывается (stale V2 или необновлённые метры).

**Варианты решения (Ц3):**
- (a) V3-метры в обычный режим: publish через `pipeline._stretchMeters` → CSS vars / rAF (это и есть Phase-2-трек SONNET-REPORT-13 — большой, отдельный пак);
- (b) быстрый мост: MixerPanel читает `__belive.pipeline._stretchMeters` вместо V2 (микро-фикс, но дублирует 60Hz-логику);
- (c) свести оба режима к одному источнику (stem-reactive.bridge) — консолидация, средний объём;
- (d) зафиксировать как известный дефицит Phase 2, не чинить сейчас (индикация — косметика, звук работает).

## ЯВЛЕНИЕ C — RouteCheck «N routes» solo-blind (INFO)

`RouteCheck` считает `audible && |stem.volume| > EPSILON` — по громкости, без учёта solo-маски. При solo показывал 1 route. Не баг сам по себе, но с Явлением A связан: при пробитии volume маршрут «оживает» — согласуется с ушами.
