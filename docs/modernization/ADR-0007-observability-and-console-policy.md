# ADR-0007 · Обсервабилити: один логгер вместо 425 неприкрытых `console.*`

> ⚠️ Исполнение частичное (31.08): BAC-109 console-гигиена (~363 вызова — источник team-m/REGISTRY.md:43) — в очереди bLb-hygiene; единый логгер не доведён.

**Статус:** proposed · **Дата:** 2026-08-29 · **Волна:** W3
**Связано:** [01-BASELINE §5.3](./01-BASELINE.md), [ADR-0008](./ADR-0008-csp-and-security-baseline.md)

---

## Контекст

Замер 2026-08-29:

| Метрика | Значение |
|---|---|
| `console.*` в `src/` | **732** |
| прикрыто `import.meta.env.DEV` | 307 |
| **не прикрыто** | **~425** |

**Что это значит на практике.** Приложение — музыкальное PWA, которое работает вживую: репетиции, выступления, синхрон с сетью. При этом:

- **В проде консоль зашумлена.** 425 вызовов, из которых подавляющее большинство — отладочные. Найти среди них настоящую ошибку пользователь не сможет, а мы не получим.
- **Ошибки не уходят никуда.** Нет ни одного механизма, кроме `console.error` в никуда. Если у Никита на выступлении «звук пропал» — у нас нет данных, чтобы понять почему.
- **`console.*` в hot path.** В аудио-коде (обработка стемов, позиция, BPM) логирование в цикле — это реальная стоимость производительности, а аудио-поток чувствителен к джиттеру.
- **Дублирование.** Один и тот же смысловой сигнал логируется в разных местах с разным форматом.

**Связь с [ADR-0008](./ADR-0008-csp-and-security-baseline.md):** логи в проде — это ещё и утечка. Отладочный вывод может содержать URL треков, токены сессии, внутренние идентификаторы. Пока логи не контролируются, включать строгий CSP и думать о приватности бессмысленно.

## Решение

### 1. Один модуль логгера

```
src/foundation/logger/
  index.ts        — публичный API
  levels.ts       — trace/debug/info/warn/error
  transports.ts   — console (DEV), remote (PROD), noop
```

```ts
import { logger } from '@/foundation/logger';

logger.debug('stem loaded', { stemId, durationMs });   // только в DEV
logger.warn('clock drift detected', { driftMs });      // DEV + PROD
logger.error('pipeline failed', { stage, cause });     // DEV + PROD + remote
```

### 2. Поведение по уровням

| Уровень | DEV | PROD | Уходит на сервер |
|---|---|---|---|
| `trace` | ✅ | ❌ | ❌ |
| `debug` | ✅ | ❌ | ❌ |
| `info` | ✅ | ❌ | ❌ |
| `warn` | ✅ | ✅ | ✅ (сэмплинг) |
| `error` | ✅ | ✅ | ✅ (всегда) |

PROD-консоль получает только `warn` и `error` — **порядка двух порядков меньше шума**, при этом критичное видно.

### 3. Правило для кода

> **Прямой вызов `console.*` запрещён. Только через `logger`.**

Исключение: временная отладка — но она не проходит ревью (гейт в CI).

### 4. Гейт в CI

```yaml
- name: No raw console
  run: |
    HITS=$(grep -rn "console\.\(log\|debug\|info\|warn\|error\)" src --include='*.ts' --include='*.tsx' \
           | grep -v "src/foundation/logger/" | wc -l)
    BASELINE=$(cat .ci-baseline/console)     # 732 на 2026-08-29
    if [ "$HITS" -gt "$BASELINE" ]; then exit 1; fi
```

Тот же **храповик**, что в [ADR-0013](./ADR-0013-ci-gate-architecture.md): новые `console.*` не принимаются, старые вычищаются постепенно.

### 5. Аудио — особая зона

В hot path (`AudioWorklet`, обработка стемов, позиция) логирование **запрещено по умолчанию** — даже `trace`. Джиттер в аудио-потоке слышен как щелчок. Диагностика там — через счётчики и флаги, а не через строки.

### 6. Куда уходят ошибки

Минимум — `window.onerror` + `unhandledrejection` → тот же `logger.error`. Этого достаточно, чтобы перестать быть слепыми. Полноценный Sentry/GlitchTip — отдельное решение, когда будет понятен объём.

## Почему не другие варианты

| Вариант | Почему нет |
|---|---|
| Обернуть все 425 в `if (import.meta.env.DEV)` | Механическая правка 425 мест; не даёт уровней, не даёт удалённой отправки. Через месяц вернутся новые |
| Удалить все логи | Отладка станет невозможной. Логи нужны — нужно ими управлять |
| Взять готовую библиотеку (pino, winston) | Они для Node. Для браузера с аудио-требованиями — лишние килобайты и не тот runtime |
| Сразу подключить Sentry | Правильно в долгую, но сначала нужен единый интерфейс. Иначе Sentry станет вторым способом логирования, а не транспортом |
| Оставить как есть, «логи не мешают» | Мешают: шум в проде, стоимость в hot path, слепота при инцидентах |

## Последствия

**Плюсы**
- Прод-консоль: ~425 вызовов → десятки. Ошибку **видно**.
- Появляется удалённый сбор ошибок → первый раз появляются данные о реальных сбоях.
- Убирается стоимость логирования в аудио-hot-path.
- Готовность к CSP: управляемый вывод вместо произвольного ([ADR-0008](./ADR-0008-csp-and-security-baseline.md)).

**Минусы / чем платим**
- **~425 правок.** Это много. Компенсация: не отдельный спринт, а правило «тронул файл — заменил `console` на `logger`» (как в [ADR-0006](./ADR-0006-state-architecture.md)). Храповик не даёт расти.
- **Один лишний импорт в каждом файле.** Компенсация: tree-shaking убирает DEV-уровни из прод-бандла.
- **Риск потерять полезный отладочный вывод.** Компенсация: `debug`-уровень сохраняет его в DEV полностью.
- Нужен выбор транспорта для удалённой отправки. Компенсация: начать с `window.onerror`-хука, не блокируясь на выборе сервиса.

## План внедрения

| Шаг | Действие | Критерий |
|---|---|---|
| 1 | `src/foundation/logger/` с уровнями и транспортами | модуль есть, протестирован |
| 2 | `window.onerror` + `unhandledrejection` → `logger.error` | ошибки попадают в логгер |
| 3 | Вычистить `console.*` в `foundation/` и `audio/` (зону hot path) — в первую очередь | 0 вхождений там |
| 4 | Храповик в CI | новые `console.*` красные |
| 5 | Остальной код — по правилу «тронул — заменил» | счётчик убывает |
| 6 | Выбрать транспорт для удалённой отправки | ошибки видны вне машины пользователя |

**Откат:** логгер — обёртка. Откат = вернуть прямые вызовы; риск минимальный.

---

## Критерий успеха (DoD W3)

- [ ] Прямых `console.*` в `src/` — **0** (кроме `src/foundation/logger/`)
- [ ] В прод-сборке из консоли идут только `warn`/`error`
- [ ] `window.onerror` и `unhandledrejection` подключены
- [ ] Храповик в CI: новые `console.*` красные
- [ ] В hot path аудио — ни одного вызова логгера

> **Критерий ценности, а не объёма:** после этой волны на вопрос «почему у пользователя пропал звук» должен появиться **ответ из данных**, а не «не знаем, не воспроизводится».
