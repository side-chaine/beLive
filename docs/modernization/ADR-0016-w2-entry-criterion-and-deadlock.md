# ADR-0016 · Критерий входа в W2 и разрыв дедлока ADR-0001 × ADR-0004

**Статус:** Proposed · **Дата:** 2026-08-29 · **Автор:** Кай (Hy4), ведущий архитектор программы  
**Связано:** [ADR-0001](./ADR-0001-legacy-isolation-project-references.md), [ADR-0004](./ADR-0004-v2-legacy-removal-sequence.md), [ADR-0015](./ADR-0015-frozen-zone-policy.md)

---

## Контекст

Бриф Босса от 2026-08-29 выдаёт OVERRIDE на FROZEN-зону «строго по ADR-0004»  
и ставит задачу полного удаления Legacy (волна W2).

При попытке начать W2 обнаруживается **циклическая зависимость между двумя  
принятыми ADR**:

| ADR          | Что утверждает                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ADR-0001** | Цель W1 = **7**, а не 0. 7 ошибок в `AudioEngineV2.ts` — это FROZEN-пол, константа, пока жив V2. «Ноль достигается в W2, когда ADR-0004 удалит V2-движок». |
| **ADR-0004** | Предусловие начала: «W1 завершена: `tsc --noEmit` = **0**».                                                                                                |

**Дедлок:**

```
Чтобы начать W2  → нужен tsc = 0        (ADR-0004)
Чтобы получить 0 → нужно удалить V2     (ADR-0001)
Чтобы удалить V2 → нужно начать W2      (ADR-0004)
```

Крутится бесконечно. Ни один шаг ADR-0004 **юридически не может начаться**,  
пока это не разрешено. Формально программа заблокирована в нулевой точке.

### Текущее фактическое состояние (замер 2026-08-29 16:25 GMT+3)

```
node node_modules/typescript/bin/tsc --noEmit   →  212 ошибок
из них в src/audio/core/AudioEngineV2.ts        →    7   ← FROZEN-пол (ровно 7, как предсказано ADR-0001)
-------------------------------------------------------------------
закрываемых без правки FROZEN                   →  205
```

**ADR-0001 подтверждён empirically:** FROZEN-пол равен ровно 7. Прогноз,  
сделанный до всяких правок, сходится.

---

## Решение

### 1. Уточнить формулировку предусловия ADR-0004

Вместо:

> W1 завершена: `tsc --noEmit` = 0

читать и применять как:

> W1 завершена: `tsc --noEmit` = **7 (FROZEN-пол)**.  
> Эквивалентно «ноль ошибок во всём коде, который мы имеем право править».

**Обоснование:** ADR-0004 писался до ADR-0001 и под «нулём» подразумевал  
«весь наш код чист». ADR-0001 уточнил, что недостижимо без правки FROZEN.  
ADR-0016 снимает противоречие в пользу ADR-0001, потому что ADR-0001  
**проверен запуском**, а ADR-0004 — нет (в нём другие два предусловия  
тоже ни разу не верифицировались).

**Ноль будет достигнут штатно**, без обходных путей — на шаге 8, физически,  
вместе с файлом. Как и обещал ADR-0001.

### 2. Критерий входа в W2 — измеримый и проверяемый

W2 (шаги ADR-0004) легально начинается, когда выполнено **всё** из списка:

- [ ] **G-W2-1** · `tsc --noEmit` = **212 → 7** (закрыто 205, остался только FROZEN-пол)
- [ ] **G-W2-2** · `verify-frozen.mjs` → `FROZEN CLEAN` на **обоих** чекаутах (Windows и Linux)
- [ ] **G-W2-3** · `V2ResurrectionDetector` **включён** (`arm(cage)`) и отработал  
  полную сессию: `report()` → `✅ No V2 leaks detected`
- [ ] **G-W2-4** · `vitest run` без регрессии относительно基线
- [ ] **G-W2-5** · Gate2 COMPLETE, Gate3B/4a закрыты, P1-d стабилен (условие D-6)

`G-W2-3` — **новый гейт, которого не было**. Обоснование ниже.

### 3. G-W2-3: доказательство смерти V2 — обязательно

ADR-0004 требует «V3 стабилен ≥ 2 спринта без fallback'ов на V2».  
Это утверждение **никем не проверялось и проверено быть не могло**:

- `V2ResurrectionDetector` был **сломан** (`require()` в ESM, неверный путь,  
  чтение несуществующего `getState()`) — см.  
  [FINDING-001](./findings/FINDING-001-v2-resurrection-detector-silent-noop.md);
- он печатал «🔭 Armed», честно возвращал «✅ No V2 leaks detected» —  
  и это была **пустая истина**: инструмент молчал не потому, что V2 мёртв,  
  а потому, что не работал;
- я починил его, но **сознательно не подключил** (`arm(cage)` не вызывается  
  нигде) — включать `setInterval` в проде без решения Босса я не имел права.

**Вывод: сегодня у нас нет ни одного байта доказательств, что V2 мёртв.**  
Сносить движок, не доказав, что он не используется — снос вслепую.  
Это ровно тот риск, от которого ADR-0004 и ADR-0015.

Поэтому: **детектор включается первым, до любых шагов сноса.**  
Сниппет подключения — в `01-ANSWERS-TO-007.md` §3 (только DEV).

### 4. Шаг 8 — по-прежнему необратим и последним

Ничего не меняется. Шаг 8 требует отдельного явного OVERRIDE и выполнения  
всех гейтов. `V2AudioCage`, `V2ResurrectionDetector`, `DuckGuardV3` живут  
до финального шага (D-6).

### 5. Не чинить 7 ошибок в FROZEN

Заманчиво «дотянуть до нуля», починив 7 ошибок в `AudioEngineV2.ts` —  
OVERRIDE ведь выдан. **Не делаем:**

- это правка файла, который будет удалён на шаге 8 → работа в мусорку;
- это правка живого аудио-движка (2 178 строк) → риск без выгоды;
- ADR-0001 уже доказал, что ноль придёт физически.

Исключение — если Босс даст отдельный явный OVERRIDE именно на правку  
(не на удаление). Тогда взвесим отдельно.

## Последствия

**Положительные:**

- Программа разблокирована **сегодня**, без нарушения ADR-0004.
- Появляется измеримая цель Фазы 0: **212 → 7** (закрыть 205).
- Появляется недостающее доказательство (G-W2-3) — снос перестаёт быть вслепую.
- FROZEN остаётся нетронутым до шага 6/8, несмотря на выданный OVERRIDE.

**Отрицательные:**

- Придётся закрыть 205 ошибок до начала сноса. Это много, но почти всё —  
  механика (TS6133 = 117 — неиспользуемые символы), хорошо параллелится.
- Формулировку ADR-0004 надо обновить (этот ADR и есть обновление).
