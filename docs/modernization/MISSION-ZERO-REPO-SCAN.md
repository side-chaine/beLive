## 3. Четыре структурных противоречия

Это не «много мелких долгов» — это **четыре неустранимых в текущей архитектуре конфликта**. Пока они не решены, ноль ошибок недостижим в принципе.

### 🔒 П-1. FROZEN-файлы математически блокируют ноль ошибок
`AudioEngineV2.ts` даёт **7 ошибок** (6× TS6133 + 1× TS2345 `Float32Array<ArrayBufferLike>`). Файл заморожен → править нельзя → **ошибки вечные**.
**Следствие:** «канон 296» — это не цель, а **пол**, заданный легаси. Ноль недостижим, пока легаси в том же compilation unit.

### 🌐 П-2. AudioWorklet-код в строке не может быть типизирован
`CaptureWorklet.ts` содержит `function captureWorkletCode()`, которая **сериализуется через `toString()`** и исполняется в AudioWorklet-реалме (нет DOM, нет модулей, нет TS). Отсюда 80 ошибок.
Просто дописать типы **нельзя**: TS-синтаксис уедет в строку и сломает рантайм в ворклете.
Плюс: `useDefineForClassFields: true` — если объявить поля класса, сгенерится `[[Define]]`-семантика, отличная от `[[Set]]` в строке; **типы «починятся», поведение сломается**.
Плюс: Blob-URL + `toString()` = **нарушение строгого CSP** (прод не сможет включить CSP без `blob:`/`unsafe-eval`).

### 🪟 П-3. Глобальная шина вместо контрактов
308 `(window as any)`, 541 `as any`. Глобалы `window.audioEngine`, `window.__belive`, `window.__getTransport`, `window.__tp`, `window.__v3play`… живут без единого `.d.ts`. TS2339 (96 ошибок) — прямое следствие.

### 💀 П-4. Мёртвый код держит ошибки
119 TS6133 — 39% всех ошибок. Часть из них — не «забыли удалить переменную», а **полувыпиленные подсистемы** (bridges в retire, V2→V3 переход).

## 4. ГЛАВНАЯ ЗАДАЧА

# 🏔 MISSION ZERO — «Нулевая терпимость к ошибкам»

> **Довести `tsc --noEmit` до 0 ошибок, не изменив ни одного FROZEN-файла.**

### Почему именно она, а не «удалить V2»

Легаси-цель №1 (выпил V2) **не может быть достигнута безопасно раньше**. Удалять 2 178 строк замороженного аудио-движка в кодовой базе с 541 `as any` — это **слепая хирургия**: типы не скажут, что сломалось, потому что их нет. Сначала — рентген (типы), потом — нож.

MISSION ZERO сложнее удаления V2 по четырём причинам:
1. Требует решить **4 структурных противоречия**, а не выпилить один модуль.
2. Требует **архитектурных решений** (project references, realm extraction, typed globals) — не механической работы.
3. Блокирована FROZEN — нужно решение, которое обходит заморозку, не нарушая её.
4. Даёт **максимальное плечо**: 39% ошибок одного кода + 26% в одном файле = **65% долга закрывается двумя ходами**.

### План (5 фаз, каждая — отдельный PR, канон переутверждается после каждой)

### Ключевые решения (где нужна экспертность, а не труд)

**Z1 — project references вместо «починить frozen».**
```jsonc
// tsconfig.json  — основной, строгий, НЕ включает легаси
{ "include": ["src"], "exclude": ["src/audio/core/AudioEngineV2.ts", "src/audio/compat/patchV1.ts", "src/bridges/**", "src/services/track.orchestrator.ts"] }
// tsconfig.legacy.json — легаси, расслабленный, компилируется отдельно
{ "compilerOptions": { "strict": false, "noUnusedLocals": false, "composite": true, ... }, "include": [...frozen...] }
```
Юридически файлы не изменены — **frozen-стоп соблюдён**. Физически они больше не отравляют основной компайл.

**Z2 — почему `toString()`+Blob надо убрать, а не «замьютить типами».**
| | Сейчас | После |
|---|---|---|
| Типизация | невозможна (код — строка) | обычный .js с JSDoc или .ts |
| CSP | требует `blob:` + `unsafe-eval` | обычный статический файл |
| Кеширование | пересоздаётся каждый раз | HTTP-кеш |
| Дебаг | стек в `eval`'d коде | нормальные исходники |
| Бандлинг | не бандлится, не минифицируется | бандлится |

Шаг: `src/audio/engine-v3/diagnostics/CaptureWorklet.ts` → `public/worklets/capture-processor.js` + `addModule('/worklets/capture-processor.js')`. Осторожно: `addModule` **асинхронный** — все 2 точки вызова нужно перевести на await.

**Z4 — контракт транспорта снимет целый класс багов.** Один интерфейс, две реализации (V2-facade и V3-pipeline) — и баг класса C3 (`play()` вернул undefined) становится **ошибкой компиляции**, а не тихим падением в проде.

### Что НЕ надо делать (ловушки)

| Ловушка | Почему нет |
|---|---|
| `@ts-ignore` / `@ts-expect-error` оптом | ошибки скроются, а не исчезнут; через год вернутся багами |
| Выключить `strict` | он и так включён; выключение = деградация, а не модернизация |
| Апгрейд Vite 5→8 и TS 5→7 в том же PR | два мажора тулчейна одновременно = неотлаживаемый ад. Отдельные PR |
| Удалять V2 до Z1–Z4 | слепая хирургия |
| `tsc` на `exclude` тестов | тесты дают 40+ ошибок — это реальные дыры, не шум |
