## TL;DR (одна страница для Босса и YouTube-новчиков)

**bLb (beLiveBase)** — это не фича и не рефакторинг. Это **способ существования** репозитория. Каждое здание = режим (`Rehearsal`, `Karaoke`, `Concert`, `Live`, `Catalog`) или зона (`Studio`, `Quest`, `Show`, `Split`, `Styles`, `Notes`). Каждый этаж = конкретный объект (плагин реверба, микшер, кейс-сценарий, маркер). У каждого здания — свой **007-здания**, который знает про него всё, мониторит Context7, и приносит инициативы наверх.

**Три обещания:**

1. **Документация = код. Всегда.** Тыкаешь в здание → читаешь его паспорт. Меняешь код → паспорт предлагает обновление. Это не «сделаем когда-нибудь», а CI-гейт, который блокирует PR.
2. **У каждой зоны свой агент.** Не «один 007 на всех», а `studio-007`, `audio-007`, `auth-007`, `rehearsal-007`... Модель лёгкая (DeepSeek V4 Flash / GLM), задача — следить за зоной, приносить 007-Хабу апдейты.
3. **Ютуб-готовый визуал.** Здание можно нарисовать, обвести клик-зоны, запустить «guided tour». Новичок видит город, а не 546 файлов подряд.

## 4. Архитектурные инварианты (не обсуждаем, помним)

Из `architecture-map-2.1.md` §20 — это законы, ломать нельзя:

- **I-1.** `window.audioEngine`, `window.lyricsDisplay`, `window.markerManager`... — глобалы продолжают жить. Их патчат, не убивают.
- **I-2.** `AudioEngineV2` владеет транспортом. Сторы и бриджи могут зеркалить, не исполнять.
- **I-3.** Маркеры = канонический backbone для активной строки. Word sync — добавка, не замена.
- **I-4.** Слой бриджей — постоянная архитектура, не временная миграция.
- **I-5.** Performance policy ортогональна остальному.
- **I-6.** Prepared catalog — легитимный продуктовый путь.
- **I-7.** Cue truth ≠ Fill truth (ранний vs точный момент подсветки).
- **I-8.** 5 legacy-шеллов на `window.*` — постоянные identity boundaries.

**bLb** проходит через все восемь. Один район «Audio Engine» сидит на I-1/I-2. Район «Sync» — на I-3/I-7. Район «Catalog» — на I-6.

## 6. Паспорт здания: живая документация

Сейчас документы стареют потому, что у них **нет владельца, который бы их обновлял**. bLb это меняет.

### 6.1 Что такое паспорт

Для каждого здания (`packages/*` или подпапка) — файл `BUILDING.md`:

```markdown
# Mixer · STUDIO · 2-й этаж

**Координаты:** studio > mixer
**Этаж:** 2
**Владелец:** 007_Мак
**Агент района:** studio-007
**Год постройки:** 2024 (v1), 2026 (v3, A/B-mix)
**Жители:** пользователи Rehearsal + Live

## Назначение
Микшер дорожек трека (Bas/Drm/Gtr/Key/Vox) соло/мьют/уровни.

## Двери (входы)
- вверх: верхняя панель (Studio)
- вниз: M/S-кнопки -> state
- вбок: stem.store

## Коммуникации
- импортирует: stem.store, audio-engine (через V2Adapter)
- импортируется: RehearsalLyrics, LiveSubtitle, CatalogLayout

## Что внутри
- `src/components/MixerPanel/index.tsx` (главный)
- `src/components/MixerPanel/Cezoimxe.js`
- `src/stem/stem.store.ts`

## Этажная книга
- 2026-08-26 · обновлён дизайн (новые микро-иконки)
- 2026-08-29 · открыт issue: Solo-кнопка не работает в Karaoke
- 2026-08-30 · плагин `reverb` подключён как FX-этаж 3.1

## Ютуб-тур
- Старт: нажать Studio
- 0:00 — полосы дорожек
- 0:08 — Solo/Mute
- 0:14 — связь со стемами

## Паспорт выдан
- документ = код (последний ревью: 2026-08-29 18:00)
- нет устаревших ссылок
- ARCH-INVARIANT совместим (I-2: транспорт не здесь)
```

### 6.2 Как поддерживается актуальность

**CI-гейт `building-guardian.yml`:**

```yaml
- name: BUILDING-guard
  run: node scripts/check-buildings.mjs
```

`scripts/check-buildings.mjs` читает каждый `BUILDING.md` и проверяет:

- Все импортируемые файлы из раздела «Что внутри» существуют
- Все импортируемые здания (раздел «Коммуникации») имеют свои `BUILDING.md`
- Владелец — реальный человек (должен быть в `OWNERS.yaml`)
- Версия инварианта совпадает с `architecture-map-2.1.md` §20

Любая ошибка — красный PR. Это значит, **документация стареет не потому, что мы забываем, а потому что CI не пускает**.

### 6.3 Чего нельзя автоматизировать

Список «ютуб-туров» — это **человеческое решение**. Скрипт может подсказать, какие здания не имеют тура, но не может решить, какие 10 зданий показывать в первом ролике.

## 8. Технические решения, которые нужно принять на брифинге

### 8.1 Где лежит «город» в репо

**Вариант A: всё в `src/`, BUILDING.md рядом с кодом.**
```
src/
├── audio/
│   ├── BUILDING.md              # район Audio
│   ├── core/AudioEngineV2.ts    # здание
│   ├── core/BUILDING.md
│   └── compat/
│       ├── BUILDING.md
│       └── patchV1.ts
```

**Плюсы:** паспорт рядом с кодом — обновляются вместе. **Минусы:** загрязняет `src/` метаданными.

**Вариант B: отдельный корень `city/`, BUILDING.md по районам.**
```
city/
├── README.md                    # генплан
├── districts/
│   ├── studio/
│   │   ├── BUILDING.md          # район Studio
│   │   ├── 2-mixer/BUILDING.md
│   │   ├── 3-fx-reverb/BUILDING.md
│   │   └── INBOX.md             # почтовый ящик studio-007
│   ├── quest/...
├── registry/
│   ├── owners.yaml
│   └── invariants.yaml
└── map.json                     # машиночитаемая карта для скриптов
```

**Плюсы:** чисто, отделено, можно выкатить как под-проект. **Минусы:** далеко от кода, легко забыть обновить.

**Моя рекомендация:** **вариант B**. `city/` — это ортогональная ось к `src/`, документ живущий, не код, не имеет смысла лежать в `src/`. Аналогия: README в корне — не часть `src/`, а про `src/`. Так же `city/`.

### 8.2 Когда запускать район-007

**Пилот:** Studio + Audio. Это 2 района, где кодовая база готова, скриншоты есть, Босс знает каждое здание лично. Запускаем на них, обкатываем ритуал, потом масштабируем.

**Время:** один вечер на настройку, один вечер на первую итерацию. **Стоимость:** 0 — DeepSeek V4 Flash бесплатен.

### 8.3 Что делает «Build the city» (CI/CD)

`quality-gates.yml` уже содержит: native-binding, tsc-ratchet, console-ratchet, secret-guard. **Добавить `building-guardian`** — проверка `city/` против `src/`. Это **последний гейт перед PR-merge**, и он ругается не на «функция не работает», а на «паспорт здания не актуален».

## 12. Почему это «bLb» и не «repo-city» или «distr-base»

**beLiveBase** = **bLb** = «база beLive» в трёх смыслах:

1. **База как фундамент.** Город — это база, на которой стоит продукт.
2. **База как штаб.** Hub живёт в городе, не над ним.
3. **База как знание.** Паспорт здания = «знай свою базу».

И сокращение `bLb` — это **b**, **L**, **b** — те же буквы, что в логотипе beLive. Город носит имя проекта.
