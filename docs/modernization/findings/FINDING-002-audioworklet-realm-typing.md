# FINDING-002 — AudioWorklet-realm: 80 ошибок `tsc` одним файлом, ноль правок рантайма

**Дата:** 2026-08-29 (ночная смена, Кай)
**Статус:** ✅ применено, проверено эмитом JS
**Кому:** 007
**Эффект:** `tsc --noEmit` **307 → 227**, `CaptureWorklet.ts` **80 → 0**

---

## 1. Суть одной фразой

80 ошибок компилятора в одном файле были не «долгом по типам», а **отсутствующими
глобальными декларациями для другого realm'а**. Закрываются одним `.d.ts` без
единого изменения в исполняемом коде.

---

## 2. Симптом

```
$ node node_modules/typescript/bin/tsc --noEmit 2>&1 | grep CaptureWorklet | wc -l
80
```

Разбивка: **75 × TS2339** (`Property X does not exist on type 'CaptureProcessor'`)
и **5 × TS2304** (`Cannot find name 'AudioWorkletProcessor'`).

Всё это выглядит как «кто-то накосячил с полями класса», и естественное желание —
идти править 75 мест. Это было бы ошибкой.

---

## 3. Корень

`CaptureWorklet.ts` — это **не модуль в обычном смысле**. Его код сериализуется
через `Function.prototype.toString()` и исполняется в **другом realm'е** —
в AudioWorkletGlobalScope.

TypeScript с `lib: ["DOM"]` знает про `AudioWorkletNode`, но **не знает** про:

- `AudioWorkletProcessor` — базовый класс, от которого наследуются процессоры;
- `currentFrame` — глобальная переменная realm'а;
- `registerProcessor(name, ctor)` — глобальная функция realm'а.

Плюс `class CaptureProcessor` присваивал поля в конструкторе без объявления —
при `noUnusedLocals`/строгом режиме и наследовании от неизвестного базового класса
это даёт лавину TS2339.

**Ключевое наблюдение:** это не ошибки в коде. Это ошибки в **описании мира**,
в котором код работает.

---

## 4. Решение

### Шаг 1 — амбиентные декларации (`src/types/audio-worklet-global.d.ts`)

```ts
declare class AudioWorkletProcessor {
  readonly port: MessagePort
  constructor(options?: AudioWorkletNodeOptions)
}

declare const currentFrame: number

declare function registerProcessor(
  name: string,
  processorCtor: new (options?: any) => AudioWorkletProcessor
): void
```

**Почему `.d.ts`, а не обычный `.ts`:** декларационный файл **стирается при сборке** —
в бандл не попадает ничего. Значит ноль влияния на рантайм и ноль риска для
сериализации `toString()`.

→ **307 → 293**

### Шаг 2 — объявления полей в классе

15 полей в `class CaptureProcessor`:

```ts
class CaptureProcessor extends AudioWorkletProcessor {
  _buffer: Float32Array
  _bufferSize: number
  _quantumLenHist: Record<string, number>
  // … и т.д.
}
```

Нюанс, который стоил времени: ключи `_quantumLenHist` — **строки** (`String(len)`),
поэтому тип `Record<string, number>`, а не `Record<number, number>`.

→ **293 → 227**. `CaptureWorklet.ts` — **0 ошибок**. `TS2339` по всему проекту: **96 → 21**.

---

## 5. Проверка безопасности (обязательный шаг)

Код исполняется через `toString()`, поэтому мало «скомпилировалось» — надо
убедиться, что в сериализуемую строку не попало ничего лишнего.

```
$ node node_modules/typescript/bin/tsc src/audio/engine-v3/diagnostics/CaptureWorklet.ts \
      --outDir .workbuddy-ai/emit ...
```

Разбор эмита:

- аннотации типов стёрлись — в JS их нет;
- объявления полей превратились в нативные class fields;
- комментарии безвредны.

**Вывод:** сериализуемый текст изменился только пояснениями, поведение не затронуто.
Директория эмита после проверки удалена.

## 6. Почему это «элегантнее», чем править 75 мест

| Подход | Объём | Риск | Что остаётся |
|---|---|---|---|
| Править каждое обращение | 75 правок в рабочем коде | высокий: можно изменить поведение в hot-path аудио | 75 мест, которые надо поддерживать |
| **Описать realm один раз** | **1 файл, 20 строк** | **нулевой: `.d.ts` стирается** | **переиспользуемое описание для всех будущих worklet'ов** |

**Главное:** второй ворклет в проекте теперь получит типы бесплатно. Первый подход
заставил бы платить 75 правок **каждый раз**.

## 7. Смежные правки того же класса (микро-, но показательные)

| Было | Стало | Почему |
|---|---|---|
| `global.fetch` (3 места в `track-meta.service.test.ts`) | `globalThis.fetch` | `global` — это узловое наследие; `globalThis` един во всех realm'ах. `TS2304` → 0 |
| `@types/node` ради `process.on` в `BpmSwitchRace100.test.ts` | узкое локальное `declare const process` | см. ниже |

### Почему НЕ `@types/node`

Соблазн был: тест использует `process.on('unhandledRejection', …)`, компилятор
ругается (TS2591), и «очевидное» решение — поставить `@types/node`.

**Это плохая идея в браузерном проекте.** Подключив `@types/node` глобально, мы
открываем всему фронтенд-коду `fs`, `path`, `Buffer`, `process` — то есть делаем
легальным то, что в браузере не существует и никогда не заработает. Ошибка
исчезнет из `tsc` и переедет в рантайм, где её искать дороже.

Вместо этого — объявление ровно того, что нужно, ровно в том файле:

```ts
// Тесты Vitest выполняются в Node, поэтому `process` здесь существует.
// Объявление намеренно УЗКОЕ и локальное для файла: подключать @types/node
// в браузерный проект нельзя — это открыло бы fs/path/Buffer всему фронтенду.
declare const process: {
  on(event: 'unhandledRejection', listener: (reason: unknown) => void): void
  off(event: 'unhandledRejection', listener: (reason: unknown) => void): void
}
```

→ `TS2591` **10 → 2** (оставшиеся 2 были тем самым `require` из [FINDING-001](./FINDING-001-v2-resurrection-detector-silent-noop.md), сейчас 0).

## 8. Паттерн для 007

> **Прежде чем править N ошибок компилятора — посмотри, не описывают ли они
> одну отсутствующую абстракцию.** Лавина однотипных ошибок почти всегда означает
> не «много плохого кода», а «нет одного хорошего описания».

Признаки, что стоит искать декларацию, а не править места:

- ошибки кучей, одного кода, в одном файле;
- текст ошибок про **базовый класс** или **глобальный объект**, а не про логику;
- код работает в рантайме (прод работает), но не компилируется — значит типы
  отстали от реальности, а не реальность сломана.

И правило про `@types/node` в браузерном проекте — см. §7.
