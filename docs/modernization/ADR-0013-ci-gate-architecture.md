# ADR-0013 · Архитектура CI-гейтов: храповик, а не выключатель

**Статус:** proposed · **Дата:** 2026-08-29 · **Волна:** W0
**Связано:** [01-BASELINE §6](./01-BASELINE.md), [ADR-0012](./ADR-0012-dependency-manifest-policy.md), [ADR-0010](./ADR-0010-dev-environment-and-node-modules-integrity.md)

---

## Контекст

В репозитории три workflow:

| Workflow | Триггер | Что делает |
|---|---|---|
| `deploy.yml` | push в `main` | `npm ci` → `npm test -- --run` → `verify:ci` → `build` → Pages |
| `deploy-rehearsal.yml` | push в `main`, `gateway/rehearsal/**` | wrangler deploy |
| `doc-sync-check.yml` | PR | проверяет `docs/sync/MASTER-SYNC-REGISTRY.yaml` |

**Три проблемы.**

**1. Гейта на типы нет вообще.** `package.json` содержит скрипт `typecheck`, но **ни один workflow его не вызывает**. 307 ошибок компилятора не блокируют ни сборку, ни деплой, ни мердж.

**2. Один гейт красный всегда.** `doc-sync-check.yml`:

```yaml
if [ ! - f docs/sync/MASTER-SYNC-REGISTRY.yaml ]; then exit 1; fi
```

Файл **загитignoreн** (`docs/sync/`, строка 66). На чистом checkout его нет никогда → `exit 1` → **джоба красная на каждом PR с момента создания**.

Это не мелочь. **Гейт, красный всегда, перестаёт быть сигналом.** Команда привыкает не смотреть в CI. А ровно в этом фоне и живут 307 ошибок: гейта на типы нет, а привыкший к красному человек не замечает отсутствия зелёного.

**3. Нельзя включить гейт «ноль ошибок» прямо сейчас.** При 307 ошибках такой гейт закроет все PR — и его выключат в тот же день. Нужен механизм, который **сначала останавливает рост**, а потом сжимается до нуля.

---

## Решение

### Принцип

> **Гейт — это храповик (ratchet), а не выключатель.**
> Он фиксирует текущий уровень и разрешает только улучшение. Никогда — ухудшение.

### 1. Храповик по типам

```yaml
- name: Typecheck ratchet
  run: |
    COUNT=$(node node_modules/typescript/bin/tsc --noEmit 2>&1 | grep -c "error TS" || true)
    BASELINE=$(cat .ci-baseline/tsc)          # 307 на 2026-08-29
    echo "tsc: $COUNT (baseline $BASELINE)"
    if [ "$COUNT" -gt "$BASELINE" ]; then
      echo "❌ Ошибок больше базового уровня. Новые ошибки не принимаются."
      exit 1
    fi
    if [ "$COUNT" -lt "$BASELINE" ]; then
      echo "✅ Стало лучше. Обнови baseline: echo $COUNT > .ci-baseline/tsc"
    fi
```

Механика: файл `.ci-baseline/tsc` содержит **307**. Любой PR, увеличивающий счётчик, — красный. Любой PR, уменьшающий, — зелёный и **обязан обновить baseline тем же коммитом**. Так счётчик только убывает, и после W1 (MISSION ZERO) естественно дойдёт до нуля, после чего гейт переключается в жёсткий режим `= 0`.

### 2. Быстрые гейты — первыми

Порядок шагов в job: от дешёвого к дорогому. Нет смысла тратить 4 минуты на сборку, если манифест сломан.

```yaml
steps:
  - checkout
  - setup-node (cache: npm)
  - npm ci
  - ✅ check-native-bindings   # ~2 с  (ADR-0010)
  - ✅ check-manifest          # ~3 с  (ADR-0012)
  - ✅ typecheck ratchet       # ~15 с → ~1-2 с после TS 7
  - ✅ verify:ci (parity)      # ~10 с
  - ✅ test                    # ~60 с
  - ✅ build                   # ~120 с
```

### 2.1 ⚠️ Подключить линтер к TypeScript — сейчас он не работает вообще

`eslint.config.mjs` содержит только `js.configs.recommended` и блок с `files: ["**/*.js"]`. **Ни одного правила для `.ts`/`.tsx`.** Пакеты `@typescript-eslint/parser` и `@typescript-eslint/eslint-plugin` установлены, но ни разу не подключены (встречаются лишь в `eslint-disable`-комментариях в `src/`).

Итог: `npm run lint` формально запускается, но **546 TS-файлов не линтится**. Именно поэтому в коде уживаются 541 `as any` и 119 неиспользуемых переменных — ни один инструмент на это не смотрит.

Что сделать:
```js
// eslint.config.mjs — добавить блок для TS/TSX
{
  files: ["**/*.{ts,tsx}"],
  languageOptions: { parser: tsParser, parserOptions: { project: "./tsconfig.json" } },
  plugins: { "@typescript-eslint": tsPlugin },
  extends: [tsPlugin.configs.recommended],
  rules: {
    "@typescript-eslint/no-explicit-any": "warn",   // warn, не error — 541 вхождений
    "@typescript-eslint/no-unused-vars": "error",   // это как раз TS6133
  },
}
```

**Важно:** включать как `warn` с нулевым бюджетом предупреждений, а не сразу `error`. При 541 `as any` гейт `error` закроет все PR — и его отключат ([ADR-0012](./ADR-0012-dependency-manifest-policy.md), тот же принцип храповика).

### 3. Починить `doc-sync-check.yml`

Три варианта, выбрать один:
- **(рекомендуется)** перенести workflow в приватный репозиторий вместе с реестром ([ADR-0011](./ADR-0011-git-and-doc-visibility-policy.md));
- если реестр переезжает в git-tracked место — поправить путь;
- если реестр больше не ведётся — **удалить workflow**.

> **Красный-всегда гейт вреднее отсутствующего гейта.** Он не просто бесполезен — он обучает команду игнорировать CI.

### 4. Защита `main`

Из `TEAM-007-ENGINEERING-PROCESS.md`, применить здесь:
- branch protection на `main`: обязательные проверки, запрет force-push;
- `CODEOWNERS` с указанием владельцев доменов;
- агентам — запрет push/deploy, только PR с меткой `agent-generated`.

### 5. Матрица ОС — позже

Сейчас CI работает только на `ubuntu-latest`. Это **маскирует поломку Windows-среды**: билд зелёный в CI, и поэтому никто не заметил, что на машине разработки ничего не запускается.

Добавить `windows-latest` в матрицу — **после** [ADR-0010](./ADR-0010-dev-environment-and-node-modules-integrity.md). Раньше нельзя: матрица будет красной по причине, которую мы уже знаем. macOS-раннер — только если появится macOS-код (в CLI он в 10× дороже).

## Почему не другие варианты

| Вариант | Почему нет |
|---|---|
| Сразу гейт «tsc = 0» | Закроет все PR. Отключат в первый же день — и надолго |
| `continue-on-error: true` для typecheck | Тот же «красный фон»: сигнал без последствий |
| Считать ошибки раз в неделю вручную | Не сработает: рутина, которую никто не делает |
| Только локальные хуки (husky/pre-commit) | Нужен работающий тулчейн на каждой машине ([ADR-0010](./ADR-0010-dev-environment-and-node-modules-integrity.md)), плюс хуки обходятся флагом `--no-verify`. CI — обязателен, хуки — дополнение |
| Добавить Windows в матрицу прямо сейчас | Будет красно по известной причине. Сначала W−1 |

## Последствия

**Плюсы**
- Рост ошибок **останавливается немедленно**, не дожидаясь W1. Это самое ценное свойство: храповик начинает работать с первого дня.
- Прогресс виден каждому PR: счётчик только убывает.
- Быстрые гейты первыми → фидбек за секунды, а не за 4 минуты.
- Убирается «красный всегда» гейт → CI снова становится сигналом.

**Минусы / чем платим**
- **Baseline-файл надо обновлять руками.** Компенсация: скрипт печатает точную команду для обновления; PR без обновления baseline просто не уменьшит число.
- **Храповик не лечит старый долг** — он только запрещает новый. Лечение — W1.
- Счётчик через `grep -c` хрупок при смене формата вывода tsc. Компенсация: зафиксировать мажорную версию TS в CI и проверять парсер при апгрейде ([ADR-0005](./ADR-0005-toolchain-upgrade-path.md)).
- Время CI вырастет на ~20 с (typecheck + 2 новых гейта). Приёмлемо при бюджете ≤10 мин.

## План внедрения

| Шаг | Действие | Проверка |
|---|---|---|
| 1 | Создать `.ci-baseline/tsc` со значением **307** | файл есть |
| 2 | Добавить шаг typecheck-ratchet в `deploy.yml` | на текущем PR зелёный |
| 3 | Добавить `check-native-bindings` ([ADR-0010](./ADR-0010-dev-environment-and-node-modules-integrity.md)) | зелёный |
| 4 | Добавить `check-manifest` ([ADR-0012](./ADR-0012-dependency-manifest-policy.md)) | зелёный |
| 5 | Разобраться с `doc-sync-check.yml` | PR больше не красный всегда |
| 6 | Branch protection + CODEOWNERS на `main` | прямой push запрещён |
| 7 | **(после W−1)** добавить `windows-latest` в матрицу | обе ОС зелёные |
| 8 | **(после W1)** переключить гейт в режим `= 0` | гейт жёсткий |

**Откат:** каждый шаг — отдельный YAML. `git revert` восстанавливает предыдущее поведение.

## Критерий успеха (DoD W0)

- [ ] Любой PR, увеличивающий число ошибок tsc, **красный** (проверить искусственно)
- [ ] Ни один workflow не падает на чистом checkout без причины
- [ ] `main` защищён: force-push запрещён, проверки обязательны
- [ ] Время пайплайна ≤ **10 минут**
- [ ] Baseline зафиксирован в `.ci-baseline/tsc` и в REGISTRY

> **Проверка храповика обязательна:** нужно искусственно добавить ошибку в ветке и убедиться, что CI краснеет. Гейт, ни разу не сработавший, — это гейт, в котором никто не уверен.
