# ADR-0015 · Политика FROZEN-зон: заморозка защищает содержимое, но не блокирует прогресс

> 🔓 Носитель эпохи замка — упразднён 03.09; механизм из этого ADR не внедрялся, охрана = ливнесс-гейты G-1/G-2/G-4 (`verify:reach=121`, `verify:ci`). Инлайн-список ниже — исторический срез W1 (одна зона на тот момент).

**Статус:** proposed · **Дата:** 2026-08-29 · **Волна:** W1
**Связано:** [ADR-0001](./ADR-0001-legacy-isolation-project-references.md), [ADR-0004](./ADR-0004-v2-legacy-removal-sequence.md), [01-BASELINE §3](./01-BASELINE.md)

---

## Контекст

`src/audio/core/AudioEngineV2.ts` (2 178 LOC) помечен **FROZEN**. Он даёт **7 ошибок tsc**:

```
6 × TS6133 — объявлено, но не используется
    (BUILTIN_STEMS, _LOOP_RESYNC_BLACKOUT_MS, _SYNC_BLACKOUT_FLOOR, opts, id, _micCaptureEnabled)
1 × TS2345 — Float32Array<ArrayBufferLike> несовместим с Float32Array<ArrayBuffer>
```

**Отсюда следует жёсткий факт:** пока FROZEN-файл компилируется в одном юните со всем остальным кодом, **`tsc --noEmit` = 0 недостижим в принципе**. «Канон 296» — это не цель, а **пол, заданный замороженным легаси**.

**Но есть деталь, которая делает ситуацию острее.** Ошибка TS2345 не наша: она прилетела из TypeScript 5.7+, сделавшего `TypedArray` дженериком по backing buffer. То есть **апгрейд тулчейна уже добавил ошибку в файл, который править нельзя** ([ADR-0005](./ADR-0005-toolchain-upgrade-path.md)). С каждым мажором TS таких ошибок будет больше.

**Проблема не в ошибках, а в неопределённости.** Что именно запрещает заморозка?
- Можно ли менять форматирование?
- Можно ли добавить `@ts-ignore`?
- Можно ли тронуть файл ради апгрейда компилятора?
- Кто имеет право снять заморозку?

Без ответов каждая ситуация решается импровизацией — а импровизация с замороженным аудио-движком дорога.

---

## Решение

### Принцип

> **Заморозка защищает файл от изменений, но не проект от прогресса.**
> Если заморозка мешает двигаться — двигается **проект вокруг файла**, а не файл.

### 1. Что именно запрещено

| Действие | Статус |
|---|---|
| Изменять логику, алгоритмы, структуру | ❌ **запрещено** |
| Добавлять `@ts-ignore` / `@ts-expect-error` / `@ts-nocheck` | ❌ **запрещено** — это маскировка, а не исправление |
| Менять форматирование, переносы строк, пробелы | ❌ **запрещено** — ломает `git blame`, а пользы ноль |
| Обновлять комментарии/документацию внутри файла | ❌ **запрещено** без OVERRIDE (см. п. 3) |
| **Исключить файл из compilation unit** (конфиг) | ✅ **разрешено** — файл не изменяется ([ADR-0001](./ADR-0001-legacy-isolation-project-references.md)) |
| **Удалить файл целиком** | ✅ разрешено по завершении W2 ([ADR-0004](./ADR-0004-v2-legacy-removal-sequence.md)) |
| Переместить файл | ⚠️ требует OVERRIDE: путь — часть контракта для импортёров |

### 2. Где живёт список

```
docs/architecture/frozen-zones-v2.md   ← существующий документ, сделать его machine-readable
```

Добавить `.frozen-zones.json`:

```json
{
  "version": 1,
  "updated": "2026-08-29",
  "zones": [
    {
      "path": "src/audio/core/AudioEngineV2.ts",
      "reason": "V2-движок, выводится из эксплуатации в W2",
      "since": "2026-08-06",
      "until": "W2 complete",
      "owner": "boss",
      "overridePolicy": "boss + 2 reviewers"
    }
  ]
}
```

Machine-readable список нужен, чтобы **CI мог проверять заморозку автоматически** — а не на глаз в код-ревью.

### 3. Процедура OVERRIDE

Если заморозку нужно нарушить:

1. Отдельный PR, в описании — **что** меняем и **почему нельзя иначе**;
2. Метка `frozen-override`;
3. Два ревьюера + подтверждение Босса;
4. Обновление `.frozen-zones.json` в том же PR (если зона снимается).

**Явное правило для апгрейдов компилятора.** Если новый мажор TS добавляет ошибки в FROZEN-файл — это **не** повод для OVERRIDE. Решение: файл уже изолирован ([ADR-0001](./ADR-0001-legacy-isolation-project-references.md)), его ошибки считаются отдельным информационным шагом. OVERRIDE нужен только если ошибка блокирует что-то ещё.

### 4. Гейт в CI

```yaml
- name: Frozen zones intact
  run: node scripts/check-frozen.mjs
  # сверяет git diff против .frozen-zones.json; красный при любом изменении без метки frozen-override
```

### 5. Срок действия

**У каждой замороженной зоны должен быть `until`.** Заморозка без срока — это способ навсегда отказаться от файла. В нашем случае срок — завершение W2, когда V2-движок удалят ([ADR-0004](./ADR-0004-v2-legacy-removal-sequence.md)).

## Почему не другие варианты

| Вариант | Почему нет |
|---|---|
| Снять заморозку и починить 7 ошибок | Дешевле выглядит, но ломает сам механизм. Если заморозку можно обойти семью правками, её нельзя соблюдать ни в чём |
| `@ts-nocheck` в начало файла | Снимает **все** проверки с 2 178 строк живого аудио-движка. Маскирует настоящие баги — худший из вариантов |
| «Канон = 296, ноль не нужен» | Закрепляет терпимость; любой апгрейд TS будет увеличивать число |
| Заморозить больше файлов (весь V2) | Сейчас заморожен один — этого достаточно. Расширение заморозки без срока = консервация долга |
| Проверять заморозку только на ревью | Человек пропустит. Нужен машинный гейт |

---

## Последствия

**Плюсы**
- Неопределённость исчезает: у каждого действия есть явный статус.
- Появляется **машинный контроль** вместо надежды на внимательность ревьюера.
- [ADR-0001](./ADR-0001-legacy-isolation-project-references.md) получает юридическую базу: исключение из compilation unit — **разрешённое** действие, не нарушающее заморозку.
- `until` не даёт заморозке стать вечной.

**Минусы / чем платим**
- **Бюрократия.** Файл конфигурации, гейт, процедура. Компенсация: зон пока одна; оверхед минимальный.
- **Гейт будет красным на легитимных правках** (например, удалении файла в W2). Компенсация: метка `frozen-override` и обновление `.frozen-zones.json` в том же PR.
- Риск «заморозили и забыли». Компенсация: поле `until` + напоминание в REGISTRY.

## План внедрения

| Шаг | Действие | Критерий |
|---|---|---|
| 1 | `.frozen-zones.json` с текущей зоной (`AudioEngineV2.ts`) | файл есть |
| 2 | `scripts/check-frozen.mjs` | гейт работает |
| 3 | Шаг в CI | гейт зелёный |
| 4 | Описать политику в `docs/architecture/frozen-zones-v2.md` | документ обновлён |
| 5 | Проверить: [ADR-0001](./ADR-0001-legacy-isolation-project-references.md) не нарушает политику | исключение — разрешённое действие ✅ |
| 6 | В W2 — удалить зону вместе с файлом | `.frozen-zones.json` → пустой |

**Откат:** политика — это документация и конфиг; откат не влияет на код.

---

## Критерий успеха (DoD W1)

- [ ] `.frozen-zones.json` существует и покрывает все замороженные файлы
- [ ] CI краснеет при изменении FROZEN-файла без метки `frozen-override`
- [ ] [ADR-0001](./ADR-0001-legacy-isolation-project-references.md) применён **без** единого изменения FROZEN-файлов
  (`git diff --stat` по зонам → пусто)
- [ ] У каждой зоны указан `until`

> **Главное:** этот ADR существует для того, чтобы фраза «frozen не трогать» не стала причиной, по которой проект не может двигаться. Заморозка защищает файл — и только файл.
