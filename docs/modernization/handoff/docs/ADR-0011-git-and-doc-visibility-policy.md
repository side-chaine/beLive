# ADR-0011 · Политика видимости: два репозитория, `gitignore` только для артефактов

**Статус:** proposed · **Дата:** 2026-08-29 · **Волна:** W0
**Связано:** [01-BASELINE §2](./01-BASELINE.md), [ADR-0010](./ADR-0010-dev-environment-and-node-modules-integrity.md)

---

## Контекст

Реестр, который Никит читает при сбросе контекста (`docs/agents/REGISTRY.md`), **отсутствует на второй машине**. В прошлой сессии я записал гипотезу «лежит на Linux-машине и не запушен».

Гипотеза оказалась неверной, и правильный ответ хуже:

```
$ git check-ignore -v docs/agents/REGISTRY.md
.gitignore:76:docs/agents/    docs/agents/REGISTRY.md   → IGNORED
```

Реестр **загитignoreн**. Он не «не запушен» — он **не может быть запушен**. Он физически не покидает машину, на которой создан.

**Масштаб:**

| Метрика | Значение |
|---|---|
| `.md` в `docs/` на диске | 125 |
| отслеживается git | 58 |
| **невидимо для git** | **67 (54%)** |

**Но прямое исправление невозможно.** Репозиторий публичный:

```
private: false · visibility: public · has_pages: true
```

А в `.gitignore` стоит комментарий, объясняющий намерение:

```gitignore
# Internal docs — not for public
docs/sync/
docs/ARCH-BASE.md
# Internal agent docs
docs/agents/
```

Игнорирование — **осознанная защита**, а не халатность. Раскомментировать = выложить внутренние документы в открытый доступ. Утечка через git **необратима**: удаление из истории требует переписывания всех коммитов.

**Сломанный гейт как следствие.** `.github/workflows/doc-sync-check.yml` проверяет наличие `docs/sync/MASTER-SYNC-REGISTRY.yaml`. Файл загитignoreн → на чистом checkout его нет никогда → шаг делает `exit 1` → **джоба красная на каждом PR с момента создания**. Гейт, красный всегда, перестаёт быть сигналом и учит команду не смотреть в CI.

---

## Решение

### Принцип

> **`gitignore` существует для артефактов сборки, секретов и машинно-локального состояния — но не для «я не хочу это видеть» и не для «это внутреннее».**
>
> У документа должен быть **дом с правильным уровнем доступа**, а не отсутствие дома.

### 1. Два репозитория

| Репозиторий | Доступ | Что лежит |
|---|---|---|
| `side-chaine/beLive` | **public** | `src/`, `gateway/`, `belive-feed-bot/`, публичные доки (`docs/architecture/`, `README`, `SECURITY`, `CONTRIBUTING`), CI, Pages |
| `side-chaine/beLive-internal` *(создать)* | **private** | `docs/agents/`, `docs/sync/`, `docs/operations/`, `docs/modernization/ADR` *(см. п.4)*, `docs/ARCH-BASE.md`, операционные пакеты |

Частные репозитории на GitHub бесплатны. Оба клонируются на все машины → **реестр наконец начинает путешествовать**.

### 2. Публичный репозиторий: чистим `gitignore`

```gitignore
# --- артефакты сборки ---
node_modules/
dist/
dev-dist/
*.log *.bak *.tmp

# --- секреты ---
.env
.env.*
!.env.example

# --- мусор ОС (ДОБАВИТЬ — сейчас 65 файлов в дереве) ---
.DS_Store
._*
Thumbs.db
desktop.ini

# --- машинно-локальное ---
.vscode/ .kiro/ .qoder/ .opencode/ .roo/ .Cline/
.workbuddy-ai/        # состояние агента конкретной машины
test-results/
```

**Удалить** из `.gitignore` (переезжают в приватный репозиторий, а здесь просто больше не нужны): `docs/agents/`, `docs/sync/`, `docs/ARCH-BASE.md`, `docs/archive/`, `research/`, `belive-api/`, `plans/`.

> ⚠️ Порядок важен: **сначала** создать приватный репозиторий и запушить туда документы, **потом** удалять правила из `.gitignore`. Иначе между шагами внутренние доки окажутся в публичном индексе.

### 3. `belive-api/` — оставляем как есть, но фиксируем явно

`belive-api/` — **вложенный репозиторий** со своим remote (`side-chaine/belive-api`), а не потерянный код (см. [01-BASELINE §2.3](./01-BASELINE.md)). Правило `.gitignore:77` избыточно — git и так не отслеживает вложенные репозитории. Оставляем правило как **документированное намерение**, но добавляем комментарий, чтобы следующий человек не поднял ложную тревогу:

```gitignore
# belive-api — отдельный репозиторий (side-chaine/belive-api), не подключать как подмодуль
belive-api/
```

### 4. Куда девать ADR

ADR — это решения команды, часть из них содержит внутренние оценки. Рекомендация: **держать ADR в приватном репозитории**, а в публичный выкладывать только `docs/architecture/` (архитектура как витрина проекта).

Исключение — если Никит решит, что ADR должны быть публичными (это позитивный сигнал для контрибьюторов). Тогда они остаются здесь. **Это решение за Никитом.**

### 5. Починить сломанный гейт — независимо от остального

`doc-sync-check.yml` должен проверять то, что реально существует. Варианты:
- **(рекомендуется)** перенести workflow в приватный репозиторий вместе с реестром;
- если реестр остаётся публичным — поправить путь;
- если реестр больше не ведётся — **удалить workflow**.

Красный-всегда гейт вреднее отсутствующего гейта: он приучает игнорировать CI.

---

## Почему не другие варианты

| Вариант | Почему нет |
|---|---|
| Раскомментировать `docs/agents/`, `docs/sync/` | **Публичная утечка внутренних документов.** Необратимо |
| Сделать `beLive` приватным целиком | Pages на приватном репозитории требует платного плана → придётся городить отдельный публичный репозиторий под Pages. Больше движущихся частей при той же защите |
| Приватный подмодуль внутри публичного репозитория | Работает (в публичное дерево уходит только gitlink), но подмодули — постоянный источник боли: `git submodule update`, отсоединённый HEAD, забытые обновления. Для кроссплатформенной команды из нескольких человек — лишний риск |
| Хранить внутренние доки в Notion/Obsidian | Решает синхронизацию, но ломает docs-as-code: нет ревью, нет истории в git, нет работы агентов. А реестр нужен именно агентам |
| Оставить как есть, носить доки флешкой | Текущее состояние. Реестр уже потерян один раз — это не гипотеза, а зафиксированный факт |

## Последствия

**Плюсы**
- Реестр, отчёты агентов и операционные пакеты **начинают синхронизироваться** между машинами — главная боль закрыта.
- Публичный репозиторий остаётся публичным и безопасным; `docs/architecture/` работает как витрина.
- Исчезает «красный всегда» гейт → CI снова становится сигналом.
- 65 мусорных файлов `._*` уходят из дерева → диффы снова читаемы.

**Минусы / чем платим**
- **Два клона вместо одного.** Нужно привыкнуть. Компенсация: зафиксировать в `TEAM-007-ENGINEERING-PROCESS.md` и в README приватного репозитория.
- **Ссылки между репозиториями ломаются.** Документ в публичном репозитории не может сослаться относительным путём на приватный. Компенсация: ссылаться на приватное только по именам файлов, без путей.
- **Риск случайного коммита внутреннего в публичный.** Компенсация: `.gitignore` публичного репозитория проверяется CI-шагом «в дереве нет `docs/agents/`, `docs/sync/`».
- Требует действия Никиты: создать приватный репозиторий.

## План внедрения

| Шаг | Действие | Проверка |
|---|---|---|
| 1 | Создать приватный `beLive-internal` | репозиторий есть, `visibility: private` |
| 2 | Перенести `docs/agents/`, `docs/sync/`, `docs/operations/`, `docs/ARCH-BASE.md` | `git -C beLive-internal ls-files \| wc -l` > 0 |
| 3 | Запушить приватный репозиторий | `git push` OK |
| 4 | **Только теперь** почистить `.gitignore` публичного | `git check-ignore docs/agents/REGISTRY.md` → путь больше не существует |
| 5 | Добавить `._*`, `desktop.ini`, `.workbuddy-ai/` в `.gitignore` | `git status` не показывает `._*` |
| 6 | Удалить/перенести `doc-sync-check.yml` | PR больше не красный всегда |
| 7 | CI-гейт: в публичном дереве нет внутренних доков | гейт зелёный |

**Откат:** каждый шаг обратим. Худший сценарий — вернуть `.gitignore` из истории; содержимое документов при этом не страдает, так как они к тому моменту уже в приватном репозитории.

---

## Критерий успеха (DoD)

- [ ] `docs/agents/REGISTRY.md` существует **на обеих машинах** и идентичен (проверить по `git log` в приватном репозитории)
- [ ] `git status` в публичном репозитории не показывает `._*`-файлы
- [ ] Ни один PR не падает в `doc-sync-check`
- [ ] В публичном индексе git нет файлов из `docs/agents/`, `docs/sync/` (проверка: `git ls-files | grep -c 'docs/agents\|docs/sync'` → 0)

> **Главный критерий:** через неделю Никит открывает вторую машину, говорит «прочти REGISTRY.md» — и он там **есть**.
