# ADR-0014 · Раскладка монорепозитория: оставить как есть, но задокументировать границы

**Статус:** proposed · **Дата:** 2026-08-29 · **Волна:** W2
**Связано:** [01-BASELINE §2.3](./01-BASELINE.md), [TEAM-007](./../governance/TEAM-007-ENGINEERING-PROCESS.md)

---

## Контекст

В одной директории живут четыре разные сущности:

| Каталог | Что | Свой git | Трекинг |
|---|---|---|---|
| `src/`, `js/`, `public/` | PWA (Vite + React) | общий | ✅ 588 файлов |
| `gateway/` | Cloudflare Workers + D1 | общий | ✅ 36 файлов |
| `gateway/rehearsal/` | отдельный воркер со своим `package.json` | общий | ✅ |
| `belive-feed-bot/` | Telegram-бот | общий | ✅ 13 файлов |
| **`belive-api/`** | Cloudflare Worker (auth) | **свой** (`side-chaine/belive-api`) | вложенный репозиторий |
| `signalsmith-spike/`, `research/`, `test-aether/` | исследования | общий | `research/` загитignoreн |
| `~`, `team-m/` | мусор и отчёты | общий | ~/ загитignoreн |

**Историческая развилка.** В 2026-08-28 команда уже решила ([TEAM-007](./../governance/TEAM-007-ENGINEERING-PROCESS.md)): **гибрид** — `beLive` остаётся монорепозиторием, desktop-клиенты (WPF, macOS) выносятся в отдельные репозитории. Это решение остаётся в силе; здесь уточняется только внутренняя раскладка.

**Что не так сейчас:**
- **вложенный репозиторий** `belive-api/` — не подмодуль, не поддерево, просто каталог с чужим `.git`. Git молча его игнорирует, из-за чего возникают ложные тревоги («сервис потерян» — именно такую я поднял в эту сессию и был неправ);
- **два `package.json` в `gateway/`** — корневой и `gateway/rehearsal/`, каждый со своим `npm ci`;
- **`~` и `team-m/`** — мусор и разовые отчёты в корне продуктового репозитория.

---

## Решение

### Принцип

> **Не перестраивать раскладку ради красоты. Задокументировать то, что есть, и убрать только опасное.**

Монорепозиторий работает. Переезд на npm workspaces / turborepo — это недели работы без прямой пользы для продукта. Гораздо дешевле зафиксировать правила.

### 1. `belive-api/` — оставить вложенным репозиторием, но описать

```gitignore
# belive-api — отдельный репозиторий: side-chaine/belive-api
# НЕ подмодуль и НЕ поддерево. Осознанно не включается в этот репозиторий.
# Коммитить оттуда: cd belive-api && git …
belive-api/
```

**Почему не подмодуль:** подмодуль зафиксировал бы конкретный коммит и требовал бы `git submodule update` на каждой машине — лишняя точка боли для команды, которая уже теряет реестр между машинами ([ADR-0011](./ADR-0011-git-and-doc-visibility-policy.md)).

**Что нужно сделать:** у сервиса **3 коммита**, последний — 2026-06-07, и **6 незакоммиченных файлов**. Закоммитить.

### 2. `gateway/` — оставить два package.json, но вынести в workspaces позже

Сейчас `deploy-rehearsal.yml` делает `npm ci` внутри `gateway/rehearsal/`. Это работает. Перевод на workspaces — отдельная задача **после W4**, когда тулчейн стабилизируется (трогать разрешение зависимостей во время апгрейда Vite 5→8 — лишний риск).

### 3. Убрать мусор

| Каталог | Действие |
|---|---|
| `~` (содержит только `Desktop/`) | **удалить** — это артефакт, не проект |
| `team-m/` | перенести содержимое в `docs/operations/reports/`, каталог удалить |
| `test-aether/`, `signalsmith-spike/` | перенести в `research/` (уже загитignoreн) либо удалить если не нужны |
| `spike-s4-real-cpu.html`, `test-aether.html` | перенести в `research/` |

### 4. Задокументировать границы

В `docs/architecture/` — короткий документ «Где что лежит»: какой каталог, какой деплой, какой репозиторий, кто владелец. Цель — чтобы новый человек (или агент) не тратил час на то, чтобы понять, что `belive-api` — это отдельный мир.

---

## Почему не другие варианты

| Вариант | Почему нет |
|---|---|
| Переехать на npm workspaces / turborepo / nx | Недели работы, риск сломать разрешение зависимостей, ноль прямой пользы для продукта. Рассмотреть только если появится 5+ пакетов с общими зависимостями |
| Вынести `gateway/`, `belive-feed-bot/` в отдельные репозитории | Разные циклы деплоя — аргумент, но и +3 репозитория к синхронизации. При текущем размере (36 и 13 файлов) не окупается |
| Сделать `belive-api` подмодулем | Добавляет `submodule update` в каждый клон; риск потерять изменения. Вложенный репозиторий проще и уже работает |
| Оставить `~` и `team-m/` | Мусор в корне продуктового репозитория — это постоянный источник ложных тревог (я сам принял `~` за что-то значимое) |

---

## Последствия

**Плюсы**
- Раскладка **задокументирована** → новые люди и агенты не тратят время на археологию.
- Вложенный репозиторий перестаёт выглядеть как потерянный код.
- Корень становится читаемым: только то, что относится к продукту.

**Минусы / чем платим**
- Два `package.json` в `gateway/` остаются до W4 — некоторая двойственность при обновлении зависимостей.
- Вложенный репозиторий по-прежнему легко не заметить. Компенсация: комментарий в `.gitignore` + документ-карта.
- Перенос `team-m/`, `test-aether/` — это перемещение файлов; ссылки на них в старых отчётах устареют. Компенсация: зафиксировать в этом ADR и в REGISTRY.

## План внедрения

| Шаг | Действие | Критерий |
|---|---|---|
| 1 | Комментарий про `belive-api/` в `.gitignore` | комментарий есть |
| 2 | Закоммитить 6 файлов в `belive-api` | `git -C belive-api status` чист |
| 3 | `docs/architecture/REPO-LAYOUT.md` — карта каталогов | документ есть |
| 4 | Удалить `~`, перенести `team-m/` в `docs/operations/reports/` | корень чист |
| 5 | Перенести исследования и спайки в `research/` | корень чист |

**Откат:** перемещения обратимы, удаление `~` — после проверки, что там только `Desktop/`.

## Критерий успеха (DoD W2)

- [ ] `docs/architecture/REPO-LAYOUT.md` существует и актуален
- [ ] В корне — только продуктовые каталоги и стандартные файлы
- [ ] `belive-api` закоммичен, remote живой
- [ ] Новый человек понимает раскладку за 5 минут, не задавая вопросов

> ⚠️ **Шаг 4 требует подтверждения Никита** перед удалением `~`. Сначала проверю содержимое и покажу список.
