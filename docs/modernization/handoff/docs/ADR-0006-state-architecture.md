# ADR-0006 · Архитектура состояния: агрегаты по доменам, декомпозиция по принципу «тронул — разбери»

**Статус:** proposed · **Дата:** 2026-08-29 · **Волна:** W5 (параллельно W3–W4)
**Связано:** [01-BASELINE](./01-BASELINE.md), [ADR-0003](./ADR-0003-typed-global-contracts.md)

---

## Контекст

**Состояние расслоено.** Zustand импортируют **43 файла** (`zustand@5.0.11`). Сторы живут в `src/stores/`, но доменная логика размазана: компоненты читают несколько сторов, сторы подписываются друг на друга, часть состояния дублируется в `window.__belive` (см. [ADR-0003](./ADR-0003-typed-global-contracts.md)).

**11 god-файлов >880 строк** (замерено 2026-08-29):

| Файл | LOC | Природа |
|---|---|---|
| `src/audio/core/AudioEngineV2.ts` | 2 178 | 🔒 FROZEN, легаси — **не трогаем** (W2 удалит) |
| `src/services/auto-lyrics.service.ts` | 2 152 | сервис-монолит |
| `src/services/__tests__/auto-lyrics.match.test.ts` | 1 940 | тест-монолит |
| `src/takes/components/TakesPanel.tsx` | 1 557 | UI-монолит |

**Диагноз, который важнее цифр.** Одиннадцать больших файлов — это не «много кода». Это **одиннадцать мест, где нет границы**. В файле на 1 500 строк любая правка касается всего, потому что всё в одной области видимости. Отсюда же 307 ошибок типов: компилятор видит один большой мусорный контекст, а не набор маленьких проверяемых.

**Почему это W5, а не раньше.** Декомпозиция без быстрых типов — это распиливание вслепую. [ADR-0001](./ADR-0001-legacy-isolation-project-references.md)–[0003](./ADR-0003-typed-global-contracts.md) дают рентген, [ADR-0005](./ADR-0005-toolchain-upgrade-path.md) (TS 7) — быстрый фидбек. Только потом нож.

## Решение

### Принцип

> **Не «переписать всё». Разбивать по домену — и только то, что уже трогаешь.**

### 1. Сторы: агрегаты по доменам

Из 43 файлов, импортирующих zustand, собрать **агрегаты** — по одному на домен:

| Агрегат | Что входит |
|---|---|
| `audio` | транспорт, стемы, громкости, BPM, петля |
| `takes` | запись дублей, список, состояние рекордера |
| `sync` | позиция, маркеры, рассинхрон |
| `lyrics` | текст, тайминги, подсветка |
| `ui` | панели, доки, модалки, тема |
| `session` | пользователь, трек, шоу |

**Правило доступа:** компонент подписывается **на агрегат домена**, а не на десять мелких сторов. Внутри агрегата — слайсы, снаружи — один фасад.

**Запрещается:** стор A подписывается на стор B напрямую. Междоменные связи идут через шину событий (`src/foundation/event-bus`), которая уже есть и типизирована.

### 2. God-файлы: «тронул — разбери»

**Не выделять спринт на декомпозицию.** Это ловушка: такой спринт никогда не наступит.

Правило вместо него:
- приходит задача меняет файл из списка → **в рамках той же задачи** выносится хотя бы один логический блок;
- новый файл получает имя по извлечённой ответственности;
- если вынос не укладывается в задачу — файл **не трогается** (лучше оставить как есть, чем разбивать второпях).

Так файлы уменьшаются **побочно**, без отдельного проекта и без риска «большого рефакторинга, который не закончили».

### 3. Порядок разбора (по отдаче на усилие)

| Приоритет | Файл | Почему первым |
|---|---|---|
| 1 | `TakesControlStrip.tsx` (918) | **9 ошибок tsc** — разбор сразу улучшает счётчик |
| 2 | `auto-lyrics.service.ts` (2 152) | крупнейший живой монолит, активно меняется |
| 3 | `TakesPanel.tsx` (1 557) | UI-монолит, ясные границы (список / контролы / превью) |
| 4 | `upload.service.ts` (1 228) | изолируемый пайплайн, легко тестировать |
| — | `AudioEngineV2.ts` | 🔒 **исключён** — удалится в W2, разбирать бессмысленно |
| — | `main.tsx` (900) | точка сборки; разберётся сам после [ADR-0003](./ADR-0003-typed-global-contracts.md) |

### 4. Порог в CI

```yaml
# Новый файл >600 строк — предупреждение; >880 — красный
```

Цель — не запретить большие файлы, а **заметить новый** до того, как он станет вторым `TakesPanel`.

## Почему не другие варианты

| Вариант | Почему нет |
|---|---|
| Выделить спринт «разобрать 11 файлов» | Такой спринт не наступит: всегда есть фичи поважнее. Правило «тронул — разбери» работает всегда |
| Перейти на Redux / MobX / Signals | Смена парадигмы состояния в проекте с 43 сторами — это переписывание, а не рефакторинг. Zustand 5 актуален и не является проблемой |
| Один глобальный стор на всё | Хуже текущего: один God-объект вместо расслоения |
| Оставить как есть, «работает же» | Работает, но каждая правка в TakesPanel (1 557) — это риск. И 9 ошибок tsc там не вычистить, не разобрав файл |
| Разбирать `main.tsx` первым | Он станет меньше сам, когда глобалы станут типизированными ([ADR-0003](./ADR-0003-typed-global-contracts.md)). Разбирать сейчас — дважды |

## Последствия

**Плюсы**
- Компонент видит **один** агрегат вместо десяти сторов → меньше перекрёстных подписок и ререндеров.
- God-файлы уменьшаются **без отдельного проекта** — побочно, в обычной работе.
- Каждый агрегат можно тестировать изолированно → растёт покрытие ([ADR-0009](./ADR-0009-testing-strategy.md)).
- Порог в CI не даёт появиться **новым** монолитам.

**Минусы / чем платим**
- **Долго.** Это недели, растянутые на месяцы. Компенсация: улучшения накапливаются постепенно, ничего не блокируется.
- **Перекрёстные подписки уже существуют**, и их распутывание — риск регресса. Компенсация: один агрегат за PR, с прогоном аудио-пути.
- **Риск рассогласования во время перехода**: часть кода на старых сторах, часть на агрегатах. Компенсация: агрегат — фасад над существующими сторами, а не замена. Старый API может жить до полного перевода.
- Порог в 880 строк может ложно сработать на тестах и сгенерированных файлах. Компенсация: белый список в проверке.

## План внедрения

| Шаг | Действие | Критерий |
|---|---|---|
| 1 | Описать границы 6 агрегатов, зафиксировать в `docs/architecture/` | документ есть |
| 2 | Первый агрегат (`takes`) как пилот | компоненты читают через него |
| 3 | Остальные агрегаты — по одному PR | по одному на PR |
| 4 | Правило «тронул — разбери» в CODEOWNERS-чеклист ревью | применяется |
| 5 | Порог строк в CI | гейт зелёный |
| 6 | `TakesControlStrip.tsx` — разбор | 9 ошибок tsc ушли |

**Откат:** агрегат — фасад, поэтому откат = вернуть импорт старого стора. Код не переписывается целиком.

## Критерий успеха (DoD W5)

- [ ] 6 доменных агрегатов, компоненты читают через них
- [ ] Ни один стор не подписывается на другой стор напрямую
- [ ] Ни одного **нового** файла >880 строк
- [ ] `TakesControlStrip.tsx`, `auto-lyrics.service.ts`, `TakesPanel.tsx` — разобраны
- [ ] `tsc --noEmit` = 0 удержан

> **Главный критерий не в цифрах, а в ощущении:** правка в takes не должна требовать чтения 1 557 строк.
