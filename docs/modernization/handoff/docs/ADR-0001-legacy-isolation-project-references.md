# ADR-0001 · Изоляция FROZEN-легаси: `exclude` не работает, цель W1 = 7, а не 0

**Статус:** **пересмотрен** · **Дата:** 2026-08-29 (оригинал — 2026-08-29) · **Волна:** W1 (Z1)
**Связано:** [ADR-0004](./ADR-0004-v2-legacy-removal-sequence.md), [ADR-0015](./ADR-0015-frozen-zone-policy.md), [01-BASELINE §3](./01-BASELINE.md)

---

> ## ⚠️ Исправление первоначального решения
>
> **Оригинальный ADR предлагал:** исключить FROZEN-файлы через `exclude` в `tsconfig.json` и получить 307 → **300**.
>
> **Проверка показала, что это не работает.** Запуск `tsc -p` с конфигом, исключающим все четыре легаси-пути, дал **всё те же 307 ошибок**, а `src/audio/core/AudioEngineV2.ts` **продолжил компилироваться**:
>
> ```
> $ tsc --noEmit -p <config with exclude>   →   307 ошибок   (ожидалось 300)
> $ ... | grep AudioEngineV2.ts             →   файл в графе компиляции
> ```
>
> **Причина:** `exclude` фильтрует только `include`-глоб, но файл попадает в компиляцию, если его **статически импортирует** кто-то из включённых. Граф такой:
>
> ```
> src/App.tsx
>   └─ import { tryActivateV2 } from './audio/featureFlag'
>        └─ import { patchV1WithV2 } from './compat/patchV1'      ← FROZEN
>             └─ import { AudioEngineV2 } from '../core/AudioEngineV2'  ← FROZEN, 7 ошибок
> ```
>
> Исключение нижних узлов не помогает: их вытягивает транзитивный импорт сверху.
>
> Ниже — пересмотренное решение на основе этого факта.

---

## Контекст

`tsc --noEmit` даёт **307 ошибок** при уже включённых `strict: true`, `noUnusedLocals`, `noUnusedParameters`.

**7 из них — в FROZEN-файле `src/audio/core/AudioEngineV2.ts`:**

```
6 × TS6133 — объявлено, но не используется
    (BUILTIN_STEMS, _LOOP_RESYNC_BLACKOUT_MS, _SYNC_BLACKOUT_FLOOR, opts, id, _micCaptureEnabled)
1 × TS2345 — Float32Array<ArrayBufferLike> несовместим с Float32Array<ArrayBuffer>
```

Ошибка TS2345 не наша: она прилетела из TypeScript 5.7+, сделавшего `TypedArray` дженериком по backing buffer. **Апгрейд компилятора уже добавил ошибку в файл, который править нельзя** ([ADR-0005](./ADR-0005-toolchain-upgrade-path.md)).

**Жёсткий факт:** пока FROZEN-файл связан статическим импортом с остальным кодом, **`tsc --noEmit` = 0 недостижим**. «Канон 296» — не цель, а пол, заданный замороженным легаси.

**Граница минимальна.** Вся замороженная связка держится на **одном** импорте:

| Файл | Статус | Роль |
|---|---|---|
| `src/App.tsx` | 🔶 в активной работе Никиты | единственная точка входа в связку |
| `src/audio/featureFlag.ts` | свободен | тонкая обёртка, ~30 строк |
| `src/audio/compat/patchV1.ts` | 🔒 FROZEN | патчит V1 поверх V2 |
| `src/audio/core/AudioEngineV2.ts` | 🔒 FROZEN | 2 178 LOC, **7 ошибок** |

---

## Решение

### Принцип

> **Не ломать рантайм ради счётчика.**
> `tryActivateV2()` вызывается при старте приложения и патчит живой аудио-движок. Менять механику загрузки V2 посреди активной работы над V3-транспортом — недопустимый риск.

### Основное решение: **цель W1 = 7, а не 0**

1. **Признать пол.** 7 ошибок FROZEN — это не долг, а **константа**, пока жив V2. Формулировка «ноль ошибок» заменяется на «ноль ошибок **вне FROZEN**».
2. **Храповик считает до 7.** В `.ci-baseline/tsc` пишется 307; гейт краснеет при росте. Итог W1 — **7**, и это полная победа: весь код, который мы имеем право править, чист.
3. **Ноль достигается в W2** — когда [ADR-0004](./ADR-0004-v2-legacy-removal-sequence.md) удалит V2-движок. В этот момент 7 ошибок исчезают **физически**, вместе с файлом. Без обходных путей, без `@ts-ignore`, без ослабления строгости.
4. **Легаси считается отдельно.** Информационный шаг `typecheck:legacy` (`continue-on-error`) показывает счётчик по FROZEN, чтобы деградация была видна.

**Почему это правильно, а не «сдача позиций».** Цель «ноль» недостижима без правки FROZEN или без изменения рантайма. Цель «7» достижима, проверяема и **честна**: она означает ровно то, что означает. А ноль мы получим штатно, удалив то, что и так собирались удалить.

### Альтернатива (если Никит захочет ноль до W2): разрыв статического импорта

Требует правки `src/audio/featureFlag.ts` и, скорее всего, `src/App.tsx`:

```ts
// featureFlag.ts — V2 подгружается лениво, статической связи нет
export async function tryActivateV2(): Promise<boolean> {
  const { patchV1WithV2 } = await import('./compat/patchV1');
  ...
}
```

**Последствия:**
- `tryActivateV2` становится асинхронной → меняется место вызова в `App.tsx`;
- меняется **момент** патча аудио-движка → окно, в котором `window.audioEngine` ещё V1;
- `App.tsx` **в активной работе Никиты** — правка конфликтует.

**Вердикт: не делать сейчас.** Зафиксировать как опцию на W2, когда V2 и так будут удалять и момент активации всё равно поменяется.

### Отклонённые варианты

| Вариант | Почему нет |
|---|---|
| `exclude` в `tsconfig.json` | ❌ **опровергнуто запуском**: файл всё равно в графе через транзитивный импорт |
| `tsconfig.legacy.json` + `references` | Та же проблема: граф тянет файл в основной юнит. Плюс `composite` конфликтует с `noEmit` |
| `paths`-маппинг на стаб-типы | `paths` не применяется к относительным спецификаторам (`'../core/AudioEngineV2'`) |
| Починить 7 ошибок в FROZEN | Требует OVERRIDE, нарушает смысл заморозки ([ADR-0015](./ADR-0015-frozen-zone-policy.md)) |
| `@ts-nocheck` в файл | Правка файла; снимает все проверки с 2 178 строк живого аудио-движка |
| Выключить `noUnusedLocals` глобально | Снимет 119 ошибок ценой потери проверки для всего проекта |

## Последствия

**Плюсы**
- Формулировка цели **достижима и проверяема**: 300 ошибок, которые мы можем исправить, → 0; 7, которые не можем, → ждут W2.
- **Ни одного изменения в рантайме.** Аудио не трогается во время активной работы над V3.
- FROZEN-файлы не изменены — заморозка соблюдена буквально.
- Легаси становится **видимо изолированным**: его счётчик ведётся отдельно и не маскируется общим числом.
- Никаких ослаблений строгости: `strict`, `noUnusedLocals`, `noUnusedParameters` остаются включёнными для всех 546 файлов.

**Минусы / чем платим**
- **«Ноль ошибок» недостижим до W2.** Это нужно явно проговорить с командой, иначе цифра 7 будет выглядеть как провал MISSION ZERO.
- Риск «расслабленного кармана»: соблазн списывать на FROZEN чужие ошибки. Компенсация: FROZEN-счётчик ведётся отдельно и **фиксирован** (7). Любое изменение этого числа — сигнал.
- Зависимость от W2: если удаление V2 затянется, число 7 задержится тоже. Компенсация: [ADR-0004](./ADR-0004-v2-legacy-removal-sequence.md) уже в плане.

## План внедрения

| Шаг | Действие | Проверка |
|---|---|---|
| 1 | Зафиксировать `.ci-baseline/tsc` = **307** | файл есть |
| 2 | Храповик в CI ([ADR-0013](./ADR-0013-ci-gate-architecture.md)): красный при росте | гейт работает |
| 3 | Чистить 300 ошибок (не FROZEN) по кластерам | счётчик убывает |
| 4 | Информационный шаг `typecheck:legacy` для FROZEN | счётчик FROZEN = 7, виден |
| 5 | **Конец W1: 307 → 7** | ✅ MISSION ZERO выполнена |
| 6 | **W2:** удаление V2 → **7 → 0** | `tsconfig.legacy.json` удаляется |

**Откат:** этот ADR **не требует изменений в коде** — только конфиги и порог в CI. Откат = вернуть baseline.

## Критерий успеха (DoD W1)

- [ ] `tsc --noEmit` = **7** (было 307)
- [ ] Все 7 — только в `src/audio/core/AudioEngineV2.ts`, и это подтверждено запуском
- [ ] `git diff --stat` по FROZEN-файлам → **пусто**
- [ ] `strict`, `noUnusedLocals`, `noUnusedParameters` по-прежнему включены
- [ ] CI: храповик по основному счётчику + информационный счётчик FROZEN

> **Главное:** критерий успеха — не «ноль любой ценой», а **«ноль там, где мы имеем право править, и честно названный остаток там, где не имеем»**.
