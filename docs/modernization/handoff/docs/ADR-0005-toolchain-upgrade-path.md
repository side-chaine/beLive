# ADR-0005 · Путь апгрейда тулчейна: один мажор на PR, чистка манифеста — первой

**Статус:** proposed · **Дата:** 2026-08-29 · **Волна:** W4 (после W1)
**Связано:** [ADR-0012](./ADR-0012-dependency-manifest-policy.md), [ADR-0010](./ADR-0010-dev-environment-and-node-modules-integrity.md), [01-BASELINE §5](./01-BASELINE.md)

---

## Контекст

`npm outdated` на 2026-08-29: **61** устаревший пакет. Но это число **врёт**.

Разбор ([01-BASELINE §5.2](./01-BASELINE.md)) показывает, что из 61 пакета **36 — транзитив**, попавший в `devDependencies` (см. [ADR-0012](./ADR-0012-dependency-manifest-policy.md)). Реальный долг:

| Метрика | Как выглядит | На самом деле |
|---|---|---|
| Устаревших пакетов | 61 | 25 |
| Отставаний на мажор | 44 | **7** |

**Семь реальных мажоров:**

| Пакет | Здесь | Latest | Что меняется |
|---|---|---|---|
| typescript | 5.9.3 | **7.0.2** | **Go-нативный компилятор.** GA 2026-07-08. Заявлено ~10× ускорение |
| vite | 5.4.21 | **8.2.2** | **Rolldown вместо esbuild+Rollup.** 8.0 stable — 2026-03-12 |
| jsdom | 28.1.0 | **30.0.1** | 2 мажора, среда тестов |
| globals | 14.0.0 | **17.11.0** | 3 мажора, список глобалок для eslint |
| vite-plugin-pwa | 0.20.5 | **1.3.0** | выход из 0.x, смена API |
| vite-tsconfig-paths | 5.1.4 | **6.1.1** | мажор |
| @testing-library/jest-dom | 6.9.1 | **7.0.1** | мажор |

### Два факта, которые определяют порядок

**1. Rolldown уже здесь.** `vitest@4` использует Rolldown. Именно поэтому `npm run test` падает на Windows с `Cannot find module './rolldown-binding.win32-x64-msvc.node'`. Апгрейд среды ([ADR-0010](./ADR-0010-dev-environment-and-node-modules-integrity.md)) — не «подготовка к Vite 8», а **починка того, от чего текущий тестовый тулчейн уже зависит**.

**2. TypeScript уже нам навредил.** Ошибка TS2345 в FROZEN-файле `AudioEngineV2.ts` (`Float32Array<ArrayBufferLike>`) прилетела из TS 5.7+, сделавшего `TypedArray` дженериком. Апгрейд компилятора **уже добавил ошибок** в файл, который править нельзя. Каждый следующий мажор сделает это снова.

---

## Решение

### Принцип

> **Один мажор — один PR. Никаких «обновим всё сразу».**
> И **сначала** чистим манифест, **потом** обновляем.

### Порядок (строгий)

```
ADR-0012: чистка devDependencies (86 → ~23)
        │
        ▼
   TS 5.9 → 6       ← каждый шаг: отдельный PR, полный прогон канона
        │
   TS 6 → 7         ← нативный компилятор; гейт ускоряется ~10×
        │
   Vite 5 → 6
        │
   Vite 6 → 7
        │
   Vite 7 → 8       ← Rolldown; требует исправных нативных бинарей (ADR-0010)
        │
   vite-plugin-pwa 0.20 → 1.x
   vite-tsconfig-paths 5 → 6
   jsdom 28 → 29 → 30
   globals 14 → 17
   @testing-library/jest-dom 6 → 7
```

**Почему TS раньше Vite.** TS-гейт — самый частый фидбек-луп. Его ускорение (~10×) окупается немедленно и ускоряет все последующие волны: W5 (декомпозиция god-файлов) без быстрого type-фидбека мучительна.

**Почему чистка манифеста первой.** Обновлять 36 пакетов, которых не должно быть в манифесте — это две трети работы впустую. После чистки [ADR-0012](./ADR-0012-dependency-manifest-policy.md) список «44 мажора» схлопывается до 7.

### Правило для каждого PR

| Требование | Зачем |
|---|---|
| Один мажор, один PR | Если сломается — понятно, что именно |
| Полный прогон канона: `typecheck` + `test` + `build` | Ловим регресс |
| Счётчик `tsc` **не вырос** | Главная метрика. Если вырос — разобрать до мержа |
| FROZEN-файлы не изменены | [ADR-0015](./ADR-0015-frozen-zone-policy.md) |
| Скриншот/снапшот аудио-пути | Аудио — зона, где типы не помогут |

### Отдельное правило для TypeScript

Новые ошибки от нового компилятора **не заморачиваются в бюджет**. Если TS 7 вскрывает ошибки в FROZEN — это повод для [ADR-0015](./ADR-0015-frozen-zone-policy.md) (пересмотр заморозки), а не для `@ts-ignore`.

## Почему не другие варианты

| Вариант | Почему нет |
|---|---|
| Обновить всё за один PR | Неотлаживаемо. При поломке непонятно, кто виноват из семи |
| Обновить сразу до latest (`npm update --latest`) | Перескакивает через миграционные гайды; ломает API без предупреждения |
| Оставить как есть | TS 5.9 уже не получает новых проверок; каждый месяц разрыв растёт, цена миграции — тоже |
| Сначала Vite 8, потом TS | Vite 8 меняет бандлинг (риск для прода), TS — только проверку (риск нулевой). Дешёвое — первым |
| Перейти на Bun/Deno вместо апгрейда | Смена рантайма — это отдельная программа на месяцы, а не апгрейд тулчейна |

## Последствия

**Плюсы**
- Type-гейт ускоряется ~10× → быстрый фидбек для W5.
- Vite 8 убирает двойной бандлер (esbuild + Rollup) → одна модель, меньше расхождений dev/prod.
- Сборка ускоряется (заявлено 10–30× на продакшен-билдах).
- К концу W4 — ноль критических отставаний.

**Минусы / чем платим**
- **~11 PR только на тулчейн.** Это много. Компенсация: они независимы от фич, их можно делать параллельно с W5.
- **TS 7 может вскрыть новые ошибки.** Нативный порт — не баг-в-баг совместимость. Компенсация: апгрейд **после** W1, когда счётчик уже 0 — новые ошибки видны сразу, их не маскируетExisting долг.
- **Vite 8 ломает плагины.** `vite-plugin-pwa` и `vite-tsconfig-paths` должны быть обновлены **до или вместе**. Компенсация: они идут в конце цепочки, когда Vite уже на 8.
- **Rolldown требует нативных бинарей.** Прямая зависимость от [ADR-0010](./ADR-0010-dev-environment-and-node-modules-integrity.md): без W−1 Vite 8 не запустится.

## План внедрения

| Шаг | Действие | Критерий |
|---|---|---|
| 0 | **[ADR-0012]** Почистить `devDependencies` | `npm outdated` показывает ≤25, мажоров ≤7 |
| 0.5 | **[ADR-0010]** `npm ci`, проверка нативных бинарей | `npm run test` запускается |
| 1 | TS 5.9 → 6 | `tsc` = 0, тесты зелёные |
| 2 | TS 6 → 7 | `tsc` = 0, гейт ускорился, замерить время |
| 3 | Vite 5 → 6 | `npm run build` собирает, PWA работает |
| 4 | Vite 6 → 7 | то же |
| 5 | Vite 7 → 8 | то же + Rolldown-бинари на месте |
| 6 | Остальные 4 пакета | `npm outdated` → 0 мажоров |

**Откат:** каждый PR откатывается отдельно (`git revert`). Lockfile в git — откат восстанавливает точные версии.

---

## Критерий успеха (DoD W4)

- [ ] TypeScript **7.x**, Vite **8.x**
- [ ] `npm outdated` → **0** пакетов с мажорным отставанием
- [ ] `npm audit` → 0 critical
- [ ] `tsc --noEmit` = **0** (удержан после апгрейда)
- [ ] Время type-гейта замерено и записано в REGISTRY (ожидается ~1–2 с вместо ~15 с)

> **Самая важная строка DoD — последняя.** Если после TS 7 гейт не ускорился, значит что-то пошло не так, и это надо разобрать, а не принять.
