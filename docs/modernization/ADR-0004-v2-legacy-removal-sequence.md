# ADR-0004 · Последовательность вывода V2-легаси (цель «ноль легаси»)

**Статус:** proposed · **Дата:** 2026-08-29 · **Волна:** W2 · **Длительность:** 3–4 недели
**Связано:** [ADR-0001](./ADR-0001-legacy-isolation-project-references.md), [ADR-0003](./ADR-0003-typed-global-contracts.md), `DECISION-LOG.md` D-6

---

## Контекст

### Что осталось от V2 — и это меньше, чем кажется

| Артефакт | Объём | Статус |
|---|---|---|
| `src/audio/core/AudioEngineV2.ts` | 2 178 LOC | 🔒 FROZEN, 7 вечных ошибок |
| `src/audio/compat/patchV1.ts` | — | 🔒 FROZEN, 2 импортёра |
| `src/services/track.orchestrator.ts` | — | 🔒 FROZEN |
| `src/bridges/` | **1 файл** (`live-guard.ts`) | было 22 — миграция почти завершена 🟢 |
| `V2Adapter` и его цепочка | 4 точки | `DuckGuardV3`, `V2AudioCage`, `V2ResurrectionDetector`, экспорт в `engine-v3/index.ts:59` |
| `js/` — глобальные скрипты v1-эпохи | 1 832 LOC | `audio-engine.js` (стаб, **не загружается**), `audio-facade-v3.js`, `marker-manager.js`, `monitor-mix.js`, `lyrics-display.js`, `track-catalog.js` |

**Ключевая пропорция:** `src/audio/engine-v3/` = **6 505 LOC** против `src/audio/core/` = **2 732 LOC**. V3 уже в 2.4 раза больше легаси. **V2 — не материк, а остров**, и он shrinking.

**Поверхность связности крошечная.** `AudioEngineV2` упоминается всего в **7 файлах**, из них:
- 2 —他自己 и `patchV1.ts` (FROZEN),
- 2 — вероятно type-only (`IV2PublicContract.ts`, `stemTypes.ts`),
- **3 реальных потребителя**: `components/MixerPanel.tsx`, `foundation/event-bus/wrappers/position-sync.ts`, `audio/engine-v3/integration/V3DataInterceptor.ts`.

### Предохранители — это тоже легаси

`V2AudioCage`, `V2ResurrectionDetector`, `DuckGuardV3` существуют **только потому, что V2 может воскреснуть**. Они — страховка миграции. Как только V2 исчезает, все три превращаются в мертвый груз, который надо удалить — но удалять их **раньше** времени нельзя, это и есть R2-риск.

### Уже принятое решение

`DECISION-LOG.md`, запись **D-6** (2026-08-06):

> `V2_EVENTUAL_REMOVAL = CONFIRMED_GOAL` · scope M8-ONLY · frozen_edits_M0_M7 = FORBIDDEN · каждый блок M8 = отдельный OVERRIDE · **`AudioEngineV2.ts` удаляется последним** · `V2AudioCage` живёт до финального шага · вход в M8 только при **Gate2 COMPLETE + Gate3B/4a закрыты + P1-d стабилен**.

Этот ADR **не заменяет** D-6, а раскладывает его на выполнимые шаги с зависимостями.

---

## Решение

Восемь шагов, **строго в этом порядке**. Каждый — отдельный PR, каждый обратим.

### Предусловия (не начинать без них)

- [ ] W1 завершена: `tsc --noEmit` = **0**, `resolveTransport()` (ADR-0003) принят всеми потребителями
- [ ] V3 стабилен **≥ 2 спринта** без fallback'ов на V2
- [ ] Gate2 COMPLETE, Gate3B/4a закрыты, P1-d стабилен (условие D-6)

### Шаг 1 · Снять инструментацию No-Birth

Убрать `__v2BirthCount` (`App.tsx:92-94`) и связанные проверки.
**Почему первым:** это счётчик, который доказывает, что V2 не рождается. Когда доказательство получено и зафиксировано в реестре, счётчик больше не нужен. Нулевой риск.

### Шаг 2 · Отвязать 3 реальных потребителя от `AudioEngineV2`

| Файл | Что делаем |
|---|---|
| `components/MixerPanel.tsx` | перевести на `resolveTransport()` (ADR-0003) |
| `foundation/event-bus/wrappers/position-sync.ts` | то же; проверить, что подписка на `currentTime` идёт через EventBus, а не через движок |
| `engine-v3/integration/V3DataInterceptor.ts` | убрать чтение V2-полей, брать данные из `pipeline` |

**Почему до удаления адаптера:** пока кто-то читает V2 напрямую, адаптер нельзя трогать.

### Шаг 3 · Вывести `V2Adapter` из публичного API

Убрать `export { V2Adapter } from './V2Adapter'` (`engine-v3/index.ts:59`). Оставить сам класс — он ещё нужен внутренним предохранителям.

### Шаг 4 · Снять `DuckGuardV3`

`DuckGuardV3` импортирует **только** `V2Adapter` и не имеет другого источника. После шагов 2–3 он либо переезжает на V3-API, либо удаляется.

### Шаг 5 · Снять `V2AudioCage`

**По D-6: живёт до финального шага.** Это последний рубеж, который не даёт V2 зазвучать параллельно с V3. Снимается, когда шаги 1–4 отработали в проде без инцидентов.

### Шаг 6 · Убрать `patchV1` (2 импортёра)

🔒 FROZEN → нужен OVERRIDE. Фактически — удаление файла, а не правка.

### Шаг 7 · Перевести `js/`-слой на контракты

`marker-manager.js:82` и `monitor-mix.js:1217` читают `window.audioEngine`. Перевести их на тот же контракт, что и Rehearsal.
**После этого** `js/audio-facade-v3.js` теряет последних потребителей и удаляется, а `js/audio-engine.js` (стаб, который и так никто не грузит) — тем более.

### Шаг 8 · Удалить `AudioEngineV2.ts` и `src/audio/core/`

🔒 Финальный OVERRIDE. **По D-6 — последним.** Вместе с ним удаляются `tsconfig.legacy.json` (ADR-0001) и понятие FROZEN для этого файла.

### Шаг 9 · Снять флаг `VITE_ENGINE`

`App.tsx:90`, `ControlDeck.tsx` (×2), `VolumeControls.tsx` (×2), `recording.store.ts:48`, `TakesControlStrip.tsx` (×2), `takes.recorder.ts:66` — 9 мест с `import.meta.env.VITE_ENGINE ?? 'v2'`.
Дефолт `'v2'` меняется на `'v3'`, ветки `engineMode !== 'v3'` удаляются.

## Последствия

**Плюсы**
- Цель «ноль легаси» достигнута: в V3-рантайме не существует ни одного V2-объекта.
- −3 файла предохранителей, −1 832 LOC `js/`-глобалок, −2 732 LOC `audio/core`.
- Исчезает **двойная реальность**: сейчас любой участок кода может неявно работать с тем или другим движком.
- Пропадает необходимость держать FROZEN-зону для V2 → ADR-0001 остаётся только для `track.orchestrator.ts` и `bridges/`.

**Минусы / чем платим**
- **Пути отката нет.** После шага 8 вернуться к V2 можно только из git-истории. Компенсация: шаг 8 — последний, после него уже ≥ 2 спринтов стабильности.
- **Sha-канон собьётся.** Любой SHA-канон из `DECISION-LOG` D-13 (физический SHA+размер), относящийся к V2-файлам, станет неактуальным. Требуется переутверждение канона.
- **Диагностика миграции теряет объект.** `V2ResurrectionDetector` после шага 5 нечего детектить. Это хорошая новость, но значит — все доказательства миграции должны быть собраны **до** шага 5.
- **9 мест с `VITE_ENGINE`** — легко пропустить одно. Компенсация: финальный grep-гейт в CI.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Удалить V2 одним большим PR | 2 178 LOC + предохранители + 9 флагов. При любой регрессии непонятно, что именно сломалось |
| Оставить V2 «на всякий случай», просто не грузить | Тогда остаётся FROZEN-зона, остаются 7 вечных ошибок, остаётся соблазн fallback'а. Это не «ноль легаси» |
| Сначала удалить предохранители, потом движок | Прямое нарушение D-6 и здравого смысла: без страховки первая же регрессия V3 не будет замечена |
| Переписать `js/`-слой на TS сразу | Объём ~1 832 LOC + ворклеты; это отдельный проект W5, не блокер для удаления V2 |
| Оставить `audio-facade-v3.js` как «совместимость для внешних интеграций» | Внешних потребителей нет; фасад существует только для внутреннего `js/`-слоя |

```
grep -rIn "AudioEngineV2\|patchV1\|V2Adapter\|V2AudioCage\|V2Resurrection" src/  → пусто
grep -rIn "VITE_ENGINE" src/                                                    → пусто
ls src/audio/core                                                               → нет такого
ls src/bridges                                                                  → пусто (или только live-guard по решению)
```
