### ⚠️ Главная находка: 9 скриптов с CDN без SRI

```html
<script src="https://cdn.jsdelivr.net/npm/@mediapipe/camera_utils/camera_utils.js"
        crossorigin="anonymous"></script>
```

`crossorigin="anonymous"` есть, **`integrity=` нет**. Это критично: атрибут `crossorigin` подготовил запрос к проверке, но проверка **отсутствует**. Любая подмена содержимого на CDN (или на пути до него) исполняется с полными правами приложения — с доступом к микрофону, аудио-контексту и сессии пользователя.

**Это единственная находка во всём аудите, которая закрывается за один вечер и не требует архитектурных решений.** Всё остальное (CSP) — длинная игра, SRI — нет.

### Почему строгий CSP сейчас невозможен

| Блокер | Шт | Что требует |
|---|---|---|
| Инлайн-скрипты | 6 | nonce или вынос в файлы |
| Инлайн-стили | 4 | nonce или вынос в файлы |
| Blob-реалмы | 22 | [ADR-0002](./ADR-0002-worklet-realm-extraction.md) — вынос ворклетов в статические файлы |
| `unsafe-eval` | — | уйдёт вместе с Blob |

Включить CSP сегодня = либо оставить `unsafe-inline` и `unsafe-eval` (тогда CSP декоративный), либо сломать приложение. **Порядок имеет значение.**

## Решение

### 1. ✅ SRI на все 9 CDN-скриптов — немедленно, отдельным PR

```html
<script src="https://cdn.jsdelivr.net/npm/@mediapipe/camera_utils/camera_utils.js"
        integrity="sha384-<hash>"
        crossorigin="anonymous"></script>
```

Хэш считается один раз:
```bash
curl -s <url> | openssl dgst -sha384 -binary | openssl base64 -A
```

**Почему первым:** не зависит ни от чего, не ломает ничего, закрывает реальную дыру. Вернуть `jsdelivr` умеет отдавать SRI сразу — можно взять готовые хэши с их страницы пакета.

**Важно зафиксировать версии.** Сейчас скрипты подключены **без версии** (`@mediapipe/camera_utils/camera_utils.js`), то есть CDN отдаёт «последнюю». Это означает:
- содержимое может измениться в любой момент → SRI внезапно станет невалидным → приложение сломается;
- невозможно воспроизвести состояние месячной давности.

**Поэтому одновременно с SRI — пиним версии.** SRI без пина = бомба с часовым механизмом.

### 2. CSP — после подготовки, в три шага

**Шаг A (W1/W2).** [ADR-0002](./ADR-0002-worklet-realm-extraction.md) убирает Blob-реалмы → отпадает необходимость в `unsafe-eval`.

**Шаг B (W3.1).** Вынести 6 инлайн-скриптов и 4 инлайн-стиля в файлы. Для того, что нельзя вынести (critical CSS, бут-тема) — **nonce**, генерируемый на сборке.

**Шаг C.** Включить политику:
```
default-src 'self';
script-src 'self' https://cdn.jsdelivr.net;
style-src 'self' 'nonce-<random>';
connect-src 'self' wss://belive-rehearsal.nikitosss007.workers.dev;
media-src 'self' blob:;
worker-src 'self';
object-src 'none';
base-uri 'none';
```

**Порядок обязателен.** `unsafe-eval` исчезает только после A; `unsafe-inline` — только после B.

### 3. `media-src blob:` — осознанное исключение

Аудио-приложение неизбежно работает с `blob:` URL для медиа (загруженные треки, записи дублей). Это нормально и не является уязвимостью, если `script-src` не содержит `blob:`. **Разделять эти две директивы обязательно** — именно их путаница создаёт дыру.

### 4. Регулярная проверка

```yaml
- name: Security baseline
  run: |
    node scripts/check-sri.mjs        # каждый CDN-скрипт имеет integrity + закреплённую версию
    npm audit --audit-level=critical  # ноль критических
```

## Почему не другие варианты

| Вариант | Почему нет |
|---|---|
| Включить строгий CSP прямо сейчас | Сломает приложение (6 инлайн-скриптов, Blob-реалмы) либо окажется декоративным с `unsafe-*` |
| Ограничиться `unsafe-inline`, «это же наш код» | CSP без защиты от XSS — это потраченное время. Весь смысл в запрете инлайна |
| Убрать MediaPipe с CDN, завендорить локально | Правильно в долгую (и снимет зависимость от доступности CDN), но это тестовый объём: MediaPipe — тяжёлый. Рассмотреть после SRI |
| SRI без закрепления версий | Приложение сломается при обновлении файла на CDN — и именно в тот момент, когда это будет некогда чинить (на выступлении) |
| Отложить и SRI | Единственный пункт этой программы, где цена — один вечер, а выгода — закрытая дверь |

## Последствия

**Плюсы**
- SRI + пины: подмена CDN перестаёт исполняться; сборка становится воспроизводимой.
- CSP после шагов A–B: защита от XSS и инъекций, без `unsafe-eval`.
- `npm audit` в CI: критические уязвимости не проезжают в прод.
- `base-uri 'none'` и `object-src 'none'` — дешёвая защита от целого класса атак.

**Минусы / чем платим**
- **Пины версий = ручные обновления.** CDN-пакеты больше не обновятся сами. Компенсация: это *преимущество* для аудио-продукта — предсказуемость важнее свежести.
- **Инлайн-стили критического CSS с nonce** усложняют сборку. Компенсация: nonce генерируется в `vite.config.ts`, а не вручную.
- **CSP ломает第三方 интеграции.** Любой новый CDN/виджет потребует правки политики. Компенсация: это и есть точка контроля — новые источники видны в diff политики.
- `npm audit` может быть красным от транзитивных уязвимостей, которые нечем лечить. Компенсация: гейт только на `critical`, остальное — отчёт.
