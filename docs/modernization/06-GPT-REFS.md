## 1. 🔥 ГЛАВНОЕ: интерактивная доска уже в протоколе

`src/Rehearsal/types/protocol.types.ts`:

```ts
export type TriggerPayload =
  | { type: 'annotation'; points: { x: number; y: number }[]; action: 'draw' | 'clear' }
  | { type: 'focus-change'; target: string };
```

- `annotation` + `draw`/`clear` = **педагог рисует на интерактивной доске**
- `focus-change` = **переключение центральной плашки** (YouTube ⇄ доска ⇄ ноты)

**Босс дословно:** *«первые решения, которые мы будем реализовывать для моста в
репетиции — интерактивная доска… центральная плашка может превращаться и в ютуб
экран, и в интерактивную доску, где педагог что-то может раздавать».*

То есть **то, что Босс назвал первым, уже спроектировано на уровне типов.**

**Но:** `grep -rn "annotation\|focus-change\|TriggerPayload" src/` → **ноль
использований вне файла типов.** Ни отправки, ни приёма.

**Причина видна в `RehearsalTriggerBridge`:**

```ts
private send(payload: ControlPayload) {
  this.pc.controlChannel?.send(JSON.stringify(this.sender.wrap(payload)));
}
```

`PeerConnectionManager` поднимает **два** DataChannel'а — `controlChannel` и
`triggerChannel`. **Пишется только в первый.** Второй — «триггеры как в компьютерной
игре» из нашей северной звезды — провисел мёртвым, потому что триггеров не случилось.

→ **Шаг ③ — это не «строим с нуля», а «дописываем вторую половину».**
→ **Начинать предлагаю с синхронизации плашки, а не с видео:** байты, видно мгновенно,
открывает ровно тот сценарий, который Босс назвал первым.

## 2. Пять багов моста (BRG-1…BRG-5)

| ID | P | Что | Чем грозит |
|---|---|---|---|
| **BRG-1** | 🔴 | `triggerChannel` не пишется; `TriggerPayload` — мёртвый код | Блокер шага ③ |
| **BRG-2** | 🔴 | `hijackAudioTransport()`: `const origPlay = ae.play.bind(ae)` **без guard'а** | `TypeError` в конструкторе, если `ae.play` undefined. В соседнем `playWithWatchdog` guard **есть** — знали, но забыли |
| **BRG-3** | 🟠 | `vclock.anchor(t, ae?.playbackRate ?? 1)` — в V3-фасаде `playbackRate` **нет** → всегда `1` | После смены темпа студент уплывает **линейно**. Убивает Tempo Ladder и питч |
| **BRG-4** | 🟡 | `if (… && ae?.audioContext)` — свойства нет в V3 → кросс-чек `getOutputTimestamp()` мёртв | Диагностика дрифта слепа |
| **BRG-5** | 🟠 | `if (role === 'teacher') this.hijackAudioTransport();` — студент шлёт только `sync-request` | Дельта питча студента не дойдёт до педагога |

### 🔥 Системный корень — просьба к 007

VIS-2 (питч не подключён к V3) и BRG-2/3/4 — **одно заболевание**: код написан под
V2-фасад `window.audioEngine`, а живёт под V3, где он пустышка
(`play/pause/seekTo/setStemVolume` → `undefined`; `playbackRate` и `audioContext`
отсутствуют). Реальный путь V3 — `window.__belive.pipeline` (`HybridPipelineService`).

**Просьба: свести VIS-2 + BRG-2/3/4 в одну инициативу «контракт аудио-фасада».**

## 3. 🎯 Референс не едет по сети — едет только дельта

Босс: *«у нас есть референс (вокальная дорожка), у которого есть свой питч-референс,
и наш мониторинг… подсвечивала косяки и собирала статистику».*

Северная звезда: **материал лежит локально на каждом ПК.** Значит референс у обоих
одинаков и **передавать его не нужно**. Достаточно:

```ts
{ type: 'pitch-delta'; tMs: number; cents: number; confidence: number }
```

20 Гц × 3 числа → **~1.5 КБ/с**. Работает там, где по северной звезде остаётся
«только аудио». Канал есть (BRG-1), типы дописать — полчаса.

**Обязательное условие:** дельта бессмысленна без общего времени. `VirtualClock` /
`DriftCorrector` / `clockOffset` / `rtt` уже есть — но их убивает **BRG-3**.
→ **Порядок: сначала время, потом питч.**

**Просьба к 007 и Sonnet: найти дыры в этой модели.** Мне она кажется слишком
дешёвой, чтобы быть правдой.

## 5. Четыре блока Босса → что это значит в коде

| Сказал Босс | Архитектурно |
|---|---|
| «центральная плашка может превращаться…» | **STAGE-SLOT** — слот с контрактом, не виджет. Провайдеры: `youtube` / `board` / `score` / `stems` / `peer-video`. Переключение = сетевое событие (`focus-change`) |
| «питч-референс и наш мониторинг… косяки… статистика» | Три series с разной судьбой: референс — **офлайн, при импорте**; мониторинг — **AudioWorklet, рантайм**; дельта — **по сети, байты** |
| «штамповать плагины а-ля VST, но своего формата» | Слово «штамповать» = **конвейер**, не один плагин. Формат `BLB-PLUGIN-1`: дескриптор + `processor` (AudioWorklet URL) + декларативный `ui` + **обязательный честный `latency`** |
| «DNA — стартовая страница, при скролле — история, фотки, сервисы» | DNA = **экскурсия по району POWER** (9 внешних станций). Секции независимы: свой загрузчик, скелетон, кэш |

**Жёсткое требование к плагинам:** хост обязан встраиваться в `HybridPipelineService`,
**не** в `window.audioEngine`. Иначе — шестой экземпляр болезни BRG-2/3/4.
И `latency` обязателен: без него мост начнёт врать, и весь `LINE UP` / `Adjust timing` поедет.

## 5bis. 🤖 ИИ-чат переезжает в правую часть — и это СЕРИЯ на Ютуб

**Босс, сразу после референсов:** *«про ИИ чат не рассказал! мы из Док переносим
в правую часть! как на референсе GPT! и это уже будет серия на Ютуб!»*

### Это совпало с измеренным

Правая рейка **x 0.79–0.98**, которую я в F3 ([06][07][08][09][15]) назвал
«панелью статистики» — **это и есть чат**. Скорее всего оба: чат сверху,
статистика под ним (этим объясняется, почему в [07] рейка выросла до 55% высоты).

### Где чат сейчас

```
src/deck/modules.ts
  registerModule({ id: 'billy', label: '🤖', order: 45,
                   modes: ['rehearsal','karaoke','concert','live'],
                   load: () => import('./BillyChatModule') … })

src/components/ControlDeck.module.css
  position: fixed; bottom: 0; left: 0; right: 0;      ← Дек во всю ширину снизу
  height: var(--bl-deck-panel, 240px);                 ← раскрытая панель
```

`src/deck/BillyChatModule.tsx`: *«dock-embedded version of AI Expert Panel»*.

То есть чат сегодня — **одна из семи вкладок в ящике на 240 px**, наравне с
Studio, Quest, Split, Notes, Show, Styles (порядок 25, 28, 29, 35, 38, 40, **45**).

### Три мины при переезде

1. **🐭 Маскот завязан на геометрию.** `ControlDeck.tsx:78`:
   *«НЕ удаляем `--bl-deck-height` — BillyDock зависит от этого значения»*.
   `useBillyZoneCache()` читает «Zone Bounds — реальная геометрия из CSS vars».
   Убрали 240 px снизу, добавили ~320 px справа → **маскот поедет**.
2. **Четыре реализации чата.** `BillyChatModule` (18 стр., активный) ·
   `AIChatPanel` (104 стр., **закомментирован** в `modules.ts`: «v2.0: AI deferred») ·
   `CatalogBillyChat` (151 стр.) · `js/ui/ai-chat-ui.ts` (363 стр., легаси).
   **Переезд = лучший момент свести к одной.**
3. **Рейка делится.** Если справа и чат, и статистика — нужен контейнер с
   секциями, а не два блока, дерущихся за место. То же решение, что STAGE-SLOT:
   слот с контрактом. Называется **RIGHT-RAIL**.

### 🎬 BLB-8 закрыт иначе, чем я предлагал

Я предлагал маршрут `SPLIT → STUDIO → мост`. **Ответ Босса лучше:**

> **Серия — это не экскурсия по готовому городу, а стройка.**
> **Эпизод = референс GPT → этаж города → коммит, который можно показать.**

Первый эпизод назван: **«переносим ИИ-чат из Дека в правую рейку»**.
У него есть всё для хорошего выпуска: до/после, реальный референс, конкретная
боль (чат задыхался в 240 px) и даже комический персонаж — маскот, который
поедет, если не поправить зоны.

**→ BLB-3 (YouTube-готовность как SLO) поднят:** было «не приоритет», стало приоритетом.

### В кадастре: переезд, а не новостройка

`REHEARSAL · BILLY` меняет адрес. Помечать надо именно как **переезд**, иначе
через месяц будем искать чат в подвале Дека. Новое здание `RIGHT-RAIL` (+3 этажа,
проект): `F01 RAIL-CONTAINER` · `F02 CHAT` · `F03 STATS`.

**Вопрос к Боссу (BLB-14):** А — BILLY переезжает целиком (рекомендую) ·
Б — RIGHT-RAIL становится зданием, BILLY расформирован · В — ничего не менять,
просто пометить адрес.
