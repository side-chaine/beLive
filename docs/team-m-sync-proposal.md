# Предложение: Cross-Team Sync — Team M (Mac) → Team V (Windows)

> **Документ-бриф для команды Мака (M007) и её суб-агентов.**
> **Статус:** предложенное решение, согласовано со стороны V (Windows/ПК).
> **Дата:** 2026-08-23

---

## 1. Зачем
Мак поднимает своих суб-агентов под задачи дизайна и макетов. Нужен надёжный канал:
когда команда Мака завершает задачу, сторона Windows (V, ПК) **автоматически видит** готовый
MD-отчёт и получает триггер «решение от Мака готово». Это система проверки состояния репозитория,
а не ручная пересылка файлов.

## 2. Как это работает (архитектура)
```
Mac sub-agent (design / layout / …)
  → пишет MD-отчёт в drop-zone репозитория
  → коммитит (или просто пишет файл)
        ↓  (sshfs-монтаж: запись Мака мгновенно видна на ПК)
Windows (V): state-checker
  → видит новый / изменённый отчёт Мака
  → стреляет триггером «здесь»:
       Layer 1: team-m/INBOX.md + секция «## Mac Team» в REPO-STATE.md
       Layer 2 (позже): звук / аватар-нотификация
                         (CharacterSoundManager, state = notification)
  → пользователь видит: «От Мака: <agent> / <task> — <status> @ <time>»
```

Фундамент уже готов (настроен ранее): sshfs-монтаж `~/beLive-pc` (Мак видит ПК-ФС вживую),
git-хук `update-repo-state.sh` (генерит `REPO-STATE.md` на каждый коммит), `docs/SYNC-PROTOCOL.md`.

## 3. Что настраивает команда Мака (ваша часть)
1. Поднимите своих суб-агентов (design-agent, layout-agent, …) — это ваша зона ответственности.
2. Каждый агент по завершении задачи **пишет отчёт** в drop-zone:
   ```
   team-m/reports/<agent-id>/<task-slug>.md
   ```
   Пример: `team-m/reports/design-agent/hero-section.md`
3. Соблюдайте **формат фронтматтера** (см. §5) — чтобы V-сторона могла распарсить и показать.
4. **Коммитьте** отчёт (`git add` + `git commit`) — тогда V-хук срабатывает мгновенно.
   (Если коммит неудобен — сообщите, добавим отдельный вотчер; но дефолт = коммит.)
5. Работаете в смонтированном репозитории `~/beLive-pc` (уже настроено). Отдельно клонировать не надо.
6. **Frozen Zone — не трогать:** `src/audio/core/AudioEngineV2.ts`, `src/audio/compat/patchV1.ts`,
   `src/bridges/*`, `src/services/track.orchestrator.ts`, приватные поля `_`.
   Только новые файлы отчётов в `team-m/reports/`.

## 4. Что настраивает сторона Windows (V, уже в работе)
- Расширяем `update-repo-state.sh`: сканирует `team-m/reports/` и дописывает новые отчёты в
  `team-m/INBOX.md` + секцию `## Mac Team` в `REPO-STATE.md`.
- (Layer 2, позже) `CharacterSoundManager` (исследован в `docs/character-ai/RESEARCH-REPORT.md`,
  состояние `notification`) + реакция аватара / Билли на появление отчёта Мака.

## 5. Формат отчёта (фронтматтер — ОБЯЗАТЕЛЬНО)
```md
---
agent: design-agent        # id агента Мака
task: hero-section         # slug задачи
status: done               # done | wip | blocked
updated: 2026-08-23T21:30:00+03:00
---
## Что сделано
<краткое описание, артефакты, ссылки на файлы в репозитории>

## Следующие шаги
<что нужно от V-стороны / блокеры>
```

## 6. Демонстрация в тестах (как доказать, что канал работает)
1. Mac-agent пишет `team-m/reports/design-agent/sample-task.md` (status: done) и коммитит.
2. На ПК хук пересобирает `REPO-STATE.md` → в разделе `## Mac Team` появляется запись об отчёте;
   `team-m/INBOX.md` получает строку-уведомление.
3. Пользователь (Windows) открывает `REPO-STATE.md` / `team-m/INBOX.md` → видит
   «Mac: design-agent / sample-task — done @ 21:30».
4. (Layer 2, опц) звук / аватар-сигнал «пришло решение от Мака».
→ Этим тестом демонстрируем нашу разработку и зафиксированный процесс работы.

## 7. Предложенные дефолты (подтвердите на Маке)
| Параметр | Дефолт |
|---|---|
| Drop-zone | `team-m/reports/<agent-id>/<task-slug>.md` |
| Сигнал завершения | коммит (хук V-стороны) |
| Тrigger на V | Layer 1: INBOX.md + REPO-STATE; Layer 2: звук / аватар (позже) |
| Фронтматтер | agent / task / status / updated |

## 8. Что дальше
- V-сторона имплементирует расширение хука (минимальный инкремент) — отдельным шагом по аппруву.
- Мак настраивает своих агентов писать / коммитить отчёты по этой конвенции.
- Прогоняем тест из §6 → канал подтверждён, процесс работы зафиксирован.
