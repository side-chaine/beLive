# Audio Behavior Spec — beLive Transport Contract

> Бэкенд-агностичный контракт поведения аудио-транспорта.  
> Не ссылается на конкретные строки кода — актуальность против списка проверяет **007** при каждом раунде.  
> **Живой документ** — статусы обновляются по факту прогона, а не наоборот.

**Статусы:**  
✅ = подтверждено в браузере  
⚠️ = в коде, живой прогон под конкретный сценарий не проводился  
❌ = не выполняется  
— = не проверялось  

**Как читать RS:** два порога — «сейчас» (День 0, pool-based FULL, MAX=7) и «цель» (после недели 2 — MultichannelStretch + transfer).

---

## Транспорт (TR)

| ID | Поведение | Режим | Статус |
|---|---|---|---|
| TR-01 | `play()` из stop начинает с позиции 0, без щелчка | оба | — |
| TR-02 | `pause()` → `play()` продолжает с той же позиции ±10 мс | оба | ✅ |
| TR-03 | seek во время воспроизведения — без двойного скачка | оба | ⚠️ |
| TR-04 | seek во время луп-перехода — без двойного скачка (счётчик поколений) | оба | — |
| TR-05 | 5 быстрых seek подряд (<100мс между) → отрабатывает только последний | оба | — |
| TR-06 | seek за пределы луп-региона — детерминированно (кламп либо снятие лупа) | оба | — |
| TR-07 | смена rate 1.0→0.85 не сдвигает позицию | оба | ⚠️ |
| TR-08 | смена rate во время паузы применяется при следующем play | оба | — |
| TR-09 | rate 0.5 и 2.0 — без креша и без тишины | оба | — |
| TR-10 | конец трека → `ended`, позиция замирает на длительности | оба | — |
| TR-11 | позиция монотонна (не идёт назад без seek) | оба | — |
| TR-12 | `getPosition()` дешёвая (<0.1мс, дёргается 60 раз/сек) | оба | — |

## Луп (LP)

| ID | Поведение | Режим | Статус |
|---|---|---|---|
| LP-01 | луп 2 бара, rate 1.0 — без щелчка на стыке | оба | — |
| LP-02 | луп 2 бара, rate 0.8 — без щелчка на стыке | оба | — |
| LP-03 | луп короче 500мс работает, не заикается | оба | — |
| LP-04 | изменение границ лупа во время игры внутри — без прыжка | оба | — |
| LP-05 | вкл/выкл лупа во время игры не двигает позицию | оба | — |
| LP-06 | 100 циклов лупа подряд — дрейф позиции < 20мс | оба | — |

## Микшер / роутинг (MX)

| ID | Поведение | Режим | Статус |
|---|---|---|---|
| MX-01 | **FULL: мастер-инструментал не загружается и не звучит вообще** — не mute, физическое исключение из набора стемов | FULL | **✅** |
| MX-02 | mute одной дорожки не меняет громкость остальных | оба | — |
| MX-03 | solo глушит остальные, снятие восстанавливает прежние gain | оба | — |
| MX-04 | изменение gain — рампа ≥10мс, без щелчка | оба | — |
| MX-05 | gain=0 = настоящая тишина, не −60дБ | оба | — |
| MX-06 | mute во время seek не залипает после seek | оба | — |
| MX-07 | все дорожки muted → мастер тишина, транспорт продолжает идти | оба | — |
| MX-08 | переключение DUO↔FULL — полный teardown, ни одна старая нода не осталась подключённой | оба | — |

## Синхронность (SY)

| ID | Поведение | Режим | Статус |
|---|---|---|---|
| SY-01 | вокал vs инструментал: дрейф < 15мс за 5 минут | DUO | — |
| SY-02 | стемы между собой: дрейф = 0 семплов | FULL | — |
| SY-03 | после seek все дорожки стартуют в одной точке | FULL | — |
| SY-04 | после смены rate синхронность сохраняется | оба | ⚠️ |
| SY-05 | нулевой тест на флэнджер: инверсия суммы стемов против инструментала → тишина (RMS < −40дБFS). **rate ≠ 1 обязателен** | FULL | — |
| SY-06 | 50 циклов лупа — синхронность не деградирует | оба | — |

## Питч / BPM (PT)

| ID | Поведение | Режим | Статус |
|---|---|---|---|
| PT-01 | rate 0.75 — питч не уехал (референсная нота, тюнер/спектр) | оба | ⚠️ |
| PT-02 | rate 1.25 — питч не уехал | оба | ⚠️ |
| PT-03 | сустейн (рояль/пэд) на rate 0.8 — без «обрывков» | оба | — |
| PT-04 | перкуссия на rate 0.8 — транзиенты не размазаны до неузнаваемости | оба | — |
| PT-05 | rate меняется плавно (слайдер) без дропаутов | оба | ⚠️ |

## Ресурсы (RS)

| ID | Поведение | Сейчас (День 0) | Цель (неделя 2+) |
|---|---|---|---|
| RS-01 | RAM, DUO, трек 4 мин | — | < 60 МБ |
| RS-02 | RAM, FULL, 6 стемов, трек 4 мин | **~1.8 ГБ** (ожидаемо, не провал) | < 350–680 МБ |
| RS-03 | CPU в паузе | < 2% (предположительно) | < 2% |
| RS-04 | CPU, FULL, rate 0.85 | — | < 35% одного ядра |
| RS-05 | загрузить/выгрузить ×10 — RAM возвращается к базовой ±10% | — | обязательно |
| RS-06 | Practice + WebRTC голос, 10 мин — 0 дропаутов | — | обязательно |

## Практика (PR)

| ID | Поведение |
|---|---|
| PR-01 | входящее «позиция X в момент T» → локальный транспорт сходится за < 2 сек, без слышимого seek |
| PR-02 | падение сети → локальное воспроизведение продолжается, не встаёт |
| PR-03 | отключение видео не влияет на аудио-позицию |
| PR-04 | педагог ставит паузу → у студента пауза < 300мс |

> **Важно:** PR-01…04 не проектируются с нуля — в Rehearsal Bridge уже есть VirtualClock / DriftCorrector / dual DataChannel. Новый TransportClock стыкуется с этой системой, а не дублирует её.
