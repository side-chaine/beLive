## 2. Главная находка: ключ был объявлен как `VITE_*`

**Vite встраивает каждую переменную с префиксом `VITE_` в клиентский бандл.**
Любой `VITE_*` секрет уезжает в браузер каждому посетителю — его видно в
DevTools, он лежит в JS-файле на CDN.

Это архитектурная ошибка, а не просто «забыли удалить». Shared-ключ beLive
должен жить **только на сервере** — в CF Worker `belive-mvsep` (`env.MVSEP_API_KEY`).

## 3. Вторая находка: ветка с ключом была недостижима

```ts
// src/services/mvsep.service.ts
const MVSEP_WORKER_URL = import.meta.env.VITE_MVSEP_WORKER_URL
  || 'https://belive-mvsep.nikitosss007.workers.dev';   // ← дефолт задан

export function resolveApiKey() {
  const userKey = ...;
  if (userKey?.trim()) return { key: userKey.trim(), source: 'user' };

  if (MVSEP_WORKER_URL) return { key: '', source: 'beLive' };  // ← ВСЕГДА TRUE

  const sharedKey = MVSEP_API_TOKEN;      // ← НЕДОСТИЖИМО
  if (sharedKey) return { key: sharedKey, source: 'beLive' };

  return { key: '', source: 'none' };
}
```

`MVSEP_WORKER_URL` имеет дефолтное значение, поэтому условие
`if (MVSEP_WORKER_URL)` истинно **всегда**. Строка с `MVSEP_API_TOKEN`
физически не выполнялась.

**Следствие:** ключ был бесполезен, но при сборке всё равно попал бы в бандл —
Vite не анализирует достижимость кода, он подставляет переменные текстом.

### ⚠️ Моя ошибка в первом замере

Первая проверка (`grep -rl "<MVSEP-KEY-REDACTED>" dist/ | head -3 && echo "KEY IN BUILT BUNDLE"`)
показала тревогу. **`head` всегда возвращает exit 0**, поэтому `&&` сработал
даже при пустом grep. Повторная проверка показала: **в `dist/` ключа не было**.

Уязвимость была **потенциальной**, не реализованной — следующая сборка бы её
раскрыла. Разница принципиальная: прод не был скомпрометирован.

## 6. Рекомендация: предотвратить повтор

Проблема не в этом ключе, а в паттерне. Что предлагаю:

1. **Правило:** ни один секрет не объявляется с префиксом `VITE_`.
   `VITE_*` — только публичные конфиги (URL воркера, ID, флаги).
2. **Pre-commit hook:** сканер на `VITE_.*(KEY|TOKEN|SECRET|PASSWORD)` —
   блокировать коммит.
3. **CI-гейт:** тот же сканер на каждый PR.
4. **`.env.example`** с комментарием про `VITE_` — чтобы следующий не наступил.

Сканер написать несложно — это один grep. Включу в волну CI-гейтов (O5).

## 8. Урок

> **Секрет с префиксом `VITE_` — это не секрет, а публикация.**
> Vite подставляет переменные текстом на этапе сборки и не анализирует,
> достижим ли код, который их использует.

И второе:

> **`cmd | head -N && echo "найдено"` — всегда печатает «найдено».**
> `head` возвращает 0 независимо от того, что передал grep.
> Проверять надо `grep -c` или через `if`.
