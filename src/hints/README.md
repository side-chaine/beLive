# `src/hints/` —guided tour / «поведём за руку»

Отдельная подсистема мягких подсказок. **Не путать** с
`src/components/onboarding/` — там старый аккордеон шагов каталога, он не
трогается и не связывается с этим контуром.

## Принципы

| Принцип | Как реализовано |
|---|---|
| Ноль координат в коде | Шаг указывает `target`; `HintLayer` сам измеряет `[data-bl-hint-target]` через `getBoundingClientRect()` + `ResizeObserver` |
| Ноль давления | Нет модалки, нет оверлея, нет обязательного клика; авто-затухание через `HINT_DEFAULT_TTL_MS` (20 с), `pointer-events: none` |
| Ничего не перекрывает | Слой выше хедера по `z-index`, но клики проходят насквозь; исключение — крошечный `×` |
| Не в первом пейнте | `App.tsx` подключает `HintLayer` через `React.lazy` **после** ухода сплеша |
| Один шаг за раз | `HINT_ORDER` → первый подходящий по `isStepEligible()` |
| Гейт у каждого шага свой | `HintSpec.gate: 'start' \| 'catalog'`. Старый глобальный `!catalogOpen` **убран** — иначе шаг ВНУТРИ каталога был невозможен |
| Политика отдельно от рендера | `eligibility.ts` — чистые функции; `HintLayer` владеет только жизненным циклом. Новый узел тура не требует правок компонента |
| 🔴 Каждая загрузка = новая подсказка | `start.catalog` помечен `repeatOnLoad: true` ⇒ `completed[]` из `localStorage` его **НЕ** глушит. Ровно **один** ролл на пару `(step, locale)` за документ (`rolledThisDocument` — `Map` в области модуля), без повтора варианта предыдущей загрузки |
| «Выучено» только на текущий визит | Реальное действие (`catalog-open`) пишет в **in-memory** `sessionDone`, а не в `localStorage` ⇒ не надоедаем в этой сессии, но здороваемся снова на следующей загрузке |
| Мастерство = факты, а не таймер | `catalog.upload` угасает по `track-saved` / двум визитам на вкладку / бюджету показов / `×`. Подробнее — отдельный раздел ниже |
| Пользователь — хозяин | `HintToggle` в Комнате и в меню аватара: **компактная плашка** «Подсказки!» + тумблер (`width: fit-content`, не полоска на всю ширину). Больше ничего |

## Файлы

```
types.ts        контракт: HintId / HintSpec / HintGate / HintStats / HintVariant
config.ts       все tunable'ы, бюджет показов, ключ хранилища
locale.ts       RU/EN по месту открытия (провайдеры, порядок, override)
variants.ts     2 пула по 7 RU + 7 EN, один на загрузку, без повтора предыдущего
registry.ts     HINT_ORDER + HINT_REGISTRY + checkHintPools() (guard 5–7)
eligibility.ts  🔱 ЧИСТЫЕ политики: isStepEligible() + uploadMastery()
store.ts        zustand/persist: enabled, localeOverride, completed, lastVariant, stats + merge-миграция
HintLayer.tsx   жизненный цикл, sessionDone, факты, один ролл варианта на визит, измерение якоря, SVG
ChalkHint.tsx   презентационная карточка: неровная черта, «ТЫК !», ×, data-bl-hint=<id>
HintToggle.tsx  одна строка + тумблер, вставляется в любую поверхность
hints.css       матовые черты, компактная .bl-hint-plate, адаптивная тема
```

## Как добавить новый шаг

1. Добавить id в `HintId` (`types.ts`).
2. Добавить `HintSpec` в `HINT_REGISTRY` и id в `HINT_ORDER` (`registry.ts`).
3. Пул 5–7 вариантов на **каждый** язык (`variants.ts`) — иначе `checkHintPools()` предупредит в консоли.
4. Повесить на целевой DOM-узел `data-bl-hint-target="<target>"`.
5. Указать `gate: 'start' | 'catalog'` — где живёт шаг.
6. При необходимости новый `completeOn` — и вариант в `seenThisVisit()` (`HintLayer.tsx`).
7. Решить про `repeatOnLoad`: приветствие на каждой загрузке (`true`, как у
   `start.catalog`) или классический learn-once шаг (`false`/не задано).
8. Если шагу нужна своя политика угасания — добавить `policy` в `types.ts` и
   чистую функцию в `eligibility.ts`. **Не** добавлять `if (id === ...)` в `HintLayer`.

Больше ничего менять не нужно: стрелка, кольцо, позиция и авто-затухание
считаются от измеренного якоря автоматически.

## 🔱 Вторая подсказка `catalog.upload` — как beLive понимает «освоил загрузку»

Никита, 05.11.2026: *«как понять beLive что пользователь уже освоил загрузку и
эти подсказки уже не нужны!? я уверен ты найдёшь необходимые триггеры!»*

**Никаких таймеров и догадок.** Таймер будет доставать человека, который уже
знает, где `ЗАГРУЗКА`. Решение принимается по наблюдаемым фактам
(`eligibility.ts → uploadMastery()`), в порядке убывания силы:

| # | Сигнал | Откуда | Что доказывает |
|---|---|---|---|
| 1 | 🟢 `track-saved` ≥ 1 | DOM-событие из `upload.service.ts` (3 точки dispatch после реального сохранения трека в IDB) | **ФАКТ.** Загрузка освоена, точка |
| 2 | 🟡 `upload-tab-open` ≥ 2 | переход `useUIStore.catalogTab` в `'upload'` | **НАМЕРЕНИЕ.** Дважды нашёл вкладку ⇒ дорогу знает, даже если ни разу не сохранил |
| 3 | 🔴 `dismisses['catalog.upload']` ≥ 1 | явный `×` | **ОТКАЗ.** Уважаем сразу, без «ещё разочек» |
| 4 | ⚪ `shows` ≥ бюджет | доставленный показ (засчитывается когда мел УШЁЛ, не когда стал eligible) | **ЭКСПОЗИЦИЯ.** Пустой каталог — 6, с треками — 3 («пару раз ещё показать») |
| 5 | ✅ `completed[]` | пишется при приходе факта | Явная печать мастерства, снимается `resetTour()` |

`tracksMeta.length` **намеренно не считается мастерством**: треки могут быть
встроенными, предзагруженными или импортированными из другого места. Это только
**состояние**, которое смягчает бюджет показов. Мастер-выключатель `enabled`
проверяется первым в `isStepEligible()` и всегда побеждает.

`stats` (счётчики `shows` / `dismisses` / `facts`) лежат в том же
`belive:hints-v1`. `persist.merge` подкладывает пустые счётчики для **старых**
записей без `stats` — без bump версии и без потери данных. CDP-свидетель это
проверяет (`oldShapeMigrated: true`).

Гейт шага: каталог открыт И активна вкладка «МОЯ МУЗЫКА». Как только юзер
встаёт на `ЗАГРУЗКА`, подсказка уходит — она своё дело сделала. Один клик по
вкладке **не** записывает `completed[]`: одно любопытное нажатие ≠ мастерство.

> 🔴 **Исторический баг (исправлен 05.11 18:05):** раньше `spec` искался как
> «первый шаг, которого нет в `completed[]`». Один клик по `Catalog` навсегда
> записывал `start.catalog` в `localStorage`, и на всех следующих загрузках
> подсказка не появлялась вообще — при включённом тумблере. Именно это Никита
> поймал скрином «где эти самые подсказки при загрузке страницы их нет?».

## Язык «в зависимости от откуда открыт beLive»

Приоритет (`locale.ts`):
1. Явная ссылка: `?lang=en` / `?locale=ru` / `?hl=en`.
2. Поверхность входа: `?src=global|intl|en` → EN, `?src=ru|tg|vk|bot` → RU;
   затем однозначный хост реферрера (`en.*` → EN, `*.ru` → RU).
   Общий `.com` **не** считается сигналом языка (google.com, auth.mybelive.com).
3. `navigator.languages` → `navigator.language`.
4. Домашняя локаль `ru`.

`localeOverride` и `resetTour` остаются **проводами** в `store.ts` (для следующих
шагов тура), но в UI больше не выведены: настройки подсказок сжаты до одной
строки. Перекрыть язык можно URL-параметром (`?lang=en`), не заходя в Комнату.

## Проверка вручную

| Что | Как |
|---|---|
| RU по умолчанию | `http://localhost:3000/beLive/` |
| EN | `...?lang=en` или `...?src=global` |
| Другой вариант на загрузку | обновить страницу (сброс тура не нужен) |
| Вторая подсказка | открыть каталог → мелом обводится вкладка `ЗАГРУЗКА` |
| Убедиться, что «освоил» работает | дважды сходить на `ЗАГРУЗКА` (или один раз сохранить трек) → обновить → подсказки нет |
| Отключить | Комната → строка «Подсказки!», либо меню аватара → та же строка |
| Посмотреть все варианты | просто обновить страницу (сброс тура не нужен) |
| Сбросить тур / задать язык вручную | из консоли: `useHintsStore.getState().resetTour()` / `setLocaleOverride('en')` — UI намеренно не показывает |
| Тест-селекторы | `[data-bl-hint-layer]` (значение = id шага), `[data-bl-hint]`, `[data-bl-hint-toggle]`, `[data-bl-hint-target="catalog"]`, `[data-bl-hint-target="upload"]`, `data-bl-hint-variant`, `data-bl-hint-track-count`, `data-bl-hint-mastery` — свидетели для CDP |

Ключ хранилища: `belive:hints-v1`. Шаг `start.catalog` завершается **только на
текущий визит**, когда `useUIStore.catalogOpen` становится `true` **или**
пользователь жмёт саму кнопку Catalog. Следующая загрузка показывает новый
вариант снова — даже если в `completed[]` осталась старая запись.

**CDP-свидетели** (Windows Chrome, нулевые зависимости), лежат рядом с паком:
`probe-upload-hint.mjs` → `upload-probe.json` (14/14 кейсов политики, миграция
старого `stats`, обводка вкладки, `track-saved`, мастер-выключатель) и
`probe-upload-wiring.mjs` → `upload-wiring.json` (`×` и два визита на вкладку).
Оба синхронизируются по **реальному уходу сплеша**: клики по старому DOM давали
ложно-зелёные результаты, поэтому каждая загрузка идёт на уникальный URL.

Плашка в Комнате — `.bl-hint-plate` (`width: fit-content`), она обжимает слово и
тумблер; растягивать её `gridColumn: 1 / -1` **нельзя** (уже пробовали —
получается непроработанная полоса на 1100 px).
