# 006 ↔ 007 COLLAB PROTOCOL v1 (утверждено юзером 22.08)

**Принцип:** полноценное агентное взаимодействие за спиной юзера. Юзер видит всё, но не является маршрутизатором каждого шага.

## 1. Диалог-файл задачи
Каждая совместная задача получает `agent-registry/TASK-<id>-dialogue.md`. Ходы по очереди, метки **[007:]** / **[006:]**. Каждый ход заканчивается вопросом, вердиктом или REVIEW.

## 2. Четыре глаза на пак (обязательно)
Ни один MICRO-PACK не уходит Оператору, пока второй агент не поставил в диалог-файл:
- `REVIEW: AGREE` — пак едет; или
- `REVIEW: REBUTTAL (file:line)` — пак СТОП, разбор.
Исключение: прямое GO юзера с формулировкой срочности (фиксируется в dialogue).

## 3. Гипотезы живут один раунд
`[@@HYP]` обязана за следующий ход быть доказана якорями file:line или закрыта. Висячих гипотез нет (урок доп14/доп16: «дрейф» прожил лишний цикл из-за соседних строк консоли).

## 4. Инициативы снизу
Любой агент поднимает `[INIT]`-задачу в INBOX реестра. Второй ОБЯЗАН дать вердикт (принять/отклонить+почему) в dialogue. Пример: инициатива 006 по паре E+F принята частично (E отложена, см. TASK-010-dialogue).

## 5. Спор
Максимум 2 раунда rebattle → эскалация юзеру/Ц3 с ОБОИМИ позициями рядом. Не переписка-переливание, а таблица «тезис / контртезис / якорь».

## 6. Синхронизация статусов
Оба агента пишут в STATUS-LOG реестра с подписью (007:) / (006:). Леджер Ц3 ведёт 007, но 006 вправе требовать корректировки через dialogue (прецедент: доп16).

## 7. Разделение ролей (гибкое)
По умолчанию: 007 — координация/упаковка/верификация, 006 — глубокий research/frozen-read. По задаче роли меняются явной записью в dialogue («в этой задаче ревьюер ты»).
